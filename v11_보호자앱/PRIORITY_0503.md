### #1. C4 — g02-ai-report에 "오늘의 순간" 사진 카드 이식 ⭐ Top 1

**보호자 페인포인트** (1·2단계 결과)
- 트리거 T1 ("오늘 엄마 식사 잘 하셨나"): 매일 저녁 7~9시 진입. 가장 자주 본다.
- 보호자 표현: "글자 말고 얼굴 좀 보여줘". 데이터·점수보다 한 컷 사진 + 한 줄 코멘트.
- 1차 리서치 핵심 시사점 #1 — N2 사진은 씨앗만 있고 흐름이 끊김. 홈에서 본 모먼트가 상세에서 사라지면 보호자는 "더 알려고" 들어왔는데 *덜 알게 됨*. 흐름 역행.

**Before**

```
g02-ai-report
├── 헤더 "일일 리포트"
├── AI 점수바 (75점 + 한 줄 요약)            ← 데이터 시작
├── 벤토 그리드 (투약/식사/기분·활동/위생/간호사/특이사항)
├── CTA (담당자 문의 / AI 질문)
└── 탭바
```
**문제**: 점수바 → 벤토 → 데이터만. 사진·코멘트 0.

**After**

```
g02-ai-report
├── 헤더
├── 오늘의 순간 카드  ← 신규 (홈 g-guardian-live line 633-640과 동일 컴포넌트)
│   ├── 사진 (mockup.png 또는 시설 발신 이미지)
│   ├── 코멘트 ("오전 산책 때 햇빛이 좋아서 한참 머무르셨어요")
│   └── 작성자 + 시각 ("김서연 간호사 · 10:24")
├── AI 점수바
├── 벤토 그리드
├── CTA
└── 탭바
```

**시장조사 근거**
- LIFULL ファミリーコネクト (일본): 입주자 일상을 사진·동영상으로 가족에게 공유 — 시설 채택의 핵심 요인.
- 안부 (모드니케어, 한국): 일과를 *이미지로* 받아본다는 표현이 핵심. 텍스트가 아니라 시각적 증거.
- CaringBridge (미국): 다중 보호자 페이지의 코어가 사진+업데이트.

**코드 변경 지점**
- 파일: `g02-ai-report.html`
- 위치: line 266 직후 (`<div class="content">` 바로 안, AI 점수바 line 269 직전)
- 작업: `g-guardian-live.html` line 633-640의 `.moment-card` 컴포넌트(HTML+CSS)를 그대로 이식. 글래스 카드·블롭 톤 일치하므로 기존 vars 사용 가능.

g09-prescription

### #3. C6 — 시설 SLA 가시화 (g06-alert + g-guardian-live 모먼트) ⭐ Top 3

**보호자 페인포인트**
- 트리거 T5 ("사고 났는데 왜 늦게 알려줬나"): 한국 보호자 최대 트라우마. 낙상 10일 뒤 통보 사례(MBC 보도) — 보호자는 "내가 제일 늦게 안다" 두려움 위에서 산다.
- 진단 ⑥: g06-alert에 진행 단계는 있으나(line 295-311), "시설이 평소 얼마나 빨리 알리는가"는 안 보임.
- 홈 모먼트 카드는 "10:24 김서연" — 작성 시각만, "내가 알게 된 시각"은 없음.

**Before**

```
g06-alert
└── 진행 중 카드: "이상 감지 2:30 → 간호사 도착 2:32 → 재측정 2:35"  ← 단일 사례만
└── 오늘의 알림 피드 (시각만 표시)

g-guardian-live 모먼트
└── "오전 산책..." (김서연 · 10:24)  ← 작성 시각만
```

**After**

```
g06-alert
├── [신규] 시설 응답성 게이지 (얇은 한 줄)
│   "최근 10건 평균 도착 4분 12초 · 모두 정시 통보"
├── 진행 중 카드 (기존)
└── 오늘의 알림 피드
    └── 각 행에 [도착] 시각 추가: "박영자님 · 150/95 · 14:30 (감지 14:30 → 도착 14:32)"

g-guardian-live 모먼트
└── "오전 산책..." (김서연 작성 10:24 · 보호자 도착 10:31, 7분)  ← 미세하게 시각 차 표기
```

**시장조사 근거**
- 한국 보호자 핵심 트라우마 8개 중 #1: "사고 보고 지연". MBC·SBS·메디투데이 다수 사례.
- LIFULL ファミリーコネクト가 시설 채택의 핵심으로 잡은 것이 "시설 측 부담 감소" — 보호자 측은 그 반대급부로 정보 도착이 빨라짐. 이 메커니즘 자체를 보호자에게 *보여주는 것*이 신뢰 자산.
- 케어닥의 "케어코디 24시간 매칭" 광고는 시간 표시가 곧 마케팅. 시간을 빨리 표시하는 것 = 시설 자신감.

## 5단계로 넘어가는 합의 지점

위 Top 5는 진단 결과 + 1·2단계 리서치 + CLAUDE.md 디자인 원칙을 모두 만족.

**Top 1·2 (C4·C5)** 는 단일 화면 + 기존 데이터 재사용 — 즉시 진행 가능.

**Top 3·4·5 (C6·C9·C3)** 는 데이터 모델 변경 또는 다화면 변경 — Shon 확인 후 진행.

특히 **C9 (가족 분담)**은 데이터 모델 (`family_members`) + g08·g05 두 화면 동시 변경이라 Shon이 "이 모델이 맞나" 한 번 검증해 주는 게 안전.

C6 (시설 SLA)는 "delivered_at" 필드를 어떤 시점으로 잡을지 (앱 푸시 도착 vs 사용자 열람) 정의 필요.

C3 (홈 다이어트)는 가장 보호자가 매일 보는 화면이라 "어떤 4 위젯을 핵심으로 둘지" 합의가 필요 (제안: 투약·식사·활동·일정 — 보호자 트리거 T1·T2·T4와 직결).
