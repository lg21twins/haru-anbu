# v11 보호자앱 UX/UI 통합 리뷰

작성일: 2026-05-10  
리뷰 대상: `v11_보호자앱` 최신 HTML/CSS 파일  
리뷰 기준: 디자인 시스템 v3.1 통일성, 탭별 UX/UI, 디자인 심미성, 보호자 사용자의 실제 불편 가능성, 파일 구조

## 결론

보호자앱은 감성, 신뢰감, “가족이 안심을 확인한다”는 제품 방향은 좋습니다. 홈의 AI 리포트 시트, 일일 리포트의 사진 중심 카드, 기록/소통/마이의 푸른 톤은 서비스 성격과 잘 맞습니다.

다만 파일을 직접 뜯어보면, 현재 보호자앱에는 두 개의 방향이 공존합니다.

1. `g-home-v31-pilot.html`: 디자인 시스템 v3.1 방식으로 만든 새 파일럿
2. `g-guardian-live.html`과 기존 주요 탭들: 화면별 inline CSS와 legacy token으로 만든 실제 최신 앱

즉, 디자인 시스템 자체는 좋아졌고 파일럿도 방향이 맞지만, 실제 최신 보호자앱 화면들은 아직 그 시스템으로 완전히 이전되지 않았습니다. 지금 필요한 작업은 새 화면을 더 만드는 것이 아니라, `g-home-v31-pilot.html`의 구조를 기준으로 실제 앱 파일들을 하나의 앱 셸, 하나의 탭바, 하나의 token 체계로 묶는 것입니다.

현재 점수:

- 디자인 심미성: 8/10
- 탭별 통일감: 6.5/10
- 디자인 시스템 일치도: 5.5/10
- 실제 사용자 편의성: 6.5/10
- 개선 후 기대치: 8.5/10

## 핵심 문제 5가지

1. 탭바 구조와 탭 구성이 화면마다 다릅니다.
2. 대부분의 화면이 `tokens.css`/`system` CSS가 아니라 `pretendard.css`와 화면 내부 hard-coded CSS에 의존합니다.
3. 하단 탭바 + AI FAB가 콘텐츠를 가리거나, 일부 화면에서 하단 여백이 부족합니다.
4. 홈은 인상적이지만 리포트 시트, 채팅 진입, 탭바, AI FAB의 인터랙션이 복잡해 첫 사용자가 길을 잃을 수 있습니다.
5. 디자인 시스템 v3.1의 flat-first/semantic token 원칙과 달리, 화면마다 rgba, hex, legacy token, inline style이 많이 남아 있습니다.

## 파일 구조 감사

### 파일 규모와 위험도

- `g-guardian-live.html`: 1706줄
- `common.css`: 1302줄
- `g08-billing.html`: 1143줄
- `g05-records.html`: 736줄
- `g02-ai-report.html`: 500줄
- `g02-ai-guide.html`: 480줄
- `g05-mypage.html`: 347줄
- `g03-sotong.html`: 366줄
- `g-home-v31-pilot.html`: 217줄

해석:

- 실제 홈인 `g-guardian-live.html`이 너무 큽니다. 홈 화면, 인트로, 리포트 시트, 채팅 모드, 대화 기록 드로어, 세부 시트 데이터까지 한 파일에 들어 있습니다.
- `g-home-v31-pilot.html`은 훨씬 짧고 디자인 시스템 import 구조가 명확합니다. 이 파일이 앞으로의 기준이 되어야 합니다.
- 기록/결제 화면도 파일 내부 CSS와 inline style이 많아 유지보수 위험이 큽니다.

### v3.1 파일럿과 실제 앱의 차이

`g-home-v31-pilot.html`은 다음을 제대로 하고 있습니다.

- `<html lang="ko" data-role="guardian" data-platform="mobile">`
- `../07_디자인/tokens/tokens.css` import
- `../07_디자인/system/app.css` import
- `../07_디자인/system/components.css` import
- `card-hero`, `card`, `card-action`, `card-alert`, `tabbar`, `fab-ai` 등 시스템 컴포넌트 사용
- 탭바에 텍스트 라벨 포함
- semantic token 중심 사용

반면 실제 최신 홈인 `g-guardian-live.html`은 다음 상태입니다.

- `<html lang="ko">`만 있고 `data-role`, `data-platform` 없음
- `pretendard.css`만 import
- 내부 `:root`에 `--blue`, `--green`, `--amber`, `--red`, `#2C7AFC`, `rgba(...)` 직접 선언
- 탭바, AI FAB, 카드, 시트, 채팅 UI가 모두 한 파일 내부 CSS
- JS 문자열 안에도 hard-coded style이 많음

개선 방향:

- `g-home-v31-pilot.html`을 폐기하지 말고 실제 홈 리팩터링의 기준 파일로 삼기
- `g-guardian-live.html`의 기능을 파일럿의 app shell/component 구조로 단계적으로 이전
- 최종적으로 파일럿이 아니라 실제 `g-guardian-live.html`이 v3.1 구조를 import하게 만들기

## 공통 UX/UI 이슈

### 1. 탭바가 컴포넌트가 아니라 화면별 복붙입니다

홈, AI 케어 가이드, 소통, 기록, 마이는 유사한 60px 탭바 + 60px AI FAB 구조를 쓰지만, 일일 리포트는 68px 탭바에 폭도 다르고, AI FAB도 없습니다. 결제 화면은 상단 back은 마이로 가는데 하단 active는 기록입니다.

사용자 불편:

- 같은 앱인데 화면마다 하단 내비게이션의 크기, 폭, 탭 구성이 달라 보입니다.
- 사용자는 지금 메인 탭 안에 있는지, 별도 상세 화면에 들어온 것인지 헷갈릴 수 있습니다.
- 일일 리포트에서는 메인 탭의 `AI 가이드` 대신 `일일 리포트`와 `결제`가 탭처럼 들어가 정보 구조가 흔들립니다.

개선안:

- `bottom-nav`를 공통 컴포넌트로 고정
- 메인 탭은 항상 동일하게 유지: 홈 / AI 가이드 / 소통 / 기록 / 마이
- 일일 리포트, 결제, 처방, 알림은 메인 탭이 아니라 기록 또는 마이 안의 상세 화면으로 처리
- 상세 화면에서는 하단 탭바를 유지할지 숨길지 정책을 통일

### 2. 디자인 시스템 토큰을 실제 화면이 충분히 쓰지 않습니다

`common.css`는 `../07_디자인/tokens/tokens.css`를 import하는 호환 레이어지만, 최신 주요 화면 다수는 `common.css`가 아니라 `pretendard.css`만 불러오고 화면 내부에 `--blue`, `--green`, `rgba(...)`, `#2C7AFC` 등을 직접 선언합니다.

개선안:

- 새 기준은 `tokens.css` + `system/app.css` + `system/components.css`
- 화면 내부 primitive token 선언 제거
- `--blue`, `--green`, `--red` 대신 `--color-accent`, `--color-success`, `--color-danger` 사용
- `rgba(44,122,252,...)`는 `rgba(var(--color-accent-rgb), ...)`로 교체
- 탭바, 카드, 버튼, 배지, FAB는 공통 class로 이동

### 3. 하단 고정 UI가 콘텐츠를 가릴 수 있습니다

일부 화면은 하단 탭바가 고정되어 있는데 bottom safe padding이 충분하지 않습니다. 특히 `g05-mypage.html`은 `.app` padding-bottom이 부족한 구조라 마지막 메뉴나 로그아웃 영역이 탭바와 너무 가까워질 수 있습니다.

개선안:

- 모든 메인 탭 화면에 동일한 bottom safe padding 적용
- 예: `padding-bottom: calc(max(env(safe-area-inset-bottom, 0px), 20px) + 112px)`
- 상세 화면도 탭바 표시 여부에 따라 bottom padding 정책 통일

### 4. 아이콘 only 탭바는 보호자 사용자에게 설명력이 약합니다

현재 실제 앱 탭바는 아이콘만 있고 텍스트 라벨이 없습니다. 시각적으로는 깔끔하지만, 보호자 앱은 사용자가 매일 빠르게 안심을 확인하는 도구이므로 `소통`, `기록`, `AI 가이드` 같은 목적이 즉시 읽혀야 합니다.

개선안:

- `g-home-v31-pilot.html`처럼 탭바에 짧은 텍스트 라벨 추가
- 최소한 active 탭에는 라벨 표시
- 아이콘은 전부 `iconify-icon`으로 통일
- 소통 탭의 inline SVG 제거
- AI FAB는 전역 액션임을 라벨 또는 microcopy로 명확히 표현

### 5. `href="#"`와 mock action이 남아 있습니다

대표 예:

- `g03-sotong.html` 일부 메시지
- `g08-billing.html` 납부하기, 계좌 변경, 알림 설정, 영수증 발급 등
- `g05-mypage.html` 로그아웃

사용자 영향:

- 눌렀는데 반응이 없거나 상단으로 튀는 느낌이 날 수 있습니다.
- 목업이라도 disabled/mock 상태를 명시해야 UX가 덜 깨집니다.

개선안:

- 실제 이동이 없으면 `<button disabled>` 또는 `aria-disabled="true"` + mock toast
- 결제/청구 액션은 상태별 feedback 필요

## 탭별 리뷰

## 1. 홈 탭

대상 파일: `g-guardian-live.html`, 참고 파일: `g-home-v31-pilot.html`

좋은 점:

- 첫 화면의 감성은 가장 강합니다.
- “오늘도 수고하셨어요, 영자님 잘 있어요”라는 문장은 보호자 앱의 정서적 목적과 잘 맞습니다.
- 일일 리포트 시트와 AI 인사이트는 하루안부의 핵심 가치가 잘 드러납니다.
- 사진/리포트/AI 대화가 한 화면 안에 연결되어 제품만의 개성이 있습니다.

사용자 불편 가능성:

1. 홈의 핵심 인터랙션이 너무 많습니다. 인트로, 리포트 시트, 시트 드래그, 채팅 진입, AI FAB, 채팅 힌트, 탭바가 동시에 존재합니다. 데모로는 인상적이지만 실제 사용자는 어디를 눌러야 일일 리포트를 보는지, AI 대화는 탭인지 버튼인지, 시트를 올리는지 내리는지 헷갈릴 수 있습니다.

2. 하단 탭바와 AI FAB가 시트/채팅 UI와 경쟁합니다. 탭바 + AI FAB도 바닥에 있고, 리포트 시트도 바닥에서 올라옵니다. 둘 다 하단에 붙은 UI라 시각적 계층이 충돌합니다.

3. 실제 홈은 v3.1 구조와 거리가 있습니다. `g-home-v31-pilot.html`은 DS 구조를 잘 따르지만, 실제 홈은 `pretendard.css`, 내부 `:root`, legacy token, JS template inline style에 의존합니다.

개선안:

- 첫 방문에는 핵심 CTA를 하나만 강조: `오늘 리포트 보기`
- AI 대화는 2차 액션으로 유지
- 시트 드래그 외에도 명시적 버튼 제공
- 리포트 시트 open 상태에서는 탭바를 숨기거나 축소
- AI FAB는 시트 상태에서는 `AI에게 질문` CTA로 시트 내부에 흡수
- `g-home-v31-pilot.html`의 app shell/component 구조를 실제 홈에 이전

우선 수정:

- P0: 홈에서 명시적 `오늘 리포트 보기` CTA 추가
- P0: 리포트 시트 open 상태에서 탭바/FAB 충돌 정리
- P0: 실제 홈에 `data-role="guardian" data-platform="mobile"` 적용
- P1: hard-coded color와 legacy token 제거
- P1: 홈 인트로는 최초 1회/스킵/다시 보기 정책 명확화

## 2. AI 케어 가이드 탭

대상 파일: `g02-ai-guide.html`

좋은 점:

- 추천 카드, 질문 리스트, 케어 지식으로 정보 구조가 명확합니다.
- 보호자가 실제로 물어볼 법한 질문이 앞에 있어 UX 방향이 좋습니다.
- 화면의 여백과 카드 톤은 비교적 깔끔합니다.

사용자 불편 가능성:

1. `AI 가이드`와 `AI 대화`의 관계가 모호합니다. 탭 이름은 AI 케어 가이드인데, 하단에는 별도 AI FAB가 있고 질문 리스트마다 `AI로 더 물어보기`가 반복됩니다.

2. 카테고리 칩 일부가 잘린 상태로 보일 수 있습니다. 가로 스크롤이 가능하다는 신호는 있지만, 첫 사용자에게는 내용이 잘린 것으로 보일 수 있습니다.

3. `data-role="guardian"`이 없고, `pretendard.css` + 내부 token 방식입니다.

개선안:

- AI 가이드 탭은 `읽는 지식/추천 질문` 중심으로 정의
- AI 대화는 전역 FAB 또는 마지막 CTA 한 곳으로 축소
- 카테고리 row 오른쪽에 fade mask 추가
- `<html lang="ko" data-role="guardian" data-platform="mobile">`
- 토큰 import 정리

우선 수정:

- P0: AI 가이드와 AI FAB의 역할 구분 문구 정리
- P1: 카테고리 칩 overflow 표시 개선
- P1: 질문 카드 CTA 반복 밀도 줄이기

## 3. 소통 탭

대상 파일: `g03-sotong.html`, 관련 하위 화면 `g03-chat-family.html`, `g03-chat-nurse.html`, `g03-chat-ai.html`

좋은 점:

- 읽지 않은 메시지, 케어/일정/결제/대화 필터가 있어 소통 허브로서의 방향은 좋습니다.
- 간호사, 혈당 검사 안내, 투약 시간 변경, 어머니 메시지가 섞여 있어 실제 맥락이 살아 있습니다.
- 카드 간 spacing과 rounded surface는 깔끔합니다.

사용자 불편 가능성:

1. 상단에 `읽지 않은 메시지 5건` 배너가 있고, 아래에 카테고리 칩이 있으며, 다시 `읽지 않음 4` 섹션이 나옵니다. 사용자는 5건과 4건이 왜 다른지 궁금해할 수 있습니다.

2. 혈당 검사 안내, 투약 시간 변경처럼 확인/동의가 필요한 메시지도 일반 대화 카드처럼 보입니다.

3. 소통 탭 아이콘만 inline SVG입니다.

4. 일부 메시지가 `href="#"`입니다.

개선안:

- count 정의 통일: 전체 미확인 / 현재 필터 미확인 중 하나
- 업무성 메시지에는 `확인`, `전화`, `일정 보기` 같은 작은 CTA 추가
- 단순 대화와 업무성 알림의 카드 스타일 차등
- 소통 아이콘을 `iconify-icon`으로 통일
- `href="#"`는 실제 상세 또는 disabled/mock 상태로 처리

우선 수정:

- P0: 미확인 count 기준 통일
- P1: 업무성 메시지 카드에 CTA 추가
- P1: 탭 아이콘 구현 방식 통일

## 4. 기록 탭

대상 파일: `g05-records.html`

좋은 점:

- 기록 탭은 정보 구조가 풍부합니다. 검색, AI 리포트, 오늘의 케어, 처방/약물, 진료/검사, 비용, 일정, 최근 기록, 의료 타임라인까지 연결됩니다.
- 보호자가 지난 기록을 확인하기에 필요한 정보들이 거의 다 들어 있습니다.
- 카드의 시각적 완성도도 좋은 편입니다.

사용자 불편 가능성:

1. 기록 탭 안에 너무 많은 도메인이 들어 있습니다. 케어 기록, 처방, 검사, 비용, 일정, 의료 타임라인이 모두 같은 탭 안에 있어 무엇을 먼저 봐야 할지 부담이 생깁니다.

2. 파일 내부 drilldown 구조가 많아 실제 URL/뒤로가기/상태 복원이 약합니다.

3. 결제/비용이 기록 탭 안에 들어 있고, 결제 화면도 기록 탭 active로 표시됩니다.

4. 카드 색상이 도메인별로 다양해 blue-accent 중심 원칙과 멀어질 수 있습니다.

개선안:

- 기록 탭 첫 화면은 `AI 리포트`, `오늘의 케어`, `최근 기록` 중심으로 축소
- `billing`은 마이 하위 또는 별도 결제 상세로 이동
- 의료 타임라인은 첫 화면에서 최근 2건만 표시하고 상세로 분리
- 카드 큰 면은 flat white 유지
- 색은 아이콘 배경/배지에만 제한

우선 수정:

- P0: 기록 탭의 1차/2차 정보 위계 정리
- P0: 결제/청구의 IA 위치 결정
- P1: 도메인 컬러 사용량 축소

## 5. 마이 탭

대상 파일: `g05-mypage.html`

좋은 점:

- 프로필, 케어 대상, 계정 메뉴가 한 화면에서 이해됩니다.
- 보호자와 케어 대상의 관계가 시각적으로 잘 드러납니다.
- 카드 구성은 깔끔하고 안정적입니다.

사용자 불편 가능성:

1. 마이 화면 상단 빠른 버튼이 소통/기록/AI 가이드로, 하단 탭과 기능이 중복됩니다.

2. 결제/청구로 가는 명확한 메뉴보다 기록 탭으로 보내는 항목이 많습니다.

3. `data-role`이 없고 CSS는 화면 내부에 독립 선언되어 있습니다.

4. 하단 탭바가 고정되어 있으므로 마지막 메뉴나 로그아웃 영역에 충분한 safe padding이 필요합니다.

개선안:

- 마이 빠른 버튼을 `가족 정보`, `결제/청구`, `알림 설정`, `계정 설정` 중심으로 변경
- 소통/기록/AI 가이드는 하단 탭바에 맡김
- 결제 화면은 마이 탭 active로 정리
- 마이 탭에도 다른 메인 탭과 동일한 bottom padding 적용

우선 수정:

- P0: bottom padding 추가
- P1: 마이 빠른 버튼 목적 재정의
- P1: 결제/청구 IA를 마이 하위로 정리

## 6. 일일 리포트 상세

대상 파일: `g02-ai-report.html`

좋은 점:

- 사진 카드와 인용 문장이 감성적으로 좋습니다.
- 보호자가 하루 상태를 빠르게 이해할 수 있게 AI 분석 점수, 투약/식사/기분/활동이 잘 구성되어 있습니다.
- 홈에서 리포트 상세로 이어지는 흐름 자체는 제품의 강점입니다.

사용자 불편 가능성:

1. 하단 탭 구성이 메인 탭과 다릅니다. 일일 리포트 상세의 탭바는 홈/채팅/리포트/결제/마이 구조입니다. 메인 탭 구조인 홈/AI 가이드/소통/기록/마이와 다릅니다.

2. 탭바 재질과 크기가 다릅니다. 일일 리포트 탭바는 68px, max-width 320px, 더 강한 blur를 사용합니다. 다른 메인 화면은 60px, max-width 370px, AI FAB 포함 구조입니다.

3. 탭바 아이콘이 대부분 inline SVG입니다.

4. 체크 표시 `✓`가 텍스트로 들어갑니다.

개선안:

- 일일 리포트는 기록 탭 하위 상세로 처리
- 하단 탭바는 메인 탭과 동일하게 유지하거나 상세 화면에서는 숨김
- 상단 back button으로 기록/홈 복귀를 명확히 제공
- `✓`는 `iconify-icon icon="fluent:checkmark-24-filled"`로 교체
- inline SVG는 iconify로 통일

우선 수정:

- P0: 리포트 상세의 탭바 구조를 메인 IA와 통일
- P1: 탭바 크기/재질 통일
- P1: 체크 기호를 iconify로 교체

## 7. 결제 / 청구 화면

대상 파일: `g08-billing.html`

좋은 점:

- 금액, 납부 상태, 보험 적용, 비용 인사이트가 한눈에 보입니다.
- 청구 금액 카드는 시각적으로 강하고 이해하기 쉽습니다.
- 보호자가 민감하게 보는 비용 정보를 크게 보여주는 방향은 좋습니다.

사용자 불편 가능성:

1. 상단 back은 `g05-mypage.html`로 가지만, 하단 탭 active는 기록입니다. 결제 화면의 소속이 마이인지 기록인지 헷갈립니다.

2. 결제 관련 버튼 다수가 `href="#"`입니다.

3. 금액 카드, 납부 버튼, AI 비용 인사이트, 보험 적용 카드가 모두 큰 면적과 강한 blue/cyan 톤을 사용합니다. 하루안부 보호자앱의 차분한 안심 톤보다 핀테크 화면처럼 느껴질 수 있습니다.

4. 긴 결제 화면에서는 마지막 CTA/내역이 탭바 뒤에 들어갈 수 있습니다.

개선안:

- 결제/청구는 마이 하위로 고정
- 하단 active는 마이로 변경하거나 상세 화면에서는 탭바 숨김
- `href="#"`는 실제 액션/disabled/mock 상태로 명확히 표시
- 금액 카드만 hero로 유지
- AI 비용 인사이트와 보험 적용 카드는 flat default card로 낮춤
- blue/cyan 배경 면적을 줄이고 상태 배지와 버튼에만 색 사용

우선 수정:

- P0: 결제/청구의 소속 탭 결정
- P1: blue/cyan 면적 축소
- P1: 하단 safe padding 추가

## 8. 하위 화면

대상 파일: `g06-alert.html`, `g07-settings.html`, `g09-prescription.html`, `g10-timeline.html`

사용자 불편 가능성:

1. 일부는 `data-role="guardian"`이 있지만 `data-platform="mobile"`은 없습니다.

2. 대부분 `pretendard.css` + 화면 내부 토큰입니다.

3. 하위 화면마다 상단/하단 내비게이션 정책이 다를 가능성이 큽니다.

4. `g10-timeline.html`은 의료 도메인 컬러로 `#0891B2`, `#C62828`, `#1565C0` 같은 직접값을 사용합니다. red 계열이 실제 긴급 상황인지 단순 의료 분류인지 구분이 약해질 수 있습니다.

개선안:

- 모든 하위 화면에도 `data-role="guardian" data-platform="mobile"` 적용
- 하위 화면 정책 정의:
  - 상단: back + title + optional action
  - 하단: 메인 탭바 유지 또는 숨김 중 하나
  - AI FAB: 전역 유지 또는 특정 화면 숨김
- 의료 도메인 색도 semantic token 또는 domain token으로 정의
- danger/red는 SOS/즉시 대응에만 사용

## 디자인 시스템 v3.1과의 통일성 점검

잘 맞는 부분:

- 보호자앱 전체가 blue accent를 중심으로 움직입니다.
- 카드 radius와 부드러운 shadow는 v3.1의 편안한 헬스케어 톤과 잘 맞습니다.
- 일일 리포트, AI 인사이트, 가족/케어 맥락은 제품 정체성이 선명합니다.
- 탭바 + AI FAB 구조는 하루안부만의 전역 사용 패턴으로 발전 가능성이 있습니다.
- `g-home-v31-pilot.html`은 v3.1 시스템을 제대로 적용한 좋은 기준입니다.

어긋나는 부분:

- primitive color와 hard-coded rgba/hex가 너무 많습니다.
- 화면마다 탭바 CSS가 중복되어 v3.1 컴포넌트 규칙으로 보기 어렵습니다.
- flat-first라고 보기에는 일부 화면이 glass/gradient 면적에 많이 기대고 있습니다.
- `common.css`는 호환 레이어라고 되어 있지만, 실제 최신 화면은 이 레이어조차 일관되게 쓰지 않습니다.
- `data-role="guardian" data-platform="mobile"` 선언이 모든 화면에서 일관되게 쓰이지 않습니다.
- 파일럿과 실제 앱 구현이 분리되어 있습니다.

### P2: 심미성/완성도

3. AI 가이드 질문 카드의 반복 CTA를 줄여 화면을 덜 복잡하게 만들기

5. 체크/화살표 등 텍스트 기호를 iconify 아이콘으로 통일
6. `href="#"` mock action을 실제 동작, mock toast, disabled 중 하나로 명확히 처리
