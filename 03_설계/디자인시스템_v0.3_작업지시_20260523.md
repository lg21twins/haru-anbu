# 하루안부 디자인 시스템 v0.3 작업 지시서

작성일: 2026-05-23  
목적: v0.2에서 정리된 색상/토큰 audit 기반 위에, SVG 아이콘 정리와 시각 검증을 추가해 실제 화면 단위의 디자인 일관성을 관리한다.

## 1. 현재 상태 판단

v0.2 기준으로 색상 토큰과 직접 hex 사용 정리는 정상 궤도에 올라왔다.

- `.css` hex 누락 48건을 추가 발견하고 정리함
- `full_cleanup_summary_20260523.md`에서 “전 영역 PASS” 표현을 “audit v0.2 기준”으로 정정함
- “검사를 안 해서 0건”과 “검사 후 분류해서 0건”을 구분함
- SVG 75건은 v0.3 별도 작업으로 분리함
- `--ink-*`, `--surface-*` 와일드카드 허용은 임시 정책으로 남아 있음

따라서 v0.3의 목표는 더 많은 색상을 기계적으로 치환하는 것이 아니라, 예외를 좁히고 실제 화면에서 깨지는 부분을 검증하는 것이다.

## 2. v0.3 핵심 목표

1. SVG 75건을 무조건 변환하지 말고 성격별로 분류한다.
2. 아이콘 목적의 SVG는 `iconify-icon`으로 전환한다.
3. 차트, 브랜드, 장식, 프로그레스 링처럼 SVG 유지가 더 적절한 항목은 예외로 명시한다.
4. `--ink-*`, `--surface-*` 와일드카드 허용을 실제 사용 토큰명 중심으로 좁힌다.
5. 정적 audit 외에 화면 캡처 기반 `visual_check`를 도입한다.
6. audit이 실제로 위반을 잡는지 확인할 수 있는 테스트 fixture를 추가한다.

## 3. 작업 우선순위

### 1순위: SVG 75건 분류표 작성

대상:

- v10 의료진웹 대시보드: 43건
- v11 보호자앱: 15건
- v11 요양보호사앱: 10건
- v15 의료진앱: 6건
- v12 환자앱: 1건

분류 기준:

| 분류 | 의미 | 처리 |
| --- | --- | --- |
| iconify 전환 | 일반 UI 아이콘, 버튼 아이콘, 상태 아이콘 | `iconify-icon`으로 교체 |
| SVG 유지 | 브랜드, 로고, 차트, 프로그레스 링, 파형, 복잡한 시각화 | 예외 목록에 명시 |
| 검토 필요 | 아이콘인지 시각화인지 애매한 항목 | 파일/라인/용도 기록 후 판단 요청 |

결과물:

- `07_디자인/review-reports/svg_inventory_v0.3_20260523.md`

필수 포함 항목:

- 파일 경로
- 라인 번호
- 현재 SVG 용도
- 분류 결과
- 권장 처리
- 변환 우선순위

### 2순위: v10 의료진웹 대시보드 SVG 우선 정리

v10 의료진웹에 SVG가 43건으로 가장 많기 때문에 우선 처리한다.

작업 원칙:

- 작은 UI 아이콘은 `iconify-icon`으로 전환
- 차트, 그래프, 링, 브랜드성 시각 요소는 유지 가능
- 유지하는 SVG는 audit 예외 사유를 명확히 남김
- 직접 색상값이 SVG 내부에 있으면 가능한 토큰 기반 색상으로 변경

주의:

- SVG를 전부 일괄 삭제하거나 전부 iconify로 바꾸지 말 것
- 의료진 대시보드의 차트/시각화 표현이 깨지면 안 됨

### 3순위: 허용 와일드카드 축소

현재 `--ink-*`, `--surface-*` 허용은 v10 의료진웹의 자체 무채색 팔레트를 수용하기 위한 임시 정책이다.

v0.3에서는 다음처럼 좁힌다.

1. 실제 사용 중인 `--ink-*`, `--surface-*` 토큰 전체 목록을 추출한다.
2. 의미가 중복되는 토큰은 공통 토큰으로 합친다.
3. 계속 필요한 토큰만 명시 허용한다.
4. `allowed_local_token_patterns`에서 넓은 와일드카드는 제거하거나 최소화한다.

완료 기준:

- `--ink-*`, `--surface-*` 전체 와일드카드가 사라지거나, 남아 있다면 명확한 사유가 리포트에 기록되어야 한다.

### 4순위: visual_check 도입

정적 audit은 코드 규칙 위반을 잡지만, 실제 화면에서 디자인이 어색한지는 확인하지 못한다.

따라서 `07_디자인/scripts/visual_check.py`를 추가한다.

초기 범위:

- `07_디자인/role-component-board.html`
- 보호자앱 대표 홈
- 요양보호사앱 대표 홈
- 의료진앱 대표 홈
- 환자앱 대표 홈
- v10 의료진웹 대시보드 대표 화면

검증 항목:

- 페이지가 정상 렌더링되는지
- 주요 컴포넌트가 화면 밖으로 밀리지 않는지
- 헤더, 카드, 버튼, 탭바가 보이는지
- 캡처 이미지가 빈 화면이 아닌지
- 모바일 기준 화면에서 텍스트가 겹치지 않는지

결과물:

- `07_디자인/review-reports/visual_check_v0.3_20260523.md`
- 필요 시 `07_디자인/review-assets/visual-check/` 아래 캡처 저장

### 5순위: audit 테스트 fixture 추가

현재 audit은 실제 파일 대상으로만 검증되는 성격이 강하다. v0.3에서는 작은 테스트 fixture를 추가해 audit 규칙이 정상 동작하는지 확인한다.

추가할 fixture 예시:

- CSS 파일 안 직접 hex가 잡히는 케이스
- HTML inline style 안 hex가 잡히는 케이스
- 허용된 토큰 정의 파일은 통과하는 케이스
- 허용되지 않은 로컬 토큰 정의가 잡히는 케이스
- 일반 inline SVG가 잡히는 케이스
- 브랜드/차트/프로그레스 링 SVG 예외가 통과하는 케이스

권장 위치:

- `07_디자인/scripts/test_fixtures/`
- 또는 `07_디자인/review-rules/test_fixtures/`

완료 기준:

- fixture 실행 방법이 README 또는 리포트에 남아 있어야 함
- v0.3 이후 audit 수정 시 회귀 검사가 가능해야 함

- SVG 75건 전체가 분류되어 있음
- iconify로 바꿀 항목과 유지할 SVG가 구분되어 있음

- `visual_check` 초안 또는 실행 계획이 있음

## 6. 주의사항

- SVG를 기계적으로 전부 iconify로 바꾸지 말 것
- 의료진웹의 차트, 그래프, 링, 브랜드 표현은 화면 품질을 먼저 확인할 것
- 직접 hex를 새로 추가하지 말 것
- 이모지를 사용하지 말 것
- 새 아이콘은 `iconify-icon`으로 통일할 것
- 새 토큰은 기존 `tokens.css` 구조와 의미를 먼저 확인한 뒤 추가할 것
- 특정 화면만 예외 스타일을 넣기보다 공통 토큰 또는 컴포넌트 변형으로 해결 가능한지 먼저 판단할 것

## 7. Codex 검토 의견

현재 v0.2 상태는 다음 작업으로 넘어가도 괜찮다. 다만 아직 “디자인 시스템 완성”이라기보다는 “정적 색상 규칙을 정리한 상태”에 가깝다.

v0.3에서 SVG 분류, 예외 축소, 시각 검증까지 붙이면 이후에는 사용자가 화면 캡처와 수정 요청만 전달해도 디자인 시스템 일관성이 크게 깨지지 않는 구조로 운영할 수 있다.
