# Claude 전달용 UX/UI 수정요청서

**작성일**: 2026.05.09  
**대상 프로젝트**: 하루안부  
**목적**: 최신 사용자별 앱의 UX/UI 문제를 정리하고, Claude가 바로 수정 작업에 들어갈 수 있도록 우선순위와 변경 방향을 명확히 전달한다.

---

## 0. 반드시 지킬 규칙

1. UI와 문서에 이모지를 쓰지 않는다.
2. 아이콘은 `iconify-icon`을 사용한다. 가능하면 `fluent:*` 계열로 통일한다.
3. 기존 앱의 시각 언어를 완전히 갈아엎지 않는다.
4. 이번 수정의 목표는 기능 추가가 아니라 **인지 부하 감소와 핵심 행동 명확화**다.
5. 각 화면에서 사용자가 3초 안에 알아야 하는 것은 하나여야 한다.

---

## 1. 전체 진단

현재 앱들은 시각 완성도는 높지만, 대부분의 화면이 "준비한 기능을 많이 보여주는 목업"에 가깝다. 하루안부의 핵심 가치는 "매일의 안심"과 "업무 부담 감소"인데, 화면마다 데이터·카드·CTA가 많아 사용자가 바로 해야 할 행동이 흐려진다.

전체 수정 방향은 다음과 같다.

| 사용자 | 현재 문제 | 수정 방향 |
|---|---|---|
| 보호자 | 안심보다 데이터 해석을 먼저 요구함 | 오늘 상태, 사진, 핵심 3지표 중심 |
| 의료진 | 대시보드가 과밀하고 모든 정보가 중요해 보임 | 지금 처리할 일 중심 |
| 요양보호사 | 빠른 기록 앱인데 상세 기록 구조가 전면에 섞임 | 빠른 기록과 상세 기록 분리 |
| 환자 | 고령자에게 홈 정보량이 많음 | 가족, 지금 할 일, 도움 중심으로 축소 |

## 2. 보호자 앱 수정 요청

**대상 폴더**: `v11_보호자앱/`  
**핵심 파일**:

- `g-guardian-live.html`
- `g02-ai-report.html`
- `g03-sotong.html`
- `g03-chat.html`
- `g05-records.html`
- `g06-alert.html`
- `g08-billing.html`
- `g09-prescription.html`

### 2.1 문제

보호자 홈은 첫인상이 좋지만, 정보 블록이 너무 많다. 모먼트, 투약, 맥박, 기분, 식사, 수면, 활동, 위생, 일정, AI 인사이트가 동시에 떠서 보호자가 "어머니가 괜찮다"를 느끼기 전에 데이터를 해석해야 한다.

또한 홈과 리포트 상세의 수치가 일관되지 않는다. 예를 들어 홈에서는 투약이 `1/3`, 리포트에서는 `3/3`처럼 보이면 보호자는 앱을 신뢰하지 못한다.

### 2.2 수정 방향

보호자 홈은 "오늘 안심 확인" 화면으로 좁힌다.

상단 우선순위:

1. 오늘 안심 상태
2. 오늘의 순간 사진
3. 식사
4. 투약
5. 특이사항

제거 또는 하단 이동:

- 맥박
- 기분
- 수면
- 활동
- 위생
- 일정
- AI 인사이트 2개 동시 노출

### 2.3 구체 작업

#### g-guardian-live.html

- 홈 위젯을 8개에서 3개 중심으로 줄인다.
- 상단에 `오늘은 평소와 비슷한 하루예요` 같은 정성 상태 문구를 둔다.
- 점수형 표현은 쓰지 않는다.
- `AI 인사이트`는 한 개만 노출하거나 리포트 상세로 보낸다.
- `마지막 업데이트`, `작성자`, `보호자 도착 시각`을 작게 표시한다.

#### g02-ai-report.html

- `75점` 같은 점수형 표현을 제거한다.
- 상태 표현을 정성화한다.
  - 예: `평소와 비슷한 하루`
  - 예: `식사만 내일 한 번 더 확인하면 좋아요`
- 홈의 `오늘의 순간` 사진 카드가 리포트 상세에도 이어지게 한다.
- 투약/식사 수치는 홈과 동일한 기준으로 맞춘다.

#### g03-sotong.html / g03-chat.html

- `소통`과 `채팅`의 역할 중복을 줄인다.
- 최종 구조는 다음 중 하나로 정리한다.
  - `소통`: 알림, 문의, 채팅을 모두 포함하는 통합 피드
  - `채팅`: 1:1 대화만 담당하고 별도 탭에서 제외
- 보호자에게 필요한 분류는 `응답 필요`, `새 소식`, `가족 공유` 정도면 충분하다.

#### g06-alert.html

- 알림에는 발생 시각만이 아니라 도착 시각을 표시한다.
- 시설 신뢰를 보여주는 문구를 추가한다.
  - 예: `최근 긴급 알림 평균 4분 안에 도착`
  - 예: `이번 달 긴급 알림 지연 0건`

#### g08-billing.html

- 자동이체 화면에서 `D-12`처럼 압박을 주는 표현은 제거하거나 약화한다.
- 가족 분담 카드가 필요하다.
  - 민지, 서연, 태우 등 가족별 부담 비율
  - 이번 달 누가 얼마를 냈는지
  - 영수증 공유 버튼

#### g09-prescription.html

- 약 이름만 보여주지 말고 `왜 바뀌었는지`를 보여준다.
- 각 약 카드에 보호자가 알아야 할 주의사항을 1개씩 둔다.
- 의료 판단처럼 보이지 않도록 담당자 또는 시설 기록 기반 문구로 쓴다.

## 3. 의료진 웹 수정 요청

**대상 파일**: `v10_의료진웹/의료진_대시보드_v9.5.html`

### 3.1 문제

의료진 웹은 업무성은 좋지만, 대시보드가 과밀하다. KPI, 차트, 업무 타임라인, 주의 환자, AI 요약, 소통 패널이 동시에 중요해 보인다. 실제 근무자는 지금 바로 처리해야 할 일을 가장 먼저 봐야 한다.

### 3.2 수정 방향

첫 화면의 주인공은 `오늘 우선 순위`가 아니라 **지금 처리할 일**이어야 한다.

상단 우선순위:

1. 긴급 대응
2. 미투약 또는 투약 거부
3. 보호자 미응답
4. 인수인계 마감

KPI와 차트는 하단 보조 영역으로 내린다.

### 3.3 구체 작업

- `오늘 우선 순위`를 더 크고 명확한 `지금 처리할 일` 섹션으로 변경한다.
- 버튼 문구를 행동 중심으로 바꾼다.
  - `대응`보다 `혈압 재측정 기록`
  - `확인`보다 `보호자 알림 작성`
  - `작성`보다 `사고보고서 작성`
- 우측 소통 패널의 기본 탭은 `응답 필요`만 보여준다.
- 전체 채팅, 요양보호사 보고, 촉탁의 채널은 필터로 이동한다.
- AI 표현은 의료 판단처럼 보이지 않도록 낮춘다.
  - 금지: `이송 권장`
  - 대체: `담당자 확인 필요`
  - 금지: `프로토콜 상향 검토`
  - 대체: `최근 패턴 확인 필요`
- 의사와 간호사의 사용 맥락을 분리할 준비를 한다.
  - 간호사 기본: 투약, 기록, 보호자 문의, 인수인계
  - 의사 기본: 환자 타임라인, 처방 변경, 보고 회신

## 4. 요양보호사 앱 수정 요청

**대상 폴더**: `v11_요양보호사앱/`  
**핵심 파일**:

- `c01-today.html`
- `c02-checklist.html`
- `c03-sotong.html`
- `c04-mypage.html`

### 4.1 문제

요양보호사 앱은 현장성이 좋다. 다만 빠른 기록 도구여야 하는데, 화면에 진행률, 담당자 카드, 인수인계, 빠른 기록, 상세 스텝퍼가 섞이면서 관리자 대시보드처럼 느껴질 수 있다.

### 4.2 수정 방향

기본 사용 흐름은 다음처럼 단순해야 한다.

```
앱 열기
-> 지금 해야 할 일 확인
-> 5초 빠른 기록
-> 특이사항이 있을 때만 상세 기록
```

### 4.3 구체 작업

#### c01-today.html

- 첫 화면의 주인공을 `지금 해야 할 일 1개`로 고정한다.
- `담당 4명` 카드는 아래로 내린다.
- `5/9`, `완료 5`, `남은 4`, `담당 9명`처럼 숫자가 많은 요약은 줄인다.
- 문구는 행동형으로 바꾼다.
  - 예: `지금은 박영자 어르신 혈압 측정 시간입니다`

#### c02-checklist.html

- `빠른 기록`을 기본 모드로 둔다.
- 8단계 스텝퍼는 `상세 기록` 또는 `전체 점검` 버튼을 눌렀을 때만 열리게 한다.
- 빠른 기록은 다음 구조로 단순화한다.
  - 환자 선택
  - 항목 선택
  - 정상/주의/완료 선택
  - 저장
- 특이사항은 별도 강조한다.
  - `간호사에게 바로 보고`
  - `보호자 공유 여부`

#### c03-sotong.html

- 소통 화면은 `응답해야 할 것`과 `읽기만 하면 되는 것`을 분리한다.
- 인수인계 5필수 체크는 좋지만, 소통 화면 상단에 너무 강하면 대화 목적이 흐려질 수 있다.
- 빠른 보고 버튼은 유지하되, 보고 대상이 간호사인지 보호자인지 명확히 표시한다.

#### c04-mypage.html

- 마이페이지의 통계는 좋지만 MVP에서는 우선순위를 낮춘다.
- 출퇴근, 서비스 제공기록지, GPS, 전자서명은 실제 업무 핵심이므로 더 명확한 진입점으로 올린다.
- SOS 수신 알림은 끌 수 없게 하거나 끌 때 경고를 둔다.

## 5. 환자 앱 수정 요청

**대상 폴더**: `v12_환자앱/`  
**핵심 파일**:

- `p01-today.html`
- `p02-med-alert.html`
- `p03-call.html`
- `p05-voice.html`
- `p08-help.html`
- `p09-sos.html`
- `p10-med-done.html`

### 5.1 문제

환자 앱은 따뜻하고 보기 좋지만, 고령자 기준으로 홈 정보량이 많다. 가족 메시지, 빠른 답장, 가족 전화 3명, 약 복용, 오늘 일정 전체, 도움 요청이 한 화면에 동시에 있다.

### 5.2 수정 방향

환자 앱의 핵심은 다음 세 가지다.

1. 가족과 연결됨
2. 지금 해야 할 일
3. 도움 요청

홈은 이 세 가지 외의 정보를 줄인다.

### 5.3 구체 작업

#### p01-today.html

- 홈 주인공을 하나로 정한다.
  - 가족 사진/메시지가 있으면 그것을 주인공으로
  - 약 먹을 시간이면 약 복용을 주인공으로
- 오른쪽 일정 리스트는 `지금 할 일`과 `다음 할 일` 정도만 남긴다.
- `오늘 일정` 전체는 `p02-med-alert.html`로 이동한다.
- 상단 네비게이션은 가능하면 3개로 줄인다.
  - 오늘
  - 가족
  - 도움

#### p02-med-alert.html

- 일정 전체 화면은 유지하되, 현재 할 일을 더 크게 보여준다.
- 완료된 일정은 접거나 흐리게 처리한다.
- 하단 CTA는 하나만 둔다.

#### p08-help.html

- 도움 요청 항목 8개는 많다.
- 4개 정도로 줄인다.
  - 직원 불러줘요
  - 아파요
  - 화장실
  - 가족에게 연락
- 도움 요청은 가족보다 시설/직원에게 먼저 가야 한다.
- 가족 알림은 보조 옵션으로 둔다.

#### p09-sos.html

- `5초 뒤 119 자동 연결`은 실제 서비스 책임 리스크가 크다.
- 1차는 시설 긴급 호출로 바꾼다.
- 2차 선택지로 119 연결을 둔다.
- 취소 버튼은 가장 크게 유지한다.

## 7. 완료 기준

작업 후 각 사용자별 첫 화면에서 다음 질문에 답할 수 있어야 한다.

| 사용자 | 3초 안에 답해야 하는 질문 |
|---|---|
| 보호자 | 오늘 가족이 괜찮은가 |
| 의료진 | 지금 무엇을 먼저 처리해야 하는가 |
| 요양보호사 | 지금 누구의 무엇을 기록해야 하는가 |
| 환자 | 지금 봐야 할 것 또는 눌러야 할 것은 무엇인가 |

작업 완료 후 브라우저에서 각 대표 화면을 확인한다.

- 보호자: `g-guardian-live.html`, `g02-ai-report.html`
- 의료진: `의료진_대시보드_v9.5.html`
- 요양보호사: `c01-today.html`, `c02-checklist.html`
- 환자: `p01-today.html`, `p08-help.html`, `p09-sos.html`
