목표:

- 클로드/Codex가 같은 기준으로 검토하게 만든다.

## 3. 1차로 만들 파일

### 3.1 디자인 감사 스크립트

파일:

```text
07_디자인/scripts/design_audit.py
```

역할:

정적 코드 검사를 수행한다. 즉, HTML/CSS를 직접 읽어서 디자인 시스템 규칙 위반을 찾는다.

우선 검사할 항목:

- 직접 hex 사용 여부
- inline style 사용 여부
- 이모지 사용 여부
- `iconify-icon` 아닌 아이콘 사용 여부
- `components.css` import 누락 여부
- `tokens.css` import 누락 여부
- `col__hex` 같은 금지 클래스명 사용 여부
- `role-component-board.html`의 12섹션/36컬럼 구조 유지 여부
- guardian / caregiver / medical 컬럼 수 균형
- `preview.html`에서 `role-component-board.html` 링크 존재 여부
- 버전 표기 불일치 여부

명령 예시:

```bash
python3 07_디자인/scripts/design_audit.py --target role-component-board
```

또는 전체 모바일 앱 감사:

```bash
python3 07_디자인/scripts/design_audit.py --target mobile-apps
```

예시 기준:

```json
    "emoji": 0,
    "forbidden_classes": ["col__hex"]
  },
  "required_links": [
    "role-component-board.html"
  ]
}
```

## 6. 화면 수정 시 작업 흐름

앞으로 화면 하나를 수정할 때는 아래 순서를 따른다.

1. 수정 요청을 받는다.
2. 먼저 공통 컴포넌트 문제인지, 역할별 문제인지, 화면 개별 문제인지 판단한다.
3. 공통 문제면 `tokens.css` 또는 `components.css`를 먼저 수정한다.
4. 역할별 문제면 앱 공통 CSS를 수정한다.
5. 화면 개별 문제면 해당 HTML/CSS만 수정한다.
6. `design_audit.py`를 실행한다.
7. 대표 화면 3개와 보드를 확인한다.
8. 감사 리포트를 남긴다.

이 흐름은 피그마에서 인스턴스를 바로 고치지 않고, 메인 컴포넌트를 고칠지 먼저 판단하는 방식과 같다.
