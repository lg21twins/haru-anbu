# 의료진앱·요양보호사앱·보호자앱 디자인 통일 개선안

작성일: 2026-05-21  
대상: `v15_의료진앱/d01-home.html`, `v11_요양보호사앱/c01-today.html`, `v11_보호자앱/g-guardian-live.html`  
전제: 의료진앱은 `v15_의료진앱` 기준이며, `v10_의료진웹`은 이번 범위에서 제외한다.

## 결론

보호자홈은 현재의 양식과 감성 구조를 유지한다. 보호자홈의 핵심은 “안부를 먼저 말하고, 일일 리포트가 겹쳐 올라오는 구조”이므로 이 틀은 바꾸지 않는다.

반면 의료진앱과 요양보호사앱은 같은 그린 계열 디자인 토큰을 쓰되, 역할 차이를 컴포넌트 밀도와 정보 우선순위로 나눠야 한다. 지금은 두 앱이 같은 색과 비슷한 카드 구조를 쓰면서도, 의료진앱 홈이 요양보호사 홈을 문구만 바꾼 느낌이 강하다. 의료진앱은 “위험 환자 판단, 회진 진입, 인수인계 누락 방지”가 전면에 보여야 하고, 요양보호사앱은 “지금 할 일, 기록 완료, 현장 호출”이 전면에 보여야 한다.

## 현재 문제점

### 1. 의료진앱과 요양보호사앱의 역할 차이가 충분히 보이지 않음

의료진앱 `d01-home.html`의 현재 구조는 헤더, 근무 문구, 위험 카드, 다음 일정, 주의 환자 목록으로 되어 있다. 방향은 맞지만 화면 리듬과 카드 형태가 요양보호사앱 `c01-today.html`의 “근무 스트립, 지금 할 일, 인수인계, 관찰 카드”와 너무 비슷하다.

문제는 색이 같아서가 아니라, 같은 그린 토큰 안에서 의료진만의 판단 밀도와 임상 우선순위가 약하다는 점이다. 의료진 홈은 단순 일정 앱이 아니라 “지금 누구를 먼저 봐야 하는가”를 결정해주는 컨트롤 타워여야 한다.

### 2. 공통 토큰은 있지만 화면별 로컬 스타일이 너무 많음

이미 `07_디자인/tokens/tokens.css`에 `data-role="medical"`과 `data-role="caregiver"` 토큰이 있고, 둘 다 `--brand-green-500`, `--color-accent`, `--color-accent-soft`, `--color-accent-strong`을 공유한다.

하지만 실제 화면에는 `#F4FAF6`, `#EAF6EE`, `rgba(34,197,94,...)`, 직접 `box-shadow`, 직접 `border-radius`가 많이 남아 있다. 이 상태에서는 화면이 추가될수록 같은 앱 안에서도 카드 높이, 그림자, 헤더 밀도, 배경 톤이 조금씩 달라진다.

### 3. 보호자홈의 양식과 다른 앱의 홈 구조가 섞여 있음

보호자홈은 “상단 안부 대화 영역 + 아래에서 올라오는 일일 리포트 시트 + AI 채팅 전환”이라는 독자적인 형식이 강점이다. 이 양식은 보호자에게 맞는 정서적 구조다.

그런데 의료진앱과 요양보호사앱이 보호자홈의 일부 요소, 예를 들어 둥근 글라스 헤더, 아이콘 중심 탭바, 둥근 카드 톤만 가져오고 의미 구조는 각자 다르게 가져가다 보니 통일성이 “겉모양”에 머물고 있다.

### 4. 의료진앱 홈의 첫 화면 정보 위계가 애매함

현재 의료진앱 홈의 첫 번째 큰 카드는 “위험 · 즉시 보고 필요”다. 좋은 방향이지만, 카드 아래가 바로 “다음 일정”으로 이어져서 의료진의 핵심 업무인 회진, 처치 판단, 보호자 응대, 인수인계가 같은 레벨로 섞인다.

의료진 홈에서는 다음 정보가 첫 화면 안에 계층적으로 보여야 한다.

- 즉시 확인해야 할 위험 환자
- 회진 또는 처치 시작 버튼
- 미처리 임상 액션 수
- 인수인계 마감까지 남은 시간
- 보호자 또는 요양보호사 메시지 중 임상 응답 필요 항목

### 5. 요양보호사앱은 현장용 장점이 있으나 카드 개수가 많아질 위험이 있음

요양보호사앱 홈은 “지금 기록 시작” CTA가 명확하고, 48px 이상 터치 영역도 방향이 좋다. 다만 근무 스트립, 관찰 카드, 히어로, AI 인수인계, 담당자 상태가 같은 카드 언어로 누적되면 “무엇부터 눌러야 하는가”가 흐려질 수 있다.

요양보호사앱은 의료진앱보다 더 단순해야 한다. 현장에서는 판단보다 실행이 우선이므로, 홈에서 가장 중요한 버튼은 항상 “지금 기록 시작”, “호출”, “완료 처리” 중 하나여야 한다.

## 통합 디자인 방향

### 보호자앱

보호자앱은 현재 홈 양식을 유지한다.

- 유지할 것: 안부형 문장, AI 오브, 일일 리포트 시트, 카드형 건강 리포트, AI 채팅 전환
- 개선할 것: 리포트 카드 안의 직접 색상값을 토큰화하고, 의료진·요양보호사 앱과 같은 헤더/탭바 물성만 맞춘다
- 바꾸지 말 것: 보호자홈을 의료진식 대시보드나 요양보호사식 작업 리스트로 바꾸지 않는다

보호자홈의 역할은 “안심과 해석”이다. 데이터의 양보다 문장과 변화 감지가 중요하다.

### 요양보호사앱

요양보호사앱은 “현장 실행 도구”로 정리한다.

- 홈 첫 화면은 근무 상태보다 “지금 할 일”이 더 커야 한다
- CTA는 한 화면에 하나만 가장 강하게 보이게 한다
- AI 인수인계는 보조 카드로 유지하되, 접힘 상태에서는 2줄 요약까지만 둔다
- 위험·주의 상태는 의료진앱보다 덜 복잡하게, “호출 필요 여부”로 번역한다

### 의료진앱

의료진앱은 “임상 판단과 우선순위 도구”로 정리한다.

- 홈 첫 화면은 위험 환자 하나만 크게 보여주는 것이 아니라, 위험 근거와 다음 액션을 함께 보여준다
- “다음 일정”보다 “미처리 임상 액션”이 먼저 와야 한다
- 회진, 소통, 인수인계가 각각 분리된 탭으로 존재하므로 홈에서는 세 탭의 미처리 상태를 요약해야 한다
- 의료진은 요양보호사보다 정보 밀도가 높아도 되지만, 카드 수를 늘리는 방식은 피한다

## 의료진앱과 요양보호사앱 공통 토큰 제안

두 앱은 같은 토큰을 사용한다. 단, 토큰 값 자체를 다르게 만들지 말고, 같은 토큰 위에서 컴포넌트 밀도만 다르게 둔다.

| 항목 | 공통 토큰 | 의료진앱 적용 | 요양보호사앱 적용 |
|---|---|---|---|
| 역할 색 | `--color-accent`, `--color-accent-strong` | 위험 외 주요 액션, 회진 진입 | 기록 시작, 완료 처리 |
| 배경 | `--color-bg-role-gradient`, `--color-bg-canvas` | 차분하고 낮은 대비 | 동일 배경, 큰 카드로 가독성 확보 |
| 카드 | `--card-bg`, `--shadow-card-borderless`, `--radius-card` | 정보 밀도 높은 카드 | 터치 여백이 큰 카드 |
| 위험 | `--color-danger`, `--color-danger-soft` | 임상 위험, 즉시 확인 | 호출, 낙상, 의식 저하 |
| 주의 | `--color-warning`, `--color-warning-soft` | 관찰 필요, 추이 이상 | 미열, 식사 저하, 거부 |
| 텍스트 | `--color-text-primary`, `--color-text-secondary`, `--color-text-tertiary` | 숫자와 라벨 계층 분리 | 큰 본문과 명확한 보조 문장 |
| 터치 | `--size-touch-target` | 최소 48px | 최소 48px, 주요 버튼 52px |

### 새로 명확히 둘 토큰 별칭

아래 별칭을 `v15_의료진앱/_shared.css`와 `v11_요양보호사앱/caregiver.css`에서 같은 의미로 맞춘다.

```css
:root {
  --clinical-bg: var(--color-bg-canvas);
  --clinical-surface: var(--color-bg-surface);
  --clinical-card-radius: var(--radius-card, 20px);
  --clinical-card-shadow: var(--shadow-card-borderless);
  --clinical-action: var(--color-accent);
  --clinical-action-strong: var(--color-accent-strong);
  --clinical-critical: var(--color-danger);
  --clinical-warning: var(--color-warning);
}
```

이름을 `clinical`로 두면 의료진과 요양보호사가 같은 토큰군을 공유한다는 점이 명확해진다. 보호자앱은 이 별칭을 쓰지 않아도 된다.

## 홈 구조 통일안

세 앱은 같은 형태의 “홈”이 아니라, 같은 위치 규칙을 가진 다른 홈이어야 한다.

| 영역 | 보호자홈 | 요양보호사홈 | 의료진홈 |
|---|---|---|---|
| 상단 | 안부 문장, AI 대화 | 로고, 알림, 마이 | 로고, 알림, 마이 |
| 첫 핵심 | 오늘 안심 상태 | 지금 할 일 | 즉시 확인 환자 |
| 보조 핵심 | 일일 리포트 시트 | AI 인수인계 요약 | 미처리 임상 액션 요약 |
| 주요 CTA | AI에게 묻기, 리포트 보기 | 지금 기록 시작 | 지금 확인, 회진 시작 |
| 하단 | 5탭 + AI FAB | 4탭 + SOS | 4탭 + SOS |
| 감정 톤 | 따뜻함, 안심 | 명확함, 실행 | 긴장감, 판단 |

## 의료진앱 `d01-home.html` 구체 개선안

### 1. 첫 카드의 정보를 “위험 환자 + 근거 + 액션”으로 재구성

현재:

- 최명자 어르신 혈압 180/110
- 위치, 시간
- 지금 확인 CTA

개선:

- 위험 수준: 즉시 확인
- 환자명과 위치
- 근거: 혈압 180/110, 이전 측정 대비 상승, 최근 두통 호소
- 권장 액션: 재측정, 담당의 보고, 회진 우선순위 상향
- CTA 2개: `지금 확인`과 `회진 카드 열기`

카드 안에서 임상 근거가 한눈에 보여야 한다. 의료진에게는 “왜 위험한지”가 보호자보다 더 중요하다.

### 2. “다음 일정”을 “미처리 임상 액션”으로 변경

현재 “다음 일정”은 시간표 느낌이 강하다. 의료진 홈에서는 아래처럼 바꾼다.

- 위험 재측정 1건
- 투약 미완료 확인 2건
- 보호자 답변 대기 3건
- SBAR 인계 누락 1건

각 항목은 시간보다 상태와 액션 중심으로 표기한다.

예시:

```text
미처리 임상 액션
1. 혈압 재측정 필요 · 최명자 · 14:02 이후 미확인
2. 오전 투약 보류 확인 · 김순자 · 보호자 문의 있음
3. SBAR 인계 작성 필요 · 이브닝 전 2시간 18분
```

### 3. “주의 환자 4명”은 리스트보다 우선순위 큐로 보이게 한다

현재 리스트는 깔끔하지만 병동 우선순위가 강하게 느껴지지 않는다. 다음처럼 세 단계로 정리한다.

- `즉시`: 지금 확인 필요
- `오늘`: 회진 중 확인
- `관찰`: 추이만 확인

컬러는 빨강, 노랑, 그린을 쓰되 배경 전체를 물들이지 말고, 작은 상태 칩과 왼쪽 인디케이터로 제한한다.

### 4. 홈에 회진 진입 버튼을 더 강하게 둔다

의료진 모바일앱의 킬러 기능은 회진이다. 홈 하단 탭에 회진이 있어도, 홈 첫 화면에서 “회진 시작”이 보여야 한다.

권장 위치:

- 위험 카드 CTA 아래 보조 버튼
- 또는 미처리 임상 액션 섹션 우측 상단

권장 문구:

- `회진 시작`
- `위험 환자부터 회진`
- `최명자 어르신부터 보기`

## 요양보호사앱 `c01-today.html` 구체 개선안

### 1. 근무 스트립은 유지하되 더 작게

현재 근무 스트립은 완료 수, 남은 수, 담당 수, 피크 시간까지 담고 있다. 정보는 좋지만 첫 화면에서 큰 비중을 차지하면 “지금 할 일”이 밀린다.

개선:

- 근무 시간과 완료율만 노출
- 담당 수와 피크 시간은 펼침 또는 마이/일정으로 이동
- 스트립 높이는 56px 안팎으로 제한

### 2. 히어로 카드는 지금 작업만 남긴다

요양보호사 홈의 히어로는 잘 작동한다. 다만 문구를 더 실행 중심으로 고정한다.

권장 구조:

- 시간
- 대상자명
- 작업명
- 위치
- 가능 여부
- `지금 기록 시작` CTA

부가 정보는 CTA 위 한 줄까지만 둔다.

### 3. AI 인수인계는 접힌 상태에서 “확인해야 할 것”만 보여준다

현재 AI 인수인계는 좋은 기능이지만, 홈에서 너무 많은 설명을 담으면 카드 피로도가 생긴다.

개선:

- 접힘 상태: “야간 특이사항 4건 중 확인 필요 2건”
- 펼침 상태: 사람별 요약
- 위험 항목은 `호출 필요`, `관찰`, `기록만`으로 번역

요양보호사에게는 SBAR 같은 임상 형식보다 “지금 무엇을 해야 하는가”가 더 적합하다.

### 4. SOS는 의료진앱과 동일한 물성을 유지

요양보호사앱과 의료진앱 모두 하단 우측 SOS를 공유한다.

- 위치 동일
- 크기 동일
- 빨강 토큰 동일
- 짧게 누름과 길게 누름 동작 동일
- 의료진앱은 수신과 대응 중심, 요양보호사앱은 발신과 호출 중심으로 문구만 다르게 한다

## 보호자홈 유지 및 보정안

보호자홈은 지금 양식을 살린다. 특히 아래 구조는 유지한다.

- 상단 AI 오브와 안부형 문장
- `일일 리포트` 시트가 아래에서 올라오는 구조
- 투약, 맥박, 기분, 식사, 수면, 활동, 위생, 일정 카드
- AI 인사이트와 AI 채팅 연결
- 하단 5탭 + AI FAB

개선은 구조 변경이 아니라 토큰 정리 중심으로 한다.

### 보호자홈에서 정리할 부분

- 카드 내부 직접 색상값을 `--color-accent`, `--color-info-soft`, `--color-warning-soft`, `--color-danger`로 교체
- 체크 표시 문자 대신 `iconify-icon` 사용
- 리포트 카드의 수치 크기와 라운드 값을 공통 토큰으로 맞춤
- 의료진·요양보호사와 같은 로고 크기 28px, 글라스 버튼 물성 유지

보호자홈은 “데이터 대시보드”가 아니라 “안부 요약”이다. 의료진앱의 위험 카드 구조를 보호자홈에 가져오면 불안감이 커질 수 있으므로 피한다.

## 컴포넌트 통일 규칙

### 헤더

- 로고는 세 앱 모두 28px
- 우측 아이콘 버튼은 44px 또는 48px 터치 영역
- 배경은 `rgba(255,255,255,.55)` 직접값 대신 공통 클래스 또는 토큰 별칭으로 관리
- 헤더 안 텍스트는 보호자홈만 감성 문장 허용, 의료진·요양보호사는 기능형 문구

### 카드

- 일반 정보 카드는 흰색 surface
- glass는 헤더 버튼, 탭바, 모달 또는 특수 강조에만 사용
- 카드 radius는 18px 또는 20px 중 하나로 통일
- shadow는 `--shadow-card-borderless` 계열로 통일
- 위험 카드는 빨간 배경을 크게 쓰지 않고, 상태 칩과 CTA에만 빨강 사용

### 탭바

- 보호자앱: 5탭 + AI FAB 유지
- 요양보호사앱: 4탭 + SOS 유지
- 의료진앱: 4탭 + SOS 유지
- 아이콘 크기와 탭바 높이는 의료진·요양보호사 동일
- 탭 라벨은 한 앱 안에서 숨김/노출 정책을 통일한다

### 버튼

- 주요 CTA는 한 화면에 하나만 가장 강하게
- 의료진앱 주요 CTA: 위험 확인, 회진 시작
- 요양보호사앱 주요 CTA: 기록 시작, 완료 처리
- 보호자앱 주요 CTA: 리포트 보기, AI에게 묻기

## 작업 우선순위

### 1순위

- 의료진앱 `d01-home.html`의 “다음 일정”을 “미처리 임상 액션”으로 변경
- 의료진앱 첫 위험 카드에 위험 근거와 권장 액션 추가
- 의료진앱과 요양보호사앱의 카드 radius, shadow, 배경 직접값을 공통 토큰으로 정리
- 요양보호사앱 히어로 CTA를 첫 화면의 가장 강한 액션으로 유지

### 2순위

- 의료진앱 `d02-round.html`, `d03-inbox.html`, `d04-handover.html`의 헤더와 카드 물성 통일
- 요양보호사앱 `c02`, `c03`, `c04`의 탭바와 SOS 컴포넌트 완전 동일화
- 보호자홈 리포트 카드 내부 직접 색상값 정리

### 3순위

- 공통 clinical 컴포넌트 클래스 분리
- `home.css`의 홈 공통 토큰을 실제 화면에서 더 적극 사용
- 미리보기용 파일과 실제 화면 파일의 토큰 차이 정리

## 클로드에게 줄 구현 지시 요약

1. `v10_의료진웹`은 건드리지 말고 `v15_의료진앱`만 수정한다.
2. 보호자홈 `g-guardian-live.html`의 양식은 유지한다. 구조를 바꾸지 말고 색상과 컴포넌트 토큰만 정리한다.
3. 의료진앱과 요양보호사앱은 같은 그린 토큰을 쓴다. 단, 의료진은 판단 밀도, 요양보호사는 실행 가독성으로 차별화한다.
4. 의료진앱 홈은 요양보호사 홈처럼 “지금 할 일”만 보여주지 말고 “위험 근거, 미처리 임상 액션, 회진 진입”을 전면에 둔다.
5. 요양보호사앱 홈은 카드 수를 늘리지 말고 “지금 기록 시작”이 항상 가장 강한 CTA로 보이게 한다.
6. 세 앱 모두 이모지는 쓰지 않는다. 아이콘은 `iconify-icon`의 `fluent:*` 계열로 통일한다.
7. 화면 코드의 직접 hex, 직접 rgba, 직접 shadow를 줄이고 `tokens.css`와 앱별 shared CSS로 이동한다.

## 최종 방향

세 앱을 같은 화면으로 만들 필요는 없다. 통일성은 같은 색을 칠하는 것이 아니라, 같은 판단 체계를 가진 컴포넌트를 각 사용자 역할에 맞게 배치하는 것이다.

보호자앱은 안심을 준다.  
요양보호사앱은 바로 실행하게 한다.  
의료진앱은 우선순위를 판단하게 한다.

이 세 문장이 각 홈의 첫 화면에서 바로 느껴지면, 디자인 통일성과 역할 차별화가 동시에 살아난다.
