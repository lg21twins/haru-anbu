**프로젝트**: 하루안부  
**대상**: 보호자 앱, 의료진 웹, 요양보호사 앱, 환자 앱  
**목적**: Claude가 이 파일 하나만 읽고 UX/UI 수정 작업에 바로 들어갈 수 있도록 정리한 통합 지시서다.

---

## 1. 작업 목표

너는 하루안부 프로젝트의 UX/UI 리팩터링을 맡은 시니어 프로덕트 디자이너 겸 프론트엔드 구현자다.

이번 작업의 목표는 새 기능을 많이 추가하는 것이 아니다. 최신 앱들의 첫 화면과 핵심 플로우에서 **인지 부하를 줄이고, 사용자가 3초 안에 해야 할 일을 알 수 있게 만드는 것**이다.

전체 방향은 다음 한 문장으로 정리한다.

> 카드와 데이터를 더 보여주지 말고, 사용자별로 가장 중요한 행동 하나가 먼저 보이게 만든다.

## 3. 반드시 지킬 규칙

1. UI와 문서에 이모지를 쓰지 않는다.
2. 아이콘은 `iconify-icon`을 사용하고, 가능하면 `fluent:*` 계열로 통일한다.
3. 기존 디자인 톤을 완전히 갈아엎지 않는다.
4. 카드와 데이터를 추가하기보다 줄인다.
5. 기존 파일의 unrelated 변경은 건드리지 않는다.
6. 각 화면에서 사용자가 3초 안에 알아야 하는 것은 하나여야 한다.
7. 작업 후 수정 파일에서 이모지 사용 여부를 검색한다.

## 4. 전체 진단

현재 앱들은 시각 완성도는 높지만, 대부분의 화면이 "준비한 기능을 많이 보여주는 목업"에 가깝다. 하루안부의 핵심 가치는 "매일의 안심"과 "업무 부담 감소"인데, 화면마다 데이터, 카드, CTA가 많아 사용자가 바로 해야 할 행동이 흐려진다.

| 사용자 | 현재 문제 | 수정 방향 |
|---|---|---|
| 보호자 | 안심보다 데이터 해석을 먼저 요구함 | 오늘 상태, 사진, 핵심 3지표 중심 |
| 의료진 | 대시보드가 과밀하고 모든 정보가 중요해 보임 | 지금 처리할 일 중심 |
| 요양보호사 | 빠른 기록 앱인데 상세 기록 구조가 전면에 섞임 | 빠른 기록과 상세 기록 분리 |
| 환자 | 고령자에게 홈 정보량이 많음 | 가족, 지금 할 일, 도움 중심으로 축소 |

## 6. 보호자 앱

**대상 폴더**: `v11_보호자앱/`

### 핵심 문제

보호자 홈은 첫인상이 좋지만 정보 블록이 너무 많다. 모먼트, 투약, 맥박, 기분, 식사, 수면, 활동, 위생, 일정, AI 인사이트가 동시에 떠서 보호자가 "어머니가 괜찮다"를 느끼기 전에 데이터를 해석해야 한다.

또한 홈과 리포트 상세의 수치가 일관되지 않는다. 예를 들어 홈에서는 투약이 `1/3`, 리포트에서는 `3/3`처럼 보이면 보호자는 앱을 신뢰하지 못한다.

### 작업 1: `g-guardian-live.html`

홈을 "오늘 안심 확인" 화면으로 좁힌다.

상단 우선순위:

1. 오늘 안심 상태
2. 오늘의 순간 사진
3. 식사
4. 투약
5. 특이사항

구체 수정:

- 홈 위젯을 8개에서 3개 중심으로 줄인다.
- 상단에 `오늘은 평소와 비슷한 하루예요` 같은 정성 상태 문구를 둔다.
- 점수형 표현은 쓰지 않는다.
- `AI 인사이트`는 한 개만 노출하거나 리포트 상세로 보낸다.
- `마지막 업데이트`, `작성자`, `보호자 도착 시각`을 작게 표시한다.
- 맥박, 기분, 수면, 활동, 위생, 일정은 하단 보조 영역으로 내리거나 숨긴다.

### 작업 2: `g02-ai-report.html`

구체 수정:

- `75점` 같은 점수형 표현을 제거한다.
- 상태 표현을 정성화한다.
  - 예: `평소와 비슷한 하루`
  - 예: `식사만 내일 한 번 더 확인하면 좋아요`
- 홈의 `오늘의 순간` 사진 카드가 리포트 상세에도 이어지게 한다.
- 투약/식사 수치는 홈과 동일한 기준으로 맞춘다.
- 홈에서 리포트 상세로 들어왔을 때 정보가 더 풍부해져야지, 사진이나 맥락이 사라지면 안 된다.

### 후속 정리 대상

이번 라운드에서 시간이 남으면 아래도 정리한다.

- `g03-sotong.html` / `g03-chat.html`: 소통과 채팅의 역할 중복 축소
- `g06-alert.html`: 발생 시각뿐 아니라 보호자 도착 시각과 시설 응답성 표시
- `g08-billing.html`: 자동이체 화면의 압박 표현 완화, 가족 분담 카드 추가
- `g09-prescription.html`: 약 변경 사유와 보호자 주의사항 추가

## 7. 의료진 웹

**대상 파일**: `v10_의료진웹/의료진_대시보드_v9.5.html`

### 핵심 문제

의료진 웹은 업무성은 좋지만 대시보드가 과밀하다. KPI, 차트, 업무 타임라인, 주의 환자, AI 요약, 소통 패널이 동시에 중요해 보인다. 실제 근무자는 지금 바로 처리해야 할 일을 가장 먼저 봐야 한다.

### 작업

첫 화면의 주인공을 `오늘 우선 순위`가 아니라 `지금 처리할 일`로 만든다.

상단 우선순위:

1. 긴급 대응
2. 미투약 또는 투약 거부
3. 보호자 미응답
4. 인수인계 마감

구체 수정:

- `오늘 우선 순위`를 더 크고 명확한 `지금 처리할 일` 섹션으로 변경한다.
- KPI와 차트는 하단 보조 영역으로 내린다.
- 버튼 문구를 행동 중심으로 바꾼다.
  - `대응`보다 `혈압 재측정 기록`
  - `확인`보다 `보호자 알림 작성`
  - `작성`보다 `사고보고서 작성`
- 우측 소통 패널의 기본 탭은 `응답 필요` 중심으로 정리한다.
- 전체 채팅, 요양보호사 보고, 촉탁의 채널은 필터로 이동한다.
- AI 표현은 의료 판단처럼 보이지 않도록 낮춘다.
  - 금지: `이송 권장`
  - 대체: `담당자 확인 필요`
  - 금지: `프로토콜 상향 검토`
  - 대체: `최근 패턴 확인 필요`
- 의사와 간호사의 사용 맥락을 분리할 준비를 한다.
  - 간호사 기본: 투약, 기록, 보호자 문의, 인수인계
  - 의사 기본: 환자 타임라인, 처방 변경, 보고 회신

## 8. 요양보호사 앱

**대상 폴더**: `v11_요양보호사앱/`

### 핵심 문제

요양보호사 앱은 현장성이 좋다. 다만 빠른 기록 도구여야 하는데, 진행률, 담당자 카드, 인수인계, 빠른 기록, 상세 스텝퍼가 섞이면서 관리자 대시보드처럼 느껴질 수 있다.

기본 사용 흐름은 다음처럼 단순해야 한다.

```text
앱 열기
-> 지금 해야 할 일 확인
-> 5초 빠른 기록
-> 특이사항이 있을 때만 상세 기록
```

### 작업 1: `c01-today.html`

구체 수정:

- 첫 화면의 주인공을 `지금 해야 할 일 1개`로 고정한다.
- `담당 4명` 카드는 아래로 내린다.
- `5/9`, `완료 5`, `남은 4`, `담당 9명`처럼 숫자가 많은 요약은 줄인다.
- 문구는 행동형으로 바꾼다.
  - 예: `지금은 박영자 어르신 혈압 측정 시간입니다`

### 작업 2: `c02-checklist.html`

구체 수정:

- `빠른 기록`을 기본 모드로 둔다.
- 8단계 스텝퍼는 `상세 기록` 또는 `전체 점검` 버튼을 눌렀을 때만 열리게 한다.
- 빠른 기록은 다음 구조로 단순화한다.
  - 환자 선택
  - 항목 선택
  - 정상/주의/완료 선택
  - 저장
- 특이사항은 별도 강조한다.
  - `간호사에게 바로 보고`
  - `보호자 공유 여부`

### 후속 정리 대상

- `c03-sotong.html`: `응답해야 할 것`과 `읽기만 하면 되는 것` 분리
- `c04-mypage.html`: 출퇴근, 서비스 제공기록지, GPS, 전자서명 진입점 강화
- SOS 수신 알림은 끌 수 없게 하거나 끌 때 경고를 둔다.

## 9. 환자 앱

**대상 폴더**: `v12_환자앱/`

### 핵심 문제

환자 앱은 따뜻하고 보기 좋지만, 고령자 기준으로 홈 정보량이 많다. 가족 메시지, 빠른 답장, 가족 전화 3명, 약 복용, 오늘 일정 전체, 도움 요청이 한 화면에 동시에 있다.

환자 앱의 핵심은 세 가지다.

1. 가족과 연결됨
2. 지금 해야 할 일
3. 도움 요청

### 작업 1: `p01-today.html`

구체 수정:

- 홈 주인공을 하나로 정한다.
  - 가족 사진/메시지가 있으면 그것을 주인공으로 둔다.
  - 약 먹을 시간이면 약 복용을 주인공으로 둔다.
- 오른쪽 일정 리스트는 `지금 할 일`과 `다음 할 일` 정도만 남긴다.
- `오늘 일정` 전체는 `p02-med-alert.html`로 이동한다.
- 상단 네비게이션은 가능하면 3개로 줄인다.
  - 오늘
  - 가족
  - 도움

### 작업 2: `p08-help.html`

구체 수정:

- 도움 요청 항목 8개는 많다. 4개 정도로 줄인다.
  - 직원 불러줘요
  - 아파요
  - 화장실
  - 가족에게 연락
- 도움 요청은 가족보다 시설/직원에게 먼저 가야 한다.
- 가족 알림은 보조 옵션으로 둔다.

### 작업 3: `p09-sos.html`

구체 수정:

- `5초 뒤 119 자동 연결`은 실제 서비스 책임 리스크가 크다.
- 1차는 시설 긴급 호출로 바꾼다.
- 2차 선택지로 119 연결을 둔다.
- 취소 버튼은 가장 크게 유지한다.

## 10. 작업 방식

1. 대상 파일을 읽고 현재 구조를 파악한다.
2. 변경 전 간단한 작업 계획을 세운다.
3. 우선순위 순서대로 수정한다.
4. 한 번에 모든 화면을 무리하게 바꾸지 않는다.
5. 각 파일 수정 후 이모지 사용 여부를 검색한다.
6. 최종적으로 대표 화면을 브라우저에서 확인한다.

## 13. 성공 기준

| 사용자 | 3초 안에 답해야 하는 질문 |
|---|---|
| 보호자 | 오늘 가족이 괜찮은가 |
