# 하루안부 요양보호사 앱 개선 분석

작성일: 2026-05-13  
대상: `v11_요양보호사앱`  
분석 파일:

- `c01-today.html`
- `c02-checklist.html`
- `c03-sotong.html`
- `c04-mypage.html`
- `c04-schedule.html`
- `caregiver.css`
- `caregiver.js`

## 1. 총평

요양보호사 앱은 현재 방향 자체는 좋다. 특히 `c01-today.html` 홈 화면은 현장 사용성 관점에서 "지금 해야 할 일", "기록 시작", "AI 인수인계", "담당 어르신 상태"의 순서가 명확하다.

하지만 앱 전체를 보면 아직 같은 앱 안에서도 화면마다 다른 사람이 만든 것처럼 보이는 지점이 있다. 핵심 원인은 공통 CSS와 공통 JS가 존재하는데도, 각 HTML 파일이 헤더, 카드, 탭바, SOS, 토스트, 바텀시트를 다시 정의하고 있기 때문이다.

즉, 문제는 색상 하나가 아니라 "공통 골격이 아직 고정되지 않은 것"이다.

## 2. 우선 수정해야 할 P0

### 2.1 하단 탭바가 주요 콘텐츠를 가림

실제 390 x 844 모바일 뷰포트에서 확인한 결과, 일부 화면의 마지막 핵심 콘텐츠가 하단 탭바와 겹친다.

문제 화면:

- `c02-checklist.html`
- `c03-sotong.html`

확인 내용:

- `c02-checklist.html`의 `빠른 기록` 영역은 화면 하단 y=758부터 시작한다.
- 하단 탭바는 y=748부터 떠 있다.
- 따라서 `빠른 기록` 버튼 첫 줄이 탭바 아래로 들어간다.
- `c03-sotong.html`의 `오늘 보호자에게 공유` 카드도 같은 방식으로 탭바에 가려진다.

개선 방향:

- 모든 탭 화면의 `.app` 또는 메인 스크롤 컨테이너에 하단 고정 UI 높이보다 충분한 `padding-bottom`을 보장한다.
- 권장 기준:
  - `padding-bottom: calc(var(--safe-b) + var(--tab-h) + var(--tab-bot) + 72px);`
- 특히 CTA, 빠른 기록, 공유 버튼이 탭바 뒤에 들어가지 않도록 실제 모바일 폭에서 재검수한다.

완료 기준:

- 390 x 844에서 모든 주요 CTA가 탭바 위에 완전히 보인다.
- 마지막 카드의 버튼이 탭바와 24px 이상 떨어진다.

## 3. 앱 내부 통일성 문제

### 3.1 헤더가 화면마다 다름

현재 헤더 패턴:

- `c01-today.html`: 로고만 노출, 우측 알림/마이 버튼
- `c02-checklist.html`: 좌측 제목과 부제, 우측 음성 버튼
- `c03-sotong.html`: 24px 큰 제목, 우측 작성 버튼
- `c04-mypage.html`: 중앙 제목, 좌측 빈 48px 더미, 우측 설정 버튼
- `c04-schedule.html`: 좌측 뒤로, 중앙 제목, 우측 공유 버튼

문제:

- 같은 앱 안에서 정보 구조가 매번 바뀐다.
- 홈, 기록, 소통, 마이가 각각 다른 앱처럼 보인다.
- 보호자앱/의료진앱과 비교하기 전에 요양보호사 앱 내부의 헤더 규칙부터 고정해야 한다.

개선 방향:

공통 헤더 슬롯을 정한다.

- 좌측: 로고 또는 뒤로 버튼
- 중앙/본문 시작점: 화면 제목
- 우측: 최대 1~2개 액션
- 아이콘 버튼: 48px 터치 영역으로 통일
- 제목 크기:
  - 일반 탭 화면: 18px
  - 홈 화면: 로고 중심 또는 18px 타이틀
  - 상세/push 화면: 중앙 17~18px

추천 클래스:

- `.cg-header`
- `.cg-header__row`
- `.cg-header__title`
- `.cg-header__subtitle`
- `.cg-iconbtn`

현재 `caregiver.css`에 이미 유사 클래스가 있으므로 HTML별 `.header`, `.icon-btn` 재정의를 줄이고 공통 클래스로 회수한다.

## 4. 공통 컴포넌트 중복 문제

### 4.1 탭바가 각 HTML에 반복 정의됨

현재 `c01`, `c02`, `c03`, `c04-mypage`가 각각 `.bottom-bar`, `.tabbar`, `.tab`, `.sos` 또는 `.cg-sos` 스타일을 들고 있다.

문제:

- 공통 CSS인 `caregiver.css`에도 `.cg-bottombar`, `.cg-tabbar`, `.cg-tab`, `.cg-sos`가 있다.
- 하지만 각 화면에서 별도 `.bottom-bar .tabbar`를 다시 정의한다.
- 이후 보호자앱/의료진앱과 통합할 때 유지보수가 매우 어려워진다.

개선 방향:

- 하단 탭바는 `caregiver.css`의 공통 클래스로만 관리한다.
- HTML에서는 구조와 active 상태만 둔다.
- 예:
  - `.cg-bottombar`
  - `.cg-tabbar`
  - `.cg-tab`
  - `.cg-sos`

완료 기준:

- 탭바 스타일 정의는 `caregiver.css`에만 존재한다.
- 각 HTML의 `<style>` 안에서 `.bottom-bar`, `.tabbar`, `.tab`, `.sos` 재정의가 사라진다.

### 4.2 SOS 구현이 중복됨

현재 상태:

- `caregiver.js`에 `HaruCG.bindSOS()`, `HaruCG.installSOS()`가 있다.
- `c02`, `c03`, `c04-mypage`는 `cg-sos`와 `data-sos-bind` 패턴을 쓴다.
- 하지만 `c01-today.html`은 자체 SOS JS를 다시 구현한다.

문제:

- 긴급 기능은 중복 구현되면 위험하다.
- 화면마다 롱프레스, 카운트다운, 취소, 토스트 동작이 달라질 수 있다.
- 현업 앱에서 SOS는 가장 먼저 단일화해야 하는 기능이다.

개선 방향:

- `c01-today.html`의 자체 SOS 스크립트를 제거한다.
- 모든 화면이 `HaruCG.installSOS()`만 사용하게 한다.
- SOS 버튼 마크업도 `.cg-sos[data-sos-bind]`로 통일한다.

완료 기준:

- 모든 화면에서 짧은 탭: 유형 선택 시트
- 모든 화면에서 3초 길게 누름: 1초 카운트다운 후 발신
- 모든 화면에서 취소/토스트 문구가 동일

## 5. 디자인 시스템 준수 문제

### 5.1 `fluent:emoji-24-filled` 사용

프로젝트 규칙상 UI와 문서에서 이모지 사용은 금지되어 있다. 현재 실제 이모지 문자는 아니지만 `emoji` 계열 아이콘명이 남아 있어 규칙 위반으로 해석될 가능성이 크다.

발견 위치:

- `c02-checklist.html`: `fluent:emoji-24-filled`
- `c03-sotong.html`: `fluent:emoji-24-filled`

개선 방향:

맥락별 대체 아이콘:

- 인지·정서: `fluent:brain-circuit-24-filled`
- 기분·수면: `fluent:weather-moon-24-filled`
- 정서/안부: `fluent:heart-24-filled`

완료 기준:

- `rg -n "emoji|[😀-🙏🌀-🗿]" v11_요양보호사앱`에서 UI 파일 매칭 없음

### 5.2 인라인 SVG 로고 반복

현재 일부 화면에서 하루안부 로고 SVG가 HTML 내부에 반복된다.

발견 위치:

- `c01-today.html` 헤더 로고
- `c03-sotong.html` AI 아바타

개선 방향:

- 공통 로고 컴포넌트 또는 `iconify-icon` 대체가 가능하면 통일한다.
- SVG를 유지해야 한다면 공통 partial 개념으로 같은 크기, 같은 색상, 같은 aria-label을 사용한다.

## 6. 화면별 분석

### 6.1 `c01-today.html` 홈

장점:

- 홈의 정보 우선순위가 좋다.
- `근무 상태 -> 지금 할 일 -> 기록 시작 -> AI 인수인계 -> 관찰 카드 -> 담당 상태` 흐름이 현장 업무와 잘 맞는다.
- CTA `지금 기록 시작`이 명확하다.

문제:

- 자체 SOS JS가 있다.
- 자체 overlay/sheet/toast와 `HaruCG` overlay/toast가 함께 존재한다.
- 홈의 헤더는 로고 중심이고, 다른 탭은 제목 중심이라 내부 통일성이 떨어진다.
- 카드 스타일이 `#fff`, `rgba`, 로컬 그림자 등으로 직접 선언되어 공통 시스템과 분리되어 있다.

개선:

- 자체 SOS 구현 제거.
- 홈 전용 sheet와 `HaruCG.openSheet()` 역할을 정리한다.
- 홈 CTA 문구를 기록 화면 CTA와 맞춘다.
  - 추천: `박영자 혈당 기록하기`
- `shift`, `hero`, `handover`, `obs-card`, `roster-list`를 공통 카드 토큰 기반으로 정리한다.

### 6.2 `c02-checklist.html` 케어 기록

장점:

- 요양보호사 앱의 핵심 업무인 기록이 가장 잘 구현되어 있다.
- 환자별/시간순 토글, 빠른 기록, 환자 상세, 2x4 그리드 구조가 좋다.
- 오프라인 대기/음성 메모 같은 현장 기능이 반영되어 있다.

문제:

- 화면 밀도가 높아 첫 화면에서 정보가 과하다.
- 빠른 기록 영역이 탭바에 가려진다.
- `html` 기본 폰트가 17px이고 `--text-body`는 18px이라 다른 화면과 기준이 다르다.
- `fluent:emoji-24-filled`가 남아 있다.
- 탭바/SOS 스타일이 HTML 내부에 반복된다.

개선:

- 첫 화면에서는 최우선 1명 + 담당 리스트 + 빠른 기록 4개 정도만 보이게 압축한다.
- 빠른 기록 6개 전체는 한 줄 스크롤 또는 접힘 처리한다.
- 하단 여백을 늘려 탭바 겹침 제거.
- `fluent:emoji-24-filled` 대체.
- 탭바/SOS를 `caregiver.css` 공통 클래스로 이동.

### 6.3 `c03-sotong.html` 소통

장점:

- 인수인계 확인 카드가 업무 맥락에 맞다.
- 읽지 않음/오늘/이전 섹션 구조는 메시지 우선순위를 잡기에 좋다.
- 보호자 공유 CTA는 요양보호사의 실제 업무와 연결된다.

문제:

- 헤더 제목이 24px로 커서 다른 화면과 다르다.
- 메시지 앱, 알림함, 보호자 공유가 한 화면에 섞여 정보 목적이 흐려진다.
- 보호자 공유 카드가 첫 화면 하단에서 탭바와 겹친다.
- `fluent:emoji-24-filled`가 남아 있다.
- AI 아바타에 인라인 SVG 로고가 들어가 있다.

개선:

- 헤더를 18px 기준으로 낮춘다.
- 소통 화면의 첫 구조를 `긴급/간호사/보호자/AI` 우선순위로 재배치한다.
- 보호자 공유는 기록 완료 후 제안하거나 별도 카드로 상단/중단 위치를 재검토한다.
- 하단 여백을 늘려 탭바 겹침 제거.

### 6.4 `c04-mypage.html` 마이

장점:

- 프로필, 오늘 근무, 일정, 의무 진척도는 요양보호사 역할과 잘 맞는다.
- 근무/자격/교육/출퇴근 같은 직무 정보를 담은 점이 좋다.

문제:

- 화면이 너무 길다.
- 마이와 설정이 섞여 있다.
- 프로필, 근무, 일정, 진척도 이후에 서비스 기록/알림 설정/자격/앱 설정까지 모두 한 화면에 있어 탐색 피로가 크다.
- 중앙 제목 헤더가 다른 탭과 다르다.

개선:

- 마이 화면은 "내 근무 상태" 중심으로 줄인다.
- 알림 설정, 언어, 고객센터, 앱 설정은 별도 설정 화면으로 분리한다.
- 첫 화면에는 다음만 남긴다.
  - 프로필
  - 오늘 근무
  - 이번 주 일정 진입
  - 이달 의무 진척도
  - 주요 메뉴 3~4개

### 6.5 `c04-schedule.html` 일정

장점:

- 주간 리스트 중심이라 이해하기 쉽다.
- 복잡한 타임라인을 피한 점은 좋다.

문제:

- push 화면인데도 카드/메뉴/토스트 스타일을 다시 정의한다.
- 휴무 행이 138px로 과하게 커져 리스트 리듬이 깨진다.
- 공유 버튼의 목적이 약하다.

개선:

- 휴무 행도 56~64px 기준으로 맞춘다.
- 주간 요약과 리스트 카드 스타일을 마이 화면 카드와 통일한다.
- 공유 버튼은 "PDF 공유"보다 "근무표 공유"처럼 실제 행동명을 명확히 한다.

## 7. 폰트와 정보 밀도 기준

현재 상태:

- `c01`: 본문 18px
- `c02`: `html` 17px, 본문 18px
- `c03`: 본문 16px
- `c04-mypage`: 본문 16px
- `c04-schedule`: 본문 16px
- `caregiver.css`: `[data-role="caregiver"] body { font-size: 18px; }`

문제:

- 요양보호사 앱의 가장 중요한 정체성인 "현장에서 빠르게 보고 누르는 앱"이라는 기준이 화면마다 달라진다.

개선 기준:

- 본문 기본: 17px 또는 18px
- 카드 제목: 15~18px
- 보조 설명: 12~14px
- 메타/라벨: 11~12px
- 터치 영역: 최소 48px
- 주요 CTA: 50~52px

## 10. 완료 검수 체크리스트

- 390 x 844에서 모든 화면의 마지막 CTA가 탭바에 가려지지 않는다.
- 홈/기록/소통/마이 헤더가 같은 규칙으로 보인다.
- 모든 화면의 SOS 짧은 탭/롱프레스 동작이 동일하다.
- `rg -n "emoji|[😀-🙏🌀-🗿]" v11_요양보호사앱`에서 UI 위반이 없다.
- 탭바 스타일 정의가 각 HTML에 반복되지 않는다.
- 카드 radius, shadow, background가 화면마다 다르게 보이지 않는다.
- 요양보호사 앱 본문 글자 크기가 17~18px 기준으로 일관된다.
- 주요 버튼 높이가 48px 이상이다.
- c02, c03에서 탭바와 콘텐츠 겹침이 없다.

## 11. 클로드에게 줄 수정 프롬프트

아래 프롬프트를 그대로 복사해서 사용하면 된다.

```text
너는 하루안부 요양보호사 앱(v11_요양보호사앱)을 수정하는 프론트엔드/디자인시스템 엔지니어다.

반드시 아래 파일을 먼저 읽어라:
- v11_요양보호사앱/CODEX_CAREGIVER_APP_IMPROVEMENT_AUDIT_20260513.md
- v11_요양보호사앱/caregiver.css
- v11_요양보호사앱/caregiver.js
- v11_요양보호사앱/c01-today.html
- v11_요양보호사앱/c02-checklist.html
- v11_요양보호사앱/c03-sotong.html
- v11_요양보호사앱/c04-mypage.html
- v11_요양보호사앱/c04-schedule.html

목표:
요양보호사 앱 내부의 홈/기록/소통/마이/일정 화면이 같은 앱처럼 보이도록 공통 골격을 통일한다. 단순히 예쁘게 바꾸지 말고, 현장 요양보호사가 빠르게 보고 누를 수 있는 업무 앱으로 정리한다.

반드시 고칠 것:
1. c02-checklist.html과 c03-sotong.html에서 하단 탭바가 콘텐츠/CTA를 가리는 문제를 해결한다.
2. c01-today.html의 자체 SOS 구현을 제거하고, 모든 화면이 caregiver.js의 HaruCG.installSOS() 기반으로 동일하게 동작하게 한다.
3. 모든 화면의 헤더 규칙을 통일한다. 아이콘 버튼은 48px 터치 영역을 유지한다.
4. fluent:emoji-24-filled 또는 emoji 계열 아이콘을 제거하고 fluent 계열 의미 아이콘으로 대체한다.
5. 탭바, SOS, 토스트, 시트, 카드 공통 스타일은 caregiver.css로 최대한 회수하고 각 HTML의 중복 정의를 줄인다.
6. 요양보호사 앱의 본문 크기는 현장 사용성을 고려해 17~18px 기준으로 일관되게 정리한다.
7. c04-mypage.html은 너무 긴 설정/마이 혼합 화면이므로 첫 화면은 프로필, 오늘 근무, 일정, 의무 진척도 중심으로 보이게 정리한다.

제약:
- 이모지 금지. 아이콘은 iconify-icon의 fluent:* 계열을 사용한다.
- 기존 사용자 수정분을 임의로 되돌리지 않는다.
- 기능을 삭제하기보다 공통화하고 정리한다.
- 모바일 390 x 844 기준으로 실제 렌더링을 확인한다.

완료 후 검수:
- 390 x 844에서 c01/c02/c03/c04/c04-schedule을 확인한다.
- 마지막 CTA가 탭바에 가려지지 않는지 확인한다.
- rg -n "emoji|[😀-🙏🌀-🗿]" v11_요양보호사앱 결과를 확인한다.
- 어떤 파일을 어떻게 수정했는지 요약한다.
```
