# 의료진 모바일앱 v15 UX/UI 디자인 리뷰

작성일: 2026-05-10  
검토 대상: `v15_의료진앱` 전체  
검토 방식: 파일 전체 정독 기반 UX/UI 리뷰  
주요 관점: 디자인 시스템 통일성, 의료진 업무 흐름, 모바일 사용성, 심미성, 탭별 개선점

---

## 0. 먼저 결론

현재 의료진 앱은 보호자 앱보다 목적성이 훨씬 선명하다. 특히 `d02-round.html` 회진 모드, `d04-handover.html` 인수인계, `d-sos.html` SOS는 의료진 모바일앱으로서 필요한 장면을 잘 잡고 있다. “지금 해야 할 일”, “위험 환자”, “회진 기록”, “교대 전달”이 분리되어 있어 제품의 핵심 가치는 꽤 분명하다.

다만 디자인 시스템 관점에서는 아직 `07_디자인`의 v3.1 체계가 완전히 적용된 상태는 아니다. 모든 파일이 `tokens.css`를 import하고 `data-role="medical" data-platform="mobile"`을 쓰는 점은 좋지만, 실제 화면 스타일은 각 HTML 파일 내부 CSS에 많이 흩어져 있다. 색상, 그림자, 카드, 탭바, SOS FAB, 버튼, sheet, toast가 파일마다 반복 정의되어 있어 “같은 제품군의 같은 앱”이라는 통일감은 있으나 “완성된 디자인 시스템 위에 올라간 앱”처럼 보이기에는 아직 정리가 필요하다.

가장 먼저 고칠 것은 다음 5가지다.

1. `tokens.css`만 가져오고 끝내지 말고 `system/app.css`, `system/components.css`까지 연결해 공통 컴포넌트 기준을 맞춘다.
2. 각 파일 내부의 `--accent`, `--danger`, `--warn`, `--t1`, `--t2`, `--t3` 별칭과 하드코딩 색상을 디자인 시스템 semantic token으로 정리한다.
3. 40px 아이콘 버튼, 작은 토글 등 의료진 모바일 사용 기준에 부족한 터치 타깃을 48px 이상으로 맞춘다.
4. 하단 탭은 현재 아이콘만 있어 고압 업무 환경에서 인지성이 낮다. 최소 active 탭에는 텍스트 라벨을 붙이거나 전체 탭 라벨을 노출한다.
5. `href="#"`, toast-only 액션, mock 버튼이 많다. 의료 앱에서는 “누르면 무엇이 일어나는지”가 명확해야 하므로 비활성/준비중/실제 이동/확인 모달을 구분해야 한다.

## 2. 전체 디자인 시스템 통일성

### 잘 된 점

- 모든 주요 HTML 파일이 `<html lang="ko" data-role="medical" data-platform="mobile">`을 사용한다.
- 모든 주요 HTML 파일이 `../07_디자인/tokens/tokens.css`를 import한다.
- 배경, 카드, 알림, 탭바, FAB, sheet, toast의 톤이 대체로 비슷해서 앱 전체가 완전히 따로 노는 느낌은 아니다.
- 의료진 앱이라는 역할에 맞게 초록/청록 계열을 주색으로 쓰고, 위험/주의 상태에는 red/orange 계열을 배치한 방향은 적절하다.
- 화면마다 상단 appbar, 하단 tabbar, 중앙 카드형 업무 목록 구조가 반복되어 기본적인 제품 일관성은 있다.

### 문제점

현재 구조는 “디자인 시스템을 참조하는 화면”이지 “디자인 시스템으로 구성된 화면”은 아니다. 각 파일마다 다음 스타일이 반복 정의되어 있다.

- `:root`의 `--accent`, `--accent-soft`, `--accent-strong`, `--danger`, `--warn`, `--t1`, `--t2`, `--t3`
- `body` 배경색과 radial/linear background
- `.appbar`
- `.icon-btn`
- `.card`
- `.tabbar`
- `.sos-fab`
- `.toast`
- `.sheet`, `.overlay`

이렇게 되면 Claude가 한 화면을 고쳐도 다른 화면에는 반영되지 않는다. 나중에 색상, radius, shadow, spacing을 한 번에 바꾸기 어렵고, 파일별로 미묘한 차이가 계속 생긴다.

### 개선안

- `07_디자인/system/app.css`와 `07_디자인/system/components.css`를 의료진 앱에도 연결한다.
- 의료진 앱 전용으로 필요한 것이 있다면 `07_디자인/system/medical-mobile.css` 또는 v15 내부 공통 CSS를 만든다.
- 파일 내부 CSS는 화면 특화 layout만 남기고, 공통 컴포넌트 스타일은 제거한다.
- 하드코딩된 색상은 가능한 한 semantic token으로 치환한다.

우선순위:

1. 공통 app shell: body, appbar, safe-area, mobile frame
2. 공통 components: icon button, card, status badge, tabbar, FAB, toast, sheet
3. 화면별 특화 컴포넌트: round patient card, SBAR card, inbox thread

## 3. 전체 심미성

### 현재 인상

전반적으로 깔끔하고, 의료진 앱답게 실용적인 느낌이 있다. 보호자 앱보다 장식성이 적고 정보 밀도가 높아서 업무용 제품에 더 잘 맞는다. 특히 회진 모드와 인수인계 화면은 “의료진이 실제로 바쁠 때 쓸 앱”이라는 느낌이 살아 있다.

하지만 완성도 면에서는 아직 프로토타입의 냄새가 남아 있다. 이유는 다음과 같다.

- 카드와 배경이 화면마다 비슷하지만 정확히 같은 체계로 보이지 않는다.
- 일부 화면은 그림자와 색상 면적이 많아 약간 무겁다.
- 위험/주의/정상 상태의 시각 언어가 화면마다 살짝 다르다.
- 하단 탭이 아이콘만 있어서 전문 앱치고는 정보 구조가 덜 친절하다.
- `#`, toast-only 버튼이 많아 “진짜 제품”보다 “시연용 목업” 느낌이 난다.

### 개선 방향

의료진 앱은 예쁘게 꾸미는 것보다 “판단이 빠르고 실수 가능성이 낮은 화면”이 더 중요하다. 따라서 심미성은 다음 방향으로 잡는 것이 좋다.

- 색상 면적은 줄이고, 상태 표현은 badge/chip/left border/icon으로 정리한다.
- 카드 shadow는 줄이고 border와 배경 대비로 계층을 만든다.
- 위험/주의/관찰/정상은 앱 전체에서 동일한 색상, 아이콘, 문구 규칙을 사용한다.
- CTA는 한 화면에 1개 primary, 나머지는 secondary/ghost로 정리한다.
- 의료진의 피로도를 고려해 다크/나이트 모드도 같은 컴포넌트 체계로 고려한다.

## 4. 전체 UX 구조

### 잘 된 점

- 탭 구조가 단순하다: 지금, 회진, 소통, 인수인계.
- 마이는 탭에서 빼고 헤더 우측에 둔 결정은 의료진 업무 흐름상 이해된다.
- SOS는 독립 FAB와 fullscreen으로 분리되어 임상 상황에 맞다.
- 회진 모드가 가장 깊고 강력하게 설계되어 있어 앱의 핵심 사용성이 살아 있다.
- 인수인계는 SBAR 중심으로 구성되어 의료 현장 언어와 잘 맞는다.

### 문제점

#### 4.1 하단 탭에 텍스트 라벨이 없다

현재 하단 탭은 아이콘 중심이며 `aria-label`만 있다. 의료진 앱은 일반 소비자 앱보다 빠른 인지가 중요하다. 특히 바쁜 회진 중에는 아이콘만 보고 `소통`과 `인수인계`를 즉시 구분하기 어렵다.

개선안:

- 전체 탭에 짧은 라벨을 표시한다.
- 공간이 부족하면 active 탭에만 라벨을 표시한다.
- 라벨은 `지금`, `회진`, `소통`, `인계` 정도로 짧게 유지한다.

#### 4.2 마이 화면의 현재 위치가 애매하다

`d05-mypage.html`은 하단 탭바를 유지하지만 active 탭이 없다. 사용자 입장에서는 “내가 어느 탭에 있는지”가 흐려진다. 헤더에서 들어온 보조 화면이라는 점은 이해되지만, 탭바가 그대로 있으면 어느 탭에도 속하지 않은 화면처럼 보인다.

개선안:

- 마이 화면에서는 하단 탭바를 숨기고 상단 back 중심의 detail 화면으로 처리한다.
- 또는 탭바 위에 “마이” context bar를 추가한다.
- 또는 헤더 우측 profile 버튼을 active 상태로 만들고 하단 탭은 그대로 둔다.

#### 4.3 mock 액션이 많아 신뢰감이 떨어질 수 있다

`href="#"`, toast-only 액션, 실제 동작 없는 버튼이 여러 화면에 있다. 프로토타입에서는 괜찮지만, 의료 앱에서는 누른 뒤 결과가 불분명하면 불안감이 커진다.

개선안:

- 구현되지 않은 액션은 disabled 처리하거나 “준비중” 상태로 명확히 표시한다.
- 위험/응급/전송 계열 액션은 toast만 띄우지 말고 detail sheet 또는 confirmation modal을 연다.
- `href="#"`는 실제 목적지, `button`, 또는 disabled affordance로 바꾼다.

#### 4.4 터치 타깃이 원칙보다 작다

README에는 `touch >=48x48` 원칙이 있다. 하지만 `.icon-btn`이 40x40으로 정의된 파일이 많고, 일부 toggle도 실제 터치 영역이 작다.

개선안:

- 모든 icon button은 최소 48x48로 통일한다.
- 시각적으로는 40px 원형처럼 보여도 hit area는 48px 이상 확보한다.
- toggle은 row 전체를 클릭 가능하게 만들고, 토글 자체도 44px 이상으로 키운다.

## 5. 탭별 상세 리뷰

## 5.1 `d01-home.html` - 지금 탭

### 좋은 점

- “오늘의 핵심 업무”를 가장 먼저 보여주는 구조가 좋다.
- 위험/주의 환자, 다음 할 일, 회진 진입이 빠르게 연결된다.
- 상단의 알림과 마이 진입 구조가 명확하다.
- 의료진 앱 첫 화면으로서 장식보다 업무를 우선하는 점이 적절하다.

### 불편할 수 있는 점

#### 위험 카드의 긴급도 계층이 더 명확해야 한다

위험 환자 카드와 SOS가 모두 빨간 계열로 강하게 보이면, “지금 확인해야 할 위험”과 “즉시 응급 대응”의 차이가 흐려질 수 있다.

개선안:

- 위험 환자는 `critical alert` 카드로, SOS는 별도의 `emergency action`으로 시각 언어를 분리한다.
- 위험 카드에는 “확인 필요”, “N분 전”, “담당자”, “다음 행동”이 한눈에 보여야 한다.
- SOS와 같은 빨간 면적을 쓰기보다 red badge + left rail 정도로 줄여도 좋다.

#### 하단 탭이 아이콘만 있어서 첫 사용자에게 불친절하다

홈에서 탭 구조를 처음 학습해야 하는데 아이콘만 있으면 메뉴 의미가 느리게 전달된다.

개선안:

- active 탭 `지금`만이라도 텍스트를 노출한다.
- 가능하면 전체 탭 라벨을 노출한다.

#### 마이 진입이 헤더 우측에 숨어 있다

README상 의도는 이해되지만, 계정/근무/설정이 많은 앱이라면 마이 진입은 조금 더 명확해야 한다.

개선안:

- 프로필 아이콘 옆에 작은 상태점 또는 근무 상태를 표시한다.
- 마이 화면에서 돌아왔을 때 사용자가 “업무 탭과 개인 설정은 분리되어 있다”고 이해하게 한다.

### 우선 수정

- 홈의 danger/critical 카드 스타일을 SOS와 분리한다.
- 하단 탭 active 라벨을 표시한다.
- icon button hit area를 48px 이상으로 조정한다.

## 5.2 `d02-round.html` - 회진 모드

### 좋은 점

- 이 앱에서 가장 강한 화면이다.
- 회진 진행률, 환자 카드, 음성 기록, AI 판단, 빠른 처방, 다음 환자 이동이 하나의 흐름으로 잘 묶여 있다.
- 회진 중 의료진이 실제로 필요한 “기록 속도”와 “다음 행동”을 잘 고려했다.
- 시작 화면과 진행 화면이 분리되어 있어 업무 진입이 자연스럽다.

### 불편할 수 있는 점

#### 화면 밀도가 높아 실사용 중 피로할 수 있다

회진 모드는 기능이 많다. 환자 정보, 위험도, 음성 기록, 빠른 처방, AI 판단, 저장, 다음 환자 이동, 환자 리스트 sheet가 한 화면에 몰린다. 기능 자체는 좋지만 모바일에서는 긴장도가 높은 화면이 될 수 있다.

개선안:

- 기본 상태에서는 핵심 3개만 보이게 한다: 환자 상태, 음성 기록, 다음 행동.
- AI 판단/빠른 처방/보조 기록은 접힘 영역 또는 bottom sheet로 분리한다.
- 회진 중 “지금 해야 할 버튼”은 하나만 primary로 유지한다.

#### AI 응급판단 문구가 너무 결정적으로 보일 수 있다

“AI 응급판단”은 의료진에게 유용하지만, 표현이 강하면 AI가 최종 판단을 내리는 것처럼 보일 수 있다. 의료 앱에서는 책임 주체가 중요하다.

개선안:

- “AI 응급판단”보다 “AI 위험 신호 제안” 또는 “AI 보조 판단”으로 낮춘다.
- 정상/관찰/주의/위험 선택 후에는 의료진 확인 상태를 명시한다.
- 위험 선택 시 단순 toast가 아니라 확인 sheet를 열어 “담당자 호출”, “인수인계 추가”, “SOS 전환”을 고르게 한다.

#### 진행률 표현이 혼동될 수 있다

시작 화면에서는 `8/15 완료`처럼 보이고, 진행 화면에서는 현재 환자 index처럼 보이는 값이 섞일 가능성이 있다. 완료 수와 현재 순번은 다른 정보다.

개선안:

- 완료 기준: `8/15 완료`
- 현재 순번 기준: `9번째 환자`
- 두 정보를 시각적으로 분리한다.

#### `?focus=10` 같은 이동은 좋지만 환자 컨텍스트가 더 선명해야 한다

홈에서 위험 환자나 특정 환자를 눌러 회진 화면으로 들어올 수 있는 점은 좋다. 다만 진입 후 사용자는 “왜 이 환자로 열렸는지” 알아야 한다.

개선안:

- 특정 환자로 진입하면 상단에 `주의 환자에서 열림`, `알림에서 열림` 같은 작은 context chip을 보여준다.
- context chip은 일정 시간 뒤 사라지거나, 사용자가 닫을 수 있게 한다.

### 우선 수정

- `icon-btn` 40px 문제를 먼저 고친다.
- AI 판단 문구와 위험 선택 후 행동 흐름을 수정한다.
- 진행률과 현재 순번을 분리한다.
- 회진 화면의 secondary 기능을 접힘/시트로 정리한다.

## 5.3 `d03-inbox.html` - 통합 소통

### 좋은 점

- 의료진이 봐야 할 메시지를 보호자/기관/AI 알림으로 한데 모은 방향이 좋다.
- 자동 회신 토글, 추천 답변, 템플릿은 실제 업무 부담을 줄이는 기능이다.
- urgent alert를 상단에 올린 점은 좋다.

### 불편할 수 있는 점

#### 필터 버튼이 실제로 필터링되는지 불분명하다

상단 필터가 있어 보이지만 파일 기준으로는 실제 필터 동작이 명확하지 않다. 누르면 상태가 바뀌는지, 목록이 줄어드는지, 몇 개가 남는지 알기 어렵다.

개선안:

- 필터 선택 시 active 상태와 목록 count를 바꾼다.
- 구현 전이면 비활성 또는 시각적으로 “준비중” 처리한다.
- urgent/보호자/기관/AI 알림의 분류 기준을 명확히 한다.

#### urgent alert가 toast-only면 위험하다

AI 위험 알림이나 urgent thread가 단순 toast로 끝나면 의료진은 실제 detail을 확인하지 못한다.

개선안:

- urgent alert 클릭 시 detail sheet를 연다.
- detail sheet에는 환자, 발생 시각, 관찰 지표, 추천 행동, 확인 버튼을 넣는다.
- 확인 후 `확인됨`, `담당자 배정`, `인수인계 추가` 같은 상태를 남긴다.

#### 자동 답변은 신뢰/통제 UI가 더 필요하다

자동 회신은 의료진 업무를 줄여주지만, 의료 커뮤니케이션에서는 오해 가능성이 있다. 현재는 토글이 너무 가볍게 느껴질 수 있다.

개선안:

- 자동 답변 상태에 “현재 회진 중 자동 안내”처럼 구체 문구를 붙인다.
- 자동 답변은 보호자에게 발송되기 전 preview 또는 로그가 필요하다.
- 자동 답변 on/off는 토글 row 전체가 클릭 가능해야 한다.

#### 메시지 톤이 일부 캐주얼하다

의료진 앱에서는 감정적으로 부드럽되 너무 채팅앱처럼 가벼우면 신뢰감이 떨어질 수 있다. 예를 들어 웃는 표정 텍스트나 과하게 구어체인 문장은 임상 업무 화면과 어울리지 않을 수 있다.

개선안:

- 보호자에게 보낼 문구는 정중하고 짧은 문장으로 통일한다.
- 캐주얼한 표현은 “안심 안내”, “확인 완료”, “추가 확인 후 답변” 같은 임상 톤으로 바꾼다.

### 우선 수정

- urgent alert 클릭 시 실제 detail sheet를 만든다.
- 필터 active/count 상태를 구현한다.
- 자동 답변 토글에 설명과 로그를 추가한다.
- mock `href="#"` 액션을 정리한다.

## 5.4 `d04-handover.html` - 인수인계

### 좋은 점

- SBAR 기반 구조는 의료진 업무에 잘 맞는다.
- 인수인계 항목, 체크리스트, 메모, 음성 기록 흐름이 설득력 있다.
- 교대 전후의 업무 누락을 줄이는 방향이 명확하다.
- 카드 제목과 상태 정보가 비교적 잘 정리되어 있다.

### 불편할 수 있는 점

#### SBAR의 Situation이 항상 danger처럼 보일 수 있다

예시 환자 때문에 빨간 강조가 들어간 것은 이해되지만, 모든 Situation이 위험 상태는 아니다. SBAR 컴포넌트 기본 스타일이 danger처럼 굳어지면 정보 위계가 왜곡될 수 있다.

개선안:

- SBAR 항목 자체는 neutral로 두고, 위험 상태가 있을 때만 danger modifier를 붙인다.
- `S`, `B`, `A`, `R` 각 항목의 기본 색상은 같은 체계로 유지한다.
- 위험도는 별도 badge로 분리한다.

#### 전송 액션은 확인 절차가 필요하다

`교대조에게 전송`은 임상적으로 중요한 액션이다. 단순 버튼이나 toast보다 전송 전 확인이 필요하다.

개선안:

- 미확인 체크리스트가 있으면 전송 전 경고를 띄운다.
- 전송 sheet에 수신자, 포함 항목, 미확인 항목, 긴급 항목을 요약한다.
- 전송 후에는 `전송됨`, `읽음`, `확인 필요` 상태를 보여준다.

#### 숫자/기호 표현을 디자인 시스템 방식으로 통일해야 한다

현재 일부 안내에 circled number 같은 특수문자 스타일이 보인다. 문서 규칙상 이모지는 금지되어 있고, 의료 앱 UI에서는 특수문자 장식보다 일반 번호/칩/아이콘 컴포넌트가 더 안정적이다.

개선안:

- `1. 2. 3. 4.` 형태의 ordered list로 바꾼다.
- 또는 숫자 chip 컴포넌트를 만든다.
- 방향 표시가 필요하면 텍스트 기호보다 iconify 아이콘을 사용한다.

### 우선 수정

- SBAR danger 표현을 modifier 방식으로 바꾼다.
- 전송 confirmation sheet를 추가한다.
- 특수문자 기반 번호/방향 표현을 컴포넌트로 치환한다.

## 5.5 `d05-mypage.html` - 마이

### 좋은 점

- 근무 상태, GPS 근무, 야간 모드, 도구, 도움말을 모은 구조가 좋다.
- 의료진 앱의 보조 설정 영역으로 필요한 항목들이 꽤 잘 잡혀 있다.
- 웹 대시보드 연결, Watch, lockscreen widget 같은 확장 방향도 좋다.

### 불편할 수 있는 점

#### 마이 화면인데 하단 업무 탭이 그대로 있어 위치감이 약하다

마이는 업무 탭 밖에 있는 보조 화면이다. 그런데 하단 탭이 그대로 있고 active 탭이 없으면 현재 위치를 이해하기 어렵다.

개선안:

- 마이 화면에서는 하단 탭을 제거하고 detail 화면으로 처리한다.
- 또는 상단에 `마이` active context를 강하게 준다.
- 업무 탭으로 돌아가는 동선을 명확히 한다.

#### 토글과 설정 row의 터치 영역이 작을 수 있다

토글 자체가 작아 보이고, row 전체 클릭 가능 여부가 명확하지 않다.

개선안:

- row 전체를 클릭 가능하게 만들고 cursor/active state를 준다.
- 토글은 최소 44px 이상, 전체 hit area는 48px 이상으로 잡는다.
- 변경된 설정은 즉시 저장 상태 또는 toast보다 더 명확한 상태 피드백을 준다.

#### 기능 목록이 많지만 실제 구현 여부가 흐리다

빠른 처방, 답변 템플릿, Watch, 잠금화면 위젯, 근무표, 활동 리포트, STT 보정 등 좋은 기능이 많다. 하지만 너무 많이 노출되면 핵심 업무보다 보조 기능이 복잡하게 느껴진다.

개선안:

- 마이 화면은 `계정/근무`, `앱 설정`, `연동`, `지원` 정도로 묶는다.
- 아직 구현 전인 기능은 `준비중` badge를 붙인다.
- 실제 업무 빈도가 높은 것만 상단에 둔다.

### 우선 수정

- 마이 화면의 navigation context를 정리한다.
- 토글 hit area를 키운다.
- 준비중 기능과 실제 사용 가능한 기능을 구분한다.

## 5.6 `d-sos.html` - SOS fullscreen

### 좋은 점

- 일반 탭에서 분리된 fullscreen 구조는 적절하다.
- 빨간 계열의 강한 시각 언어는 응급 상황에 맞다.
- 위치, 담당자, 전화, 채팅, 상황 종료 같은 핵심 액션이 모여 있다.
- 하단 탭바를 제거한 점도 좋다.

### 불편할 수 있는 점

#### 닫기/종료 동작이 너무 쉽게 보일 수 있다

SOS는 의료 앱에서 가장 위험한 액션이다. 닫기나 상황 종료가 너무 쉽게 동작하면 실수로 종료할 가능성이 있다.

개선안:

- 닫기 버튼은 단순 close가 아니라 `취소 사유`, `오등록`, `상황 종료` 중 하나를 선택하게 한다.
- 상황 종료는 확인 modal을 거친다.
- 종료 후 로그가 남는다는 문구를 표시한다.

#### 전화 연결은 오작동 방지 장치가 필요하다

`119 연결` 같은 액션은 즉시 실행되면 위험할 수 있다.

개선안:

- 전화 연결 전 confirmation sheet를 둔다.
- “119 연결”, “원내 응급팀 호출”, “담당자 호출”을 구분한다.
- 자동 연결 countdown이 있다면 pause/cancel이 명확해야 한다.

#### SOS와 위험 환자 alert의 시각 언어를 분리해야 한다

홈의 위험 카드와 SOS fullscreen이 모두 강한 red 중심이면 긴급도의 단계가 흐릴 수 있다.

개선안:

- SOS는 full red emergency로 유지한다.
- 위험 환자 alert는 red badge/rail 수준으로 낮춘다.
- `위험`, `응급`, `SOS`의 용어 기준을 명확히 한다.

### 우선 수정

- close/종료/전화 액션에 확인 단계를 추가한다.
- SOS 로그와 종료 상태를 명확히 한다.
- 응급 단계 용어를 앱 전체에서 통일한다.

## 6. 디자인 시스템과의 불일치 목록

### 6.1 공통 CSS 부재

문제:

- 각 HTML이 자체 CSS를 많이 가진다.
- appbar, tabbar, card, icon button, toast, sheet가 반복된다.

개선:

- 공통 CSS로 추출한다.
- 화면 파일은 layout과 화면 전용 스타일만 남긴다.

### 6.2 semantic token 미완전 사용

문제:

- `#fff`, `#F4FAF6`, `rgba(...)`, `linear-gradient(...)`가 다수 보인다.
- `var(--brand-green-300)`, `var(--palette-red-700)`처럼 primitive token이 직접 쓰인다.
- `--accent`, `--danger`, `--warn` 등 로컬 alias가 파일마다 반복된다.

개선:

- 배경, 표면, 텍스트, border, status color를 semantic token으로 통일한다.
- primitive token은 시스템 내부에서만 쓰고 화면에서는 semantic token을 쓰게 한다.
- 의료진 앱 전용 semantic alias가 필요하면 한 파일에서만 정의한다.

### 6.3 터치 타깃 원칙 불일치

문제:

- README는 `touch >=48x48`을 말하지만 `.icon-btn`은 40x40이 많다.
- 토글과 일부 pill 버튼도 hit area가 작을 수 있다.

개선:

- 모든 clickable control의 실제 hit area를 48px 이상으로 보장한다.
- compact UI가 필요하면 visual size와 hit area를 분리한다.

### 6.4 이모지/특수문자 규칙 정리 필요

문제:

- 이모지는 직접 보이지 않지만, circled number, 방향 기호, emoticon성 문구는 임상 UI 톤과 맞지 않을 수 있다.
- 프로젝트 규칙은 UI와 문서에서 이모지 금지, 아이콘은 `iconify-icon`으로 통일이다.

개선:

- 번호는 ordered list 또는 number chip으로 통일한다.
- 방향/상태 표시는 iconify fluent icon으로 통일한다.
- 보호자에게 나가는 문구도 전문적이고 차분한 톤으로 정리한다.

## 8. 브라우저로 추가 확인해야 할 항목

파일만 봐도 구조, 토큰, IA, 반복 CSS, mock 액션, 접근성 위험은 상당히 잡을 수 있다. 하지만 다음은 브라우저에서 실제 렌더링 확인이 필요하다.

- `d02-round.html`에서 swipe bar, tabbar, keyboard 입력 영역이 겹치지 않는지

- 다크/야간 모드가 있다면 색 대비가 충분한지
- 긴급 alert와 SOS red 계열이 실제 화면에서 과도하게 피로하지 않은지

즉, 이번 리뷰는 파일 기준으로 충분히 유효하지만, 최종 수정 전에는 브라우저에서 모바일 viewport로 한 번 더 보는 것이 좋다.

이번 작업의 목표는 새 기능을 많이 추가하는 게 아니라, 기존 의료진 모바일앱을 더 통일감 있고, 깔끔하고, 실제 의료진이 쓰기 편한 앱처럼 다듬는 거야.

우선순위는 다음이야.

1. v15_의료진앱의 모든 화면에서 공통 CSS를 정리해줘. appbar, card, icon button, tabbar, SOS FAB, toast, sheet 같은 반복 스타일은 공통화하고, 각 HTML 내부에는 화면 고유 layout만 남겨줘.
2. 07_디자인의 design system v3.1 방향과 맞게 semantic token 중심으로 정리해줘. hardcoded hex, rgba, primitive token 직접 사용은 최대한 줄여줘.
3. 의료진 모바일앱 원칙에 맞게 모든 주요 터치 타깃을 실제 48px 이상으로 맞춰줘. 특히 icon button, tab, toggle, FAB를 확인해줘.
4. 하단 탭은 아이콘만 있어서 인지성이 낮아. 전체 라벨 또는 active 탭 라벨을 추가해서 `지금`, `회진`, `소통`, `인계`가 빠르게 구분되게 해줘.
5. d05-mypage.html은 하단 탭 active 상태가 없어 현재 위치가 애매해. 마이 화면을 detail screen처럼 처리하거나, profile context가 명확해지게 navigation을 정리해줘.
6. d02-round.html의 AI 응급판단 표현은 너무 결정적으로 보일 수 있어. `AI 보조 판단`, `AI 위험 신호 제안`처럼 의료진이 최종 확인한다는 톤으로 바꾸고, 위험 선택 시 toast만 띄우지 말고 다음 행동 sheet를 열어줘.
7. d03-inbox.html의 urgent alert와 AI 위험 알림은 toast-only로 끝나면 안 돼. 클릭하면 환자, 발생 시각, 관찰 지표, 추천 행동, 확인 버튼이 있는 detail sheet가 열리게 해줘.
8. d04-handover.html의 교대조 전송은 confirmation sheet를 추가해줘. 미확인 체크리스트가 있으면 전송 전 경고하고, 전송 후 상태가 남게 해줘.
9. d-sos.html은 close, 상황 종료, 전화 연결 액션이 너무 쉽게 보이면 위험해. confirmation, 취소 사유, 종료 로그, 전화 연결 전 확인 단계를 추가해줘.
10. `href="#"`, 구현되지 않은 mock 액션, toast-only 주요 액션을 정리해줘. 실제 이동, button, disabled, 준비중 badge 중 하나로 명확히 처리해줘.
11. 프로젝트 규칙상 UI와 문서에서 이모지는 절대 쓰지 말고, 아이콘은 iconify-icon fluent 계열로 통일해줘. circled number나 장식 기호도 일반 번호/칩/아이콘 컴포넌트로 정리해줘.
12. 최종적으로 모바일 viewport에서 하단 tabbar, SOS FAB, bottom sheet, 긴 텍스트가 겹치거나 잘리지 않는지 확인해줘.
