# 하루안부 — 요양보호사 앱 IA & 기획 분석

**v1.0 | 2026.04.18**

---

## 0. 분석 요약

> 하루안부의 기존 '의료진' 역할은 실제 요양보호사의 업무 흐름과 맞지 않는 부분이 있다.  
> 의사/간호사 중심으로 설계된 UI를 **요양보호사 실무 기준**으로 재설계하면 차별화된 UX를 만들 수 있다.

| 항목 | 현재 (의료진) | 개선 방향 (요양보호사) |
|------|--------------|----------------------|
| 핵심 진입점 | 체크리스트 입력 | **출퇴근 기록 → 케어 일지** 흐름 |
| 가장 빈번한 작업 | 처방전·진료기록 입력 | **ADL 케어 기록** (식사/투약/위생/배변/활동) |
| 역할 정체성 | 의료진 (포괄) | **요양보호사 1급/2급** 자격 기반 |
| 누락된 기능 | - | 출퇴근 전자서명, 서비스 제공기록지, 급여 청구 연동 |
| 커뮤니케이션 | 보호자 ↔ 의료진 채팅 | **보호자 + 시설 관리자**와의 소통 분리 |

## 1. 요양보호사 유저 이해

### 1.1 핵심 페르소나

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  박미선 (48세) — 방문요양 요양보호사 4년차
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  하루 담당 수급자: 3명 / 1인당 방문 2~4시간
  주요 도구: 카카오톡, 종이 케어 일지, 센터 전화
  
  불편한 점:
  ├── 종이 케어 일지를 나중에 한꺼번에 적어서 실수 발생
  ├── 보호자에게 케어 상황 설명하는 데 시간 많이 걸림
  ├── SOS 상황 시 119 + 보호자 + 센터 동시에 연락 어려움
  └── 급여 청구 서류 매월 직접 작성 → 오류, 누락 발생
  
  원하는 것:
  ├── 케어 기록을 현장에서 바로 앱으로 처리
  ├── 가족이 실시간으로 확인 가능한 투명한 케어 기록
  └── 긴급 상황 시 원터치 알림 발송
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 1.2 하루 업무 플로우 (현실)

```
출근 (이동 중)
  │
  ▼
수급자 댁 도착 → 출근 서명 (수급자 or 가족 확인)
  │
  ▼
바이탈 체크 (혈압/체온/맥박) — 이상 시 즉시 보고
  │
  ▼
케어 서비스 제공
  ├── 신체활동 지원 (식사, 배변, 목욕, 이동 보조)
  ├── 가사활동 지원 (청소, 세탁, 조리)
  └── 인지활동 지원 (대화, 활동 프로그램)
  │
  ▼
케어 일지 기록 (현장에서 또는 귀가 후)
  │
  ▼
퇴근 서명 + 보호자에게 오늘 케어 요약 전달
  │
  ▼
다음 수급자 이동 (방문요양) / 근무 종료 (시설)
```

### 1.3 요양보호사가 실제로 기록하는 항목 (ADL)

| 분류 | 세부 항목 |
|------|-----------|
| **식사** | 식사량(%), 식사 형태(일반/연식/유동식), 수분 섭취량, 기호도 |
| **배변** | 대변 횟수·형태, 소변 횟수·색상, 실금 여부, 기저귀 교체 |
| **위생** | 구강청결, 세수/세발, 목욕/샤워, 손발 위생 |
| **투약** | 투약 여부, 약 종류, 시간, 거부 여부 |
| **이동/활동** | 보행 보조, 체위 변경, 낙상 위험도, 물리치료 |
| **바이탈** | 혈압, 체온, 맥박, 혈당 (당뇨 수급자) |
| **인지/정서** | 인지 상태, 감정 상태, 대화 내용 요약 |
| **특이사항** | 낙상, 피부 이상, 구토, 발열, 행동 변화 |

## 2. 기존 하루안부 IA 분석 — 의료진 관점에서의 문제점

```
현재 의료진 화면 (PC 중심)
├── /medical/checklist     ✅ 필요하나 ADL 항목이 부족
├── /medical/patients      ✅ 담당 수급자 목록 (OK)
├── /medical/patients/:id  ✅ 수급자 상세 (OK)
├── /medical/sos           ✅ SOS 발송 (필수)
├── /medical/chat          ✅ 보호자 채팅 (OK)
├── /medical/schedule      ✅ 스케줄 (OK)
├── /medical/prescriptions ⚠️  의사 처방전 입력 → 요양보호사는 입력 권한 없음
└── /medical/records       ⚠️  진료기록 입력 → 요양보호사 역할 아님

누락된 기능:
├── ❌ 출퇴근 기록 (전자서명 포함)
├── ❌ 서비스 제공기록지 (급여 청구 서식)
├── ❌ 바이탈 측정 기록
├── ❌ 수급자별 케어 계획서 조회
└── ❌ 인수인계 메모
```

## 3. 요양보호사 앱 정보구조도 (IA)

### 3.1 전체 구조 — 모바일 탭바 기준 (3탭 + 플로팅 SOS)

> **설계 원칙**: 요양보호사가 하루에 진짜 쓰는 건 출퇴근 + 케어 기록 두 가지.  
> 나머지는 "가끔"이므로 탭이 아닌 더보기/헤더로 밀어낸다.

```
┌────────────────────────────────────────────────────────────┐
│  하루안부 — 요양보호사            ⊙ 프로필 (MY 이동)         │
├────────────────────────────────────────────────────────────┤
│                                                             │
│                                                             │
│                     메인 콘텐츠 영역                         │
│                                                             │
│                                            ╔══════╗         │
│                                            ║  SOS ║ ← 플로팅 │
│                                            ╚══════╝         │
├────────────────────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐      │
│  │   📋 오늘    │  │  ✏️ 케어    │  │   💬 소통   │      │
│  │ 출퇴근+일정  │  │     기록    │  │  채팅+AI    │      │
│  └──────────────┘  └──────────────┘  └──────────────┘      │
└────────────────────────────────────────────────────────────┘
```

**5탭 → 3탭 통합 근거:**

| 기존 5탭 | 통합 위치 | 이유 |
|---------|-----------|------|
| 홈 (오늘) | → **탭 1: 오늘** | 출퇴근+일정은 같은 맥락 |
| 케어기록 | → **탭 2: 케어기록** | 가장 빈번 → 독립 탭 유지 |
| 채팅 | → **탭 3: 소통** | 채팅+AI는 같은 소통 맥락 |
| 일정 | → **탭 1: 오늘**에 통합 | 달력은 오늘 화면 하단 스크롤로 |
| MY | → **헤더 우측 아이콘** | 하루에 한 번도 안 쓸 수 있음 |
| SOS | → **플로팅 버튼** | 항상 접근 가능해야 함 |

### 3.2 탭별 상세 IA

#### 📋 탭 1: 오늘 (구 홈 + 일정 통합)

```
오늘
├── 출퇴근 배너 (최상단, 눈에 띄게)
│   ├── [출근하기] → GPS + 시간 자동 기록
│   ├── 출근 중: 경과 시간 실시간 표시
│   └── [퇴근하기]
│
├── 오늘 담당 수급자 카드
│   ├── 수급자 A — 방문 예정 / 케어 중 / 완료
│   ├── 수급자 B
│   └── 카드 탭 → 탭 2 케어기록으로 바로 이동
│
├── 미완료 케어 항목 알림
│
├── AI 한줄 요약 — "어제 김복순 어르신 식사량 감소"
│
└── [접을 수 있는] 이번 주 일정 간략 뷰
    └── 풀 달력은 MY > 일정에서 확인
```

---

#### ✏️ 탭 2: 케어 기록

```
케어 기록
├── 수급자 선택 (오늘 담당 목록 우선)
│   └── 수급자 상세 — 진단명, 등급, 금기사항 확인
│
├── [스텝 형식 입력 — 한 화면에 한 항목씩]
│   ├── Step 1: 바이탈 (혈압/체온/맥박/혈당)
│   ├── Step 2: 식사 (슬라이더 %, 형태, 수분량)
│   ├── Step 3: 투약 (약 목록 체크 + 거부 메모)
│   ├── Step 4: 위생 (체크박스 — 구강/세수/목욕)
│   ├── Step 5: 활동 (보행보조, 체위변경, 프로그램)
│   ├── Step 6: 배변 (횟수, 형태, 기저귀)
│   ├── Step 7: 인지/정서 (상태 선택 + 음성메모)
│   └── Step 8: 특이사항 (사진 첨부, 인수인계 메모)
│
├── 케어 일지 이력 (날짜별 타임라인)
│
└── 서비스 제공기록지 (월별 자동 집계 → PDF)
```

---

#### 💬 탭 3: 소통 (구 채팅 + AI 통합)

```
소통
├── 채팅 목록
│   ├── 보호자 채팅 (수급자별)
│   │   └── 오늘 케어 요약 공유 버튼
│   └── 센터/시설 공지
│
└── AI 케어 가이드 (Claude)
    ├── "치매 어르신 배회 대응법은?"
    ├── "오늘 너무 힘들었어요" → 감정 지원 모드
    └── "낙상 발생 시 대처법" → 긴급 대응 가이드
```

---

#### ⊙ 헤더 아이콘: MY (프로필)

```
MY (헤더 우측 아이콘 → 드로어 or 별도 페이지)
├── 내 프로필 (이름, 자격증, 소속 센터)
├── 근무 통계 (이번 달 시간, 수급자별)
├── 일정 달력 (풀뷰)
├── 자격증 & 보수교육 이수 현황
└── 설정 (알림, 언어, 다크모드)
```

---

#### 🆘 플로팅 버튼: SOS

```
SOS (모든 화면에서 우하단 고정)
├── 탭 → 상황 유형 선택 (낙상/의식저하/호흡곤란/기타)
├── 보호자 + 센터 동시 푸시 알림 발송 (30초 이내)
└── 119 연결 버튼 노출
```

## 4. 핵심 사용자 플로우

### 4.1 하루 시작 플로우 (가장 빈번)

```
앱 열기
  │
  ▼
홈 화면 — "오늘 방문 일정: 3명"
  │
  ▼
첫 번째 수급자 댁 도착
  │  (GPS 자동 감지 또는 수동)
  ▼
[출근하기] 탭
  ├── 시간 자동 기록
  ├── 위치 기록 (GPS)
  └── 수급자 또는 가족 서명 (옵션)
  │
  ▼
케어 서비스 시작
  │
  ▼
케어 기록 탭 — 항목별 기록
  ├── 바이탈 측정
  ├── 식사 기록
  ├── 위생 기록
  └── 특이사항 입력
  │
  ▼
[퇴근하기] 탭
  ├── 서비스 종료 시간 기록
  └── 오늘 케어 요약 → 보호자 자동 공유 여부 선택
  │
  ▼
보호자 채팅 — 간단 인사 + AI 요약 공유
```

---

### 4.2 긴급 상황 플로우 (SOS)

```
이상 징후 발견 (낙상, 의식저하 등)
  │
  ▼
플로팅 SOS 버튼 (어느 화면에서든 접근 가능)
  │
  ▼
상황 유형 선택 (3초 이내 원터치)
  ├── 낙상
  ├── 의식저하
  ├── 호흡곤란
  └── 기타 (음성 메모)
  │
  ▼
동시 발송:
  ├── 보호자 → 푸시 알림 (30초 이내)
  ├── 센터/시설 관리자 → 푸시 알림
  └── 119 연결 버튼 표시
  │
  ▼
SOS 타임라인 기록
  ├── 발송 시각
  ├── 보호자 확인 시각
  └── 대응 완료 기록
  │
  ▼
케어 일지에 특이사항 자동 반영
```

---

### 4.3 월말 급여 청구 플로우

```
케어 기록 탭 → 서비스 제공기록지
  │
  ▼
월별 자동 집계
  ├── 일별 서비스 제공 시간
  ├── 제공 서비스 항목
  └── 담당 요양보호사 정보
  │
  ▼
수급자 또는 보호자 전자서명
  │
  ▼

```

## 5. 기존 하루안부와 요양보호사 앱의 관계

### 통합 구조 (권장)

```
하루안부 플랫폼
│
├── 보호자 앱 (모바일)
│   ├── 대시보드 (케어 현황 실시간 확인)
│   ├── AI 케어 가이드
│   ├── 요양보호사와 채팅
│   └── SOS 수신
│
├── 요양보호사 앱 (모바일) ← 이번 설계 대상
│   ├── 출퇴근 + 케어 일지
│   ├── SOS 발송
│   ├── 보호자/센터 채팅
│   └── 일정 관리
│
└── 시설 관리자 앱 (PC 웹)
    ├── 요양보호사 관리
    ├── 수급자 현황
    └── 리포트 & 통계
```

> **핵심 인사이트**: 기존 '의료진' 역할을 '요양보호사'로 분리하면 UX가 훨씬 명확해진다.  
> 의료진(의사/간호사)과 요양보호사는 완전히 다른 업무 플로우를 가지므로  
> 하나의 '의료진' 역할로 묶으면 두 사용자 모두 불편하다.

## 6. 디자인 방향 제안

### 6.1 색상 시스템 (역할별 구분)

| 역할 | 메인 컬러 | 의미 |
|------|-----------|------|
| **요양보호사** | `#4A90D9` 따뜻한 파랑 | 신뢰, 전문성, 안정 |
| **보호자** | `#5B8A6F` 초록 계열 | 자연, 안심, 가족 |
| **수급자(어르신)** | `#E8956D` 따뜻한 오렌지 | 온기, 친근함 |
| **긴급/SOS** | `#E84040` 빨강 | 위험, 즉각 주의 |

### 6.2 UI 원칙

**요양보호사 앱 특화 원칙:**

1. **한 손 조작 가능** — 케어 중에도 한 손으로 기록 가능한 UI
2. **빠른 입력 우선** — 드래그/슬라이더/체크박스 위주, 타이핑 최소화
3. **큰 터치 영역** — 장갑 낀 상태에서도 터치 가능 (최소 44px)
4. **음성 입력 지원** — 특이사항, 인수인계 메모는 음성 입력 허용
5. **오프라인 대비** — 인터넷 불안정 환경에서도 기록 가능 (로컬 저장 후 동기화)

### 6.3 컴포넌트 우선순위

```
HIGH PRIORITY (MVP)
├── 출퇴근 버튼 (홈 화면 최상단, 매우 눈에 띄게)
├── 케어 기록 폼 (슬라이더 + 체크박스 + 스텝퍼)
├── SOS 플로팅 버튼 (항상 접근 가능)

MEDIUM PRIORITY

└── 주간 달력

LOW PRIORITY (Level 2)
├── 서비스 제공기록지 PDF
```

## 8. DB 스키마 추가 항목

기존 `care_records` 테이블 확장이 필요한 항목:

```sql
-- 바이탈 기록 (신규)
CREATE TABLE vitals (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id UUID NOT NULL REFERENCES patients(id),
  staff_id UUID REFERENCES users(id),
  blood_pressure_systolic INTEGER,
  blood_pressure_diastolic INTEGER,
  temperature DECIMAL(4,1),
  pulse INTEGER,
  blood_sugar INTEGER,
  measured_at TIMESTAMPTZ DEFAULT now()
);

-- 출퇴근 기록 (신규)
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES users(id),
  patient_id UUID NOT NULL REFERENCES patients(id),
  check_in TIMESTAMPTZ,
  check_out TIMESTAMPTZ,
  check_in_gps POINT,
  check_out_gps POINT,
  signature_url TEXT,  -- 수급자/보호자 전자서명
  service_minutes INTEGER GENERATED ALWAYS AS (
    EXTRACT(EPOCH FROM (check_out - check_in)) / 60
  ) STORED
);

-- 인수인계 메모 (신규)
CREATE TABLE handover_notes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id UUID NOT NULL REFERENCES patients(id),
  from_staff_id UUID REFERENCES users(id),
  content TEXT,
  voice_url TEXT,
  care_date DATE DEFAULT CURRENT_DATE,
  created_at TIMESTAMPTZ DEFAULT now()
);
```
