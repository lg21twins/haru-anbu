# 의료진 대시보드 v9.5 상세 리뷰

## 1. 전체 개요
- 화면은 고정형 좌측 사이드바와 우측 통신 패널을 가진 전형적인 데스크톱 대시보드 구조.
- 중앙에 대시보드 콘텐츠가 집중되며, 여러 카드와 KPI, 일정/환자 관리, AI/커뮤니케이션 패널이 혼재.
- 스타일은 깔끔하지만 화면 밀도가 높고, 반응성/접근성이 약한 부분이 있음.

## 2. 가장 큰 문제점
1. **반응형이 거의 없음**
   - `.main-wrapper`가 `margin-left: 232px; margin-right: 300px;`로 고정되어 있음.
   - `.body-grid`, `.med-cols`, `.pt-cols` 등 주요 레이아웃이 고정 폭과 고정 컬럼으로 구성되어 있어 작은 화면에서 강제 수평 스크롤을 유발.
   - 모바일/태블릿 대응이 고려되지 않은 상태.

2. **정보 과부하와 시각적 잡음**
   - 카드, 리스트, 패널이 모두 비슷한 배경과 테두리로 펼쳐져 있어 시선 흐름이 분산됨.
   - 한 화면에 KPI 카드, 히어로 섹션, 타임라인, 알림, AI, 환자 리스트가 너무 많이 들어가 보임.
   - 중요 항목(긴급 환자, 지금 해야 할 일)과 보조 항목(알림, AI 요약)의 시각적 차이가 충분치 않음.

3. **접근성/사용성 미비**
   - 키보드 포커스 스타일이 없음. `button`, `a`, `role="button"` 요소 모두 `:focus` 스타일 미정의.
   - 많은 항목이 `cursor: pointer`로 클릭 가능하게 보이지만 실제로는 버튼/링크가 아니면 스크린리더/키보드 사용자에게 혼란.
   - 색 대비가 전체적으로 약한 편. 특히 사이드바 비활성 링크와 회색 텍스트의 대비가 낮음.

4. **레이블/상태 표현 모호**
   - `.pt-room`, `.pt-row`, `.ph-item` 등 여러 클래스가 함수적 상태를 담고 있으나, 색상만으로 구별.
   - 회색/흰색 기반의 배경 대비가 적어 중요 경고가 충분히 돋보이지 않을 수 있음.

## 3. 구체적 개선 포인트
### 레이아웃
- 좌우 고정 패널 대신 반응형 레이아웃으로 전환
  - `min-width`/`max-width`와 `clamp()` 사용
  - 사이드바와 우측 커뮤니케이션 패널에 토글/접기 기능 추가
- 내부 카드들에 `auto-fit` / `minmax()` 적용
  - `grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));`
  - 고정 폭 대신 유동 폭으로 구성

### 시각적 계층
- 중요 항목을 보다 크게, 덜 중요한 항목은 낮춰서 배치
  - `priority-hero`, `kpi.hero`, `alert-feed` 등에 색상/타입 차별성 강화
- 모노톤 카드가 너무 많음
  - 전체를 흰색 카드로 채우기보다, 긴급 카드/진행 카드에 배경 톤 변화를 줘서 구분
- 텍스트 크기와 가중치를 좀 더 계층화
  - 주요 타이틀/숫자는 16~18px 이상으로 확대
  - 보조 텍스트는 12px 수준으로 정리

### 인터랙션
- 클릭 영역과 버튼 구분
  - `.ph-item`, `.al-item`, `.pt-row` 같은 항목은 실제 버튼/링크 요소로 바꾸거나 `role`, `aria-label` 추가
  - `:focus-visible` 스타일 추가
- hover/active만으로 상태 표현하지 않기
  - 터치 환경 대응 시 `hover`는 사용할 수 없음.
- 현재 `sos-btn`과 활동 버튼은 잘 눈에 띔. 이점은 유지하되, 긴급한 컬러 사용을 과도하게 확장하지 말 것.

### 접근성
- keyboard focus 상태 정의
  - `outline: none` 제거, 대신 `box-shadow`/`outline` 커스텀 포커스 스타일 사용
- 충분한 콘트라스트 확보
  - 텍스트 대비 비율 점검 (WCAG AA 이상)
  - `.nav-link`, `.pt-tab`, `.pt-row` 텍스트 대비 개선
- 의미 있는 HTML 구조 권장
  - 현재는 CSS 중심 설계. 실제 DOM에 `nav`, `main`, `aside`, `section` 활용이 필요.

### 코드 정리
- 동일한 색/간격 정의가 반복됨
  - `--card-bg`, `--surface`, `--ink-*` 외에 컴포넌트별 변수를 더 명확히 분리
- 클래스 재사용 충돌
  - `.pt-room`가 두 곳에서 별도 의미로 사용됨. 유지보수 위험.
- 애니메이션 과용
  - `pulse`와 `medTlPulse`는 시각적 주의 집중에는 유용하지만, 너무 많은 애니메이션이 동시에 돌아가면 피로.

## 4. 치명적인 UX 리스크
- **우측 고정 커뮤니케이션 패널이 콘텐츠를 과도하게 압박**
  - 특히 화면 폭이 1200px 이하일 때 메인 콘텐츠 폭이 매우 좁아짐.
  - 환자 관리·타임라인·리스트가 모두 중앙에 몰릴 경우 실제 사용자가 보기 어렵다.
- **데이터 우선순위 설정이 불분명**
  - `Now/Next` 중요도와 `AI 요약`/`알림` 중 누가 더 먼저 봐야 하는지 맥락이 약함.
  - 긴급 환자 정보를 상단 근처에 고정해서 즉시 식별할 수 있도록 재배치해야 함.

## 5. 결론
- 현재 디자인은 깔끔하지만, 실제 의료진이 빠르게 판단하고 조작해야 하는 대시보드로서는 너무 많은 요소가 한 화면에 섞여 있음.
- 반응형 전략, 접근성, 정보 계층화에 우선순위를 두고 다시 다듬어야 함.
- 클라우드가 만든 버전이라면, 기본 UX는 잡았지만 “작업 가능한 실사용 대시보드”로 가기 전 단계로 판단됨.

---

### 추천 우선순위
1. 반응형/접기 가능한 사이드바·우측 패널 도입
2. 키보드 접근성과 포커스 스타일 보강
3. 주요 경보/긴급 정보의 시각적 계층 강화
4. 카드·테이블 레이아웃의 고정 폭 제거
5. 클래스 네이밍 명확화 및 CSS 변수 일관성 정리
