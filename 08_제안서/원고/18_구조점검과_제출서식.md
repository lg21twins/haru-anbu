# PART 1 · 구조 점검 — PSST 대조

## 1-1. 표준 구조

정부지원사업 사업계획서는 사실상 예외 없이 **PSST**를 쓴다. `[2차]`

| 블록 | 내용 |
|---|---|
| **P** Problem | 문제 인식 — 기존 시장의 문제, 고객 불편을 **객관적 데이터**로 |
| **S** Solution | 해결 방안 — 기능·구조 + **수익 구조** |
| **S** Scale-up | 성장 전략 — 확산 경로, 시장 진입 |
| **T** Team | 팀 역량 — **누가 이걸 할 수 있는가** |

전체 구성은 통상 **일반현황 / 개요(요약) / 본문(PSST)** 3부다.

## 1-2. 우리 제안서를 대조한 결과

| 블록 | 우리 섹션 | 판정 |
|---|---|---|
| **P** | 01 왜 지금인가 · 02 문제 정의 | **강함** — 출처 검증된 수치 세트, 2010년 학술 근거 |
| **S** (Solution) | 03 제안 서비스 · 05 차별화 · 07 법 대응 | **강함** — 실물 39화면, 조문 단위 대조 |
| **S** (Scale-up) | 06 정책 정합성 · 09 실증 로드맵 · 09-1 착수 조건 | **약함** — 파일럿까지만 있고 **그다음이 없다** |
| **T** (Team) | — | **없음** |

### 팀 섹션이 0건이다

```
제안서_시각화.html   "팀 역량 | 팀 소개 | 팀원명 | 서비스 디자인"  →  0건
```

25쪽짜리 제안서에 **누가 이걸 만들었고 왜 우리가 할 자격이 있는지가 한 줄도 없다.**
1페이지 소개서 맨 아래에 이름 세 개가 있을 뿐이다.

> **실적 없는 팀일수록 이 블록이 중요하다.**
> 경력으로 증명할 수 없으면 **산출물로 증명해야 하는데**, 우리는 그 산출물이 있으면서 말을 안 하고 있었다.

## 1-3. 그래서 팀 블록에 무엇을 쓰는가

우리에게는 학위도 경력도 법인도 없다. **대신 이런 것들이 있다.**

| 증거 | 무엇을 증명하는가 |
|---|---|
| **4역할 고유 화면 39개** (언어 변형 포함 67파일), 클릭 동작 | **끝까지 만든다.** 기획서가 아니라 실물을 낸다 |
| **공개 배포 후 유지 중** (haruanbu.site) | 만들고 버리지 않는다 |
| **조문 단위 법 대조** — 개인정보보호법·의료법·디지털의료제품법·노인장기요양보험법 | **학생 작업의 정밀도가 아니다.** 뭘 만들면 안 되는지부터 센다 |
| **디자인 시스템 + 자동 검사 도구** (토큰·감사 스크립트·회귀 테스트) | 엔지니어링 규율이 있다 |
| **수치 검증 대장** — 인용 금지 판정까지 기록 | **못 믿을 숫자를 스스로 버린다** |
| **한계 문서 16쪽** — 못 하는 것을 먼저 문서화 | 과장하지 않는다 |
| 한국어·영어·중국어 3개 언어 | 외국인 요양보호사 증가에 대응 가능 |

> **이 표가 곧 "팀 역량"이다.** 이력이 아니라 **행동의 증거**로 쓴다.
> 그리고 마지막 두 줄이 핵심이다 — **자기 숫자를 버릴 줄 아는 팀**이라는 것.

### 같이 적어야 할 것 — 팀에 없는 것

| 없는 것 | 대응 |
|---|---|
| **개발 인력** | 9월 학기 캡스톤·산학 연계로 확보 시도 (`17_착수조건과_일정.md`) |
| 법인격 | 학교·산학협력단 경유 연구 협력 |
| 의료·요양 현장 경험 | **그래서 KHF에서 인터뷰를 따 온다.** 없는 걸 있다고 하지 않는다 |

## 1-4. Scale-up이 약한 이유와 보강 방향

지금 제안서는 **파일럿 1곳까지만** 그린다. 그다음이 없다.

> 상대(특히 기업·심사자)가 알고 싶은 건 **"그래서 이게 6,361개소로 어떻게 퍼지나"**다.

정직하게 쓸 수 있는 것:

1. **파일럿 1곳 → 같은 법인 내 확산** — 시설 법인은 대개 여러 곳을 운영한다. 첫 시설이 곧 다음 시설이다
2. **SW 사업자 연동 경로** — 케어포·이지케어 등이 이미 6,361개소에 깔려 있다. **우리가 직접 영업하는 것보다 그 위에 얹히는 게 빠르다**
3. **보험사 요양 자회사** — 브랜드 차별화 수요 + 다수 시설 동시 적용 가능
4. **지자체 컨소시엄** — 스마트 사회서비스 계열 사업. 단, 우리 단독 신청은 불가

> **핵심 문장**: "**우리가 6,361곳을 영업할 수는 없다.**
> 이미 그곳에 들어가 있는 시스템 위에 얹히는 것이 유일하게 현실적인 확산 경로다."
> — 이건 약점 고백이 아니라 **채널 전략**이다.

# PART 2 · 지금 없는 제출 서식

현장에서 종이가 없으면 그 요청은 말로만 끝난다.

## 2-2. 현장 인터뷰 — 구두 동의 문구

기록 전에 반드시 읽는다. **녹음은 하지 않는다.**

```
"저희가 지금 나눈 이야기를 메모로 남겨도 될까요.
 이름이나 소속은 적지 않고, 직군과 답변 요지만 적습니다.
 학생 팀의 서비스 설계 참고용으로만 쓰고, 공개할 때는
 어느 기관인지 알 수 없게 처리하겠습니다. 녹음은 하지 않습니다."
```

> 이름·연락처는 **명함을 주신 경우에만** 남긴다. 명함 없이 개인 신상을 적지 않는다.

## 2-3. 아직 만들지 않았지만 필요해질 서식

| 서식 | 언제 필요한가 | 상태 |
|---|---|---|
| **연구 협력 요청서** (학교 → 시설) | 산학협력단 경유가 확정된 뒤 | 미작성 — **학교 표준 양식을 따라야 하므로 산학협력단 확인 후 작성** |
| **개인정보 수집·이용 동의서** (파일럿용) | Phase 0 완료 후 | 미작성 — 온보딩 화면(`ob04-agree`)이 원형. 문서화 필요 |
| **파일럿 협약서(MOU)** | 시설 확정 후 | 미작성 — **법인 문제가 풀려야 주체가 정해진다** |
| **데이터 파기 확인서** | 파일럿 종료 시 | **작성 완료 (2026-08-07)** — `21_데이터파기확인서.md` · `PDF/하루안부_데이터파기확인서.pdf` (A4 1쪽) |

> **지금 만들 필요는 없다.** 다만 **약속한 것(파기 확인서)은 반드시 만들어야 한다** —
> 1페이지 소개서에 "파기 확인서를 드립니다"라고 이미 적혀 있다.
>
> **2026-08-07 처리됨.** 개인정보 보호법 제21조·시행령 제16조에 근거한 A4 1쪽 서식으로 만들었다.
> 용도가 하나 더 생겼다 — **파일럿 종료 시가 아니라 시작 전에 보여준다.**
> 시설이 망설이는 진짜 이유는 "학생들이 어르신 정보를 가져가서 어떻게 되는가"이고,
> **끝을 먼저 보여주면 시작을 허락한다.**
