# 기관별 제출 양식 · 접근법 가이드

> 2026-08-02. **같은 제안서를 모든 곳에 보내면 전부 떨어진다.**
> 받는 쪽이 무엇으로 판단하는지가 다르기 때문이다. 이 문서는 수신자 유형별로
> **분량 · 파일형식 · 목차 · 강점을 어디까지 세우고 한계를 어디에 놓을지**를 정한다.
>
> 국내 공공·복지·창업 분야의 실제 표준 양식(PSST, 정책제안서, 사회복지사업계획서,
> 제휴제안서)을 조사해 우리 상황에 맞춰 재구성했다. 출처는 끝에 정리.

## 0. 모든 제출물을 관통하는 원칙 — 강점은 증거로, 한계는 먼저

우리는 **학생팀 · 법인 없음 · 백엔드 없음**이다. 이 셋은 숨겨지지 않는다. 실사 한 번이면 드러난다.
그래서 전략은 하나뿐이다.

> **강점은 확인 가능한 형태로 세우고, 한계는 상대가 묻기 전에 우리가 먼저 말한다.**

이건 겸손이 아니라 **신뢰 설계**다. 순서가 핵심이다.

| 잘못된 순서 | 결과 |
|---|---|
| 강점만 → 실사에서 한계 발각 | 신뢰 붕괴. 두 번째 기회 없음 |
| 한계부터 장황하게 → 강점 흐림 | "그래서 왜 만나야 하지" |
| **강점(증거 포함) → 한계(자진 고지) → 그럼에도 지금 만날 이유** | **신뢰 + 진행** |

### 우리가 실제로 가진 강점 세 가지 (전 제출물 공통)

1. **완성된 설계 자산** — 고유 화면 39개(언어 변형 포함 67개 파일), 4역할 전체, 공개 배포되어 **지금 열어볼 수 있다**
2. **법 대조를 마친 설계** — 개인정보보호법·의료법·노인장기요양보험법을 조문 단위로 대조해 SaMD(의료기기) 회피 범위를 스스로 그어 놓았다. 이 단계에서 여기까지 한 팀은 드물다
3. **검증된 수치만 쓴다는 규율** — 미검증 수치를 전량 걷어내고 출처·연도가 확인된 것만 남긴 대장(`01_수치검증대장.md`)이 있다

### 우리가 실제로 못 가진 것 세 가지 (전 제출물 공통, 표현 통일)

1. **동작하는 백엔드가 없다** — 현재는 프로토타입이며 서버·DB·인증이 없다. 화면은 완성이고 연동은 미구현
2. **도입 레퍼런스가 없다** — 실제 시설 운영 데이터로 검증한 적이 없다
3. **법인·사업자가 없다** — 계약 주체가 될 수 없다. 파일럿은 학교·지도교수 경유 또는 무상 협력 형태여야 한다

> **표현 통일**: 위 여섯 문장은 어떤 제출물에서도 **문구를 바꾸지 않는다.**
> 상대에 따라 강조 비중만 조절하고, 사실 자체는 동일하게 쓴다.
> 자세한 근거·범위는 `11_강점과_한계_정리.md` 참조.

### 절대 쓰지 않는 표현 (전 제출물 공통 금지)

| 금지 | 대체 |
|---|---|
| "동작하는 서비스", "출시", "운영 중" | "설계 완성 단계의 프로토타입" |
| "국내 최초", "유일한", "없다" | "공개 자료 기준 확인되지 않았다" |
| "진단합니다", "이상을 감지합니다" | "기록을 정리해 보여줍니다" (의료행위 표현 회피) |
| 출처 없는 통계 | 대장에 등재된 수치만 |
| "AI가 판단" | "AI가 요약", 판단 주체는 항상 사람 |
| 이모지 | 사용하지 않음 |

## 2. 요양시설 원장 · 법인 사무국

**가장 중요한 수신자다.** 파일럿 한 곳이 나머지 전부를 푼다.

### 형식
- **이메일 본문에 핵심을 다 넣는다.** 첨부만 보내면 안 열린다
- 첨부는 **PDF 2장.** 그 이상은 읽지 않는다
- 데모 링크를 본문 첫 화면에 넣는다 (haruanbu.site)

### 2장 구성

| 면 | 내용 |
|---|---|
| **앞면** | 한 줄 정의 / 화면 4장(요양보호사·가족·환자·의료진) / **"요양보호사가 추가로 하는 일: 없음"** |
| **뒷면 상단** | **현재 상태 고지** — 프로토타입, 백엔드 미구현, 레퍼런스 없음, 법인 없음 |
| **뒷면 하단** | 파일럿 제안 — 기간 / 시설이 부담하는 것 / 우리가 부담하는 것 / 개인정보 처리 주체 / 중단 조건 |

### 반드시 들어갈 것

1. **"요양보호사 업무가 늘지 않습니다"** — 시설의 1번 공포. 첫 문장에 온다
2. **개인정보 책임 소재** — 누가 수집·보관하고, 사고 시 누가 책임지는지. 2번 공포
3. **비용** — 파일럿 기간 무상이면 무상이라고 명시. 애매하면 안 만난다
4. **중단 조건** — "언제든 중단 가능"을 먼저 말한다. 퇴로가 있어야 시작한다
5. **연락처와 이름** — 팀 대표 실명·전화번호. 익명 제안은 버려진다

### 절대 넣지 말 것

- 시장 규모, 초고령사회 통계 → 시설장이 우리보다 잘 안다. **모욕이 된다**
- "혁신", "패러다임" 같은 말
- 화면 캡처 10장 이상 나열
- 경쟁사 비방

### 톤

**"저희가 배우러 갑니다"** 가 기본. 학생팀이라는 사실이 여기서는 오히려 방어막이 된다.
영업이 아니라 **현장 검증 요청**의 형태로 간다.

### 후속

- 발송 후 **5영업일** 무응답 → 전화 1회
- 그래도 무응답 → **더 이상 하지 않는다.** 3회 이상은 역효과

## 3. 요양병원 · 의료기관

시설과 다른 점은 하나다. **법을 먼저 본다.**

### 구성 (4~6장)

1. 개요 — 무엇을 하는 서비스인가 (1장)
2. **법적 검토 — 의료행위·의료기기에 해당하지 않는 이유** (1~2장, 조문 인용)
3. 화면과 흐름 (1장)
4. **현재 한계와 파일럿 범위** (1장)
5. 협력 요청 사항 (1장)

### 반드시 들어갈 것

- **SaMD(의료기기 소프트웨어) 비해당 근거** — 식약처는 2015년 「의료기기와 개인용 건강관리(웰니스) 제품 판단기준」을 두고 있고, 최근 「디지털의료기기소프트웨어 허가·심사 가이드라인」 등을 제·개정했다. **우리 기능이 진단·치료 목적이 아니라 기록 전달임을 명시**한다
- **의료법 제19조(비밀 누설 금지)·제21조(기록 열람)** 관련 처리 방식
- **진료기록에 접근하지 않는다**는 사실 (접근한다면 그 근거와 동의 구조)
- IRB 필요 여부에 대한 우리 판단과, 판단을 병원 측에 맡긴다는 태도

### 톤

의료진 앞에서 **의료를 아는 척하지 않는다.** 우리는 소통 도구를 만들었고,
임상 판단은 전부 의료진의 것이라는 선을 문서 안에서 명확히 긋는다.

## 4. 케어테크 기업 (케어닥 · 케어포 · 케어네이션 등)

이쪽은 **"우리를 대체하려는 건가"** 를 먼저 본다. 그 의심을 첫 3장 안에 풀어야 한다.

### 구성 (8~12장)

| 장 | 내용 |
|---|---|
| 1 | 표지 — 팀·연락처·날짜 |
| 2 | **한 줄 제안** — "기록은 귀사 시스템, 소통은 하루안부" |
| 3 | 우리가 만든 것 (화면·역할 구조) |
| 4 | **귀사와 겹치지 않는 지점 / 겹치는 지점** — 겹치는 걸 숨기지 않는다 |
| 5 | 우리 강점 3가지 (증거 포함) |
| 6 | **현재 한계 3가지** (백엔드·레퍼런스·법인) |
| 7~8 | 협업 형태 3안 — 연동 / 화이트라벨 / 공동 파일럿 |
| 9 | 우리가 요청하는 것 / 귀사가 얻는 것 |
| 10 | 일정과 팀 |

### 반드시 들어갈 것

1. **상대 제품을 실제로 써보고 왔다는 증거.** 한 문장이면 된다. 안 써보고 온 제안은 즉시 티가 난다
2. **상호 이익** — 우리가 뭘 얻는지도 쓴다. 일방적 요청은 제휴가 아니다
3. **협업 형태를 복수로 제시** — 상대가 고르게 한다

### 톤

경쟁사를 낮추지 않는다. 특히 **케어포는 이미 가족앱을 갖고 있다.**
"저희가 더 낫습니다"가 아니라 **"저희는 다른 축을 봤습니다"** 로 간다.

## 5. 보험사 요양 자회사 (KB라이프골든케어 · 신한라이프케어 · 삼성노블라이프)

이쪽의 판단 기준은 기술이 아니라 **브랜드와 가족 만족도**다.

### 케어테크용 문서에서 바꿀 곳

| 바꿀 것 | 이렇게 |
|---|---|
| 기술 아키텍처 → | **가족 경험** 중심으로 |
| 기능 목록 → | "가족이 무엇을 받게 되는가" |
| 개발 일정 → | 시설 운영에 주는 부담 |
| 무료 강조 → | **프리미엄 시설의 차별화 자산** 관점 |

### 반드시 들어갈 것

- **운영 중인 시설을 정확히 알고 왔다는 것** — 시설명을 직접 대는 편이 숫자보다 낫다
  (예: KB골든라이프케어라면 "위례·서초 빌리지와 평창 카운티"). **총 개소 수는 재확인 실패라 말하지 않는다**(`09` §3-B 주의)
- 신규 시설 오픈 시점에 붙이기 좋다는 논리 (신한 2027년 은평, 삼성 노블카운티 등)
- 개인정보·보안에 대한 보수적 태도. 금융사 계열은 이게 통과 못하면 끝

### 주의

**오픈이노베이션 정규 트랙(삼성 C랩 아웃사이드, 신한 스퀘어브릿지, KB이노베이션허브)은
대부분 법인 사업자를 요구한다.** 학생팀은 정규 접수가 어렵다.
따라서 **회사 대표 문의 창구로 직접 가는 편**이 현실적이다. 이 사실을 알고 접근한다.

## 6. 지자체 · 공공기관

여기만 **문서 문법이 완전히 다르다.** 제안서가 아니라 **정책 문서**다.

### 형식
- **HWP.** PDF만 보내면 내부 회람이 안 된다
- A4 3~5장. 개조식(짧은 명사형 문장)
- 그림보다 **표**

### 목차 — 국내 공공 정책제안서의 표준 골격

```
1. 추진 배경
2. 현황 및 문제점
3. 제안 내용
4. 기대 효과
5. 소요 예산 (또는 무예산 사항)
6. 추진 일정
7. 고려사항 및 한계
```

### 반드시 들어갈 것

1. **근거 법령** — 돌봄통합지원법(법률 제20415호, 2026-03-27 시행), 노인장기요양보험법, 개인정보보호법
2. **전례** — 서울시복지재단 돌봄서비스 디지털 전환 지원사업(2026년 40개 기관 신청 → 6개 선정, 기관당 700만원 내외)처럼 **이미 존재하는 사업에 붙이는 형태**로 쓴다. 새 사업을 만들어 달라고 하면 통과 안 된다
3. **"7. 고려사항 및 한계"를 반드시 별항으로 둔다.** 공무원 문서에서 한계를 안 쓴 제안은 검토 대상이 아니라 홍보물로 분류된다
4. 소요 예산이 없으면 **"무예산, 시설 자율 참여"** 라고 명시

### 절대 하지 말 것

- 회사 소개서 톤 (기업 홍보물로 분류되면 그대로 종결)
- 부처에 직접 신규 사업 제안 (**지자체 → 컨소시엄** 경로가 정석)
- 미검증 통계

## 7. 창업지원 사업 (예비창업패키지 등) — PSST 양식

국내 정부 창업지원 사업계획서의 표준은 **PSST**다.

| 항목 | 내용 | 우리 대응 |
|---|---|---|
| **P — 문제인식 (Problem)** | 시장·고객에게서 발견한 문제 정의 | 4역할 사이의 소통 단절. **검증된 수치만** |
| **S — 실현가능성 (Solution)** | 어떻게 만들고 어떻게 고객을 확보하나. **가장 중요한 항목** | 설계 완성 자산 + Phase 0 개발 계획 |
| **S — 성장전략 (Scale-up)** | BM·시장진입·확장 | 시설 파일럿 → 법인 → 확산 |
| **T — 팀구성 (Team)** | 수행 역량 | 팀 3인 역할·강점 |

### 주의

- **공고가 뜨면 반드시 그 회차 양식을 새로 받는다.** 양식은 매년 바뀐다
- 한계는 별도 절이 없다. **Solution의 "개발 계획"과 Team의 "보완 계획"에 녹인다**
- 예비창업패키지는 **사업자 미보유가 자격 요건**이다. 우리 약점 하나가 여기서는 자격이 된다

## 8. 공모전 · 디자인 어워드

**심사위원은 우리를 만나지 않는다.** 이미지와 몇 백 자가 전부다.

### 원칙

1. **첫 이미지 한 장에서 끝난다.** 대표 이미지가 곧 당락
2. 설명은 **문제 → 통찰 → 해결 → 결과** 순. 기능 나열 금지
3. **컨셉·학생 부문임을 정확히 표기.** 실제 운영 중인 것처럼 쓰면 규정 위반이 될 수 있다
4. 한계는 최소한으로. 다만 **"컨셉 단계"라는 사실은 명시**한다 (허위 표시 방지)
5. 영문판은 번역이 아니라 **다시 쓴다**

## 9. 협회 · 학회

### 협회 (한국노인복지중앙회, 대한요양병원협회 등)
- 1~2장 + **협회지 기고 / 세미나 발표 제안**을 함께 건다
- 협회는 물건을 사지 않는다. **회원에게 도움이 되는 정보**를 원한다
- 각도: "요양시설 종사자 대상 디지털 소통 설계 사례 공유"

### 학회
- 현재 상태로 가능한 것은 **설계 사례 연구(case study)** 뿐
- **Limitations 절이 필수**다. 학술 문서에서 한계 미기재는 결격
- 파일럿 결과가 나오면 그때 실증 논문
