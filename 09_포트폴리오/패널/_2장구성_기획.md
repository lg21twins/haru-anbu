### 1-2. 추가 레퍼런스 2장 (2026-08-14 투입, `_레퍼런스/ATOMX-01·02` — 2026-08-28 이름·위치 정리)

둘 다 3507×2480 = **A4 가로 300dpi**. NASA 판과 동일 판형.

**001 ATOMX — 개요·리서치판**
- 초대형 고스트 워드마크(배경에 반투명으로 깔린 프로젝트명)
- 기울인 3D 폰 2대 + 하늘 그라데이션 배경 + 실사 인물 워터마크
- 우측 상단 `User Needs → Solution` **2열 대응표** — 니즈 한 줄마다 해법 한 줄이 마주 봄
- **Service Diagram (벤 3원)** — 개념을 3축 교집합으로
- `92%` 초대형 수치 + 라인차트, `How / Who / Why / When / Where` **5W 카드 그리드**

**002 화면 갤러리판 — 이미 하루안부 화면이 배치된 WIP**
- 보호자 홈·일일 리포트, 어르신 태블릿, 요양보호사 오늘, 의료진 웹 대시보드, AI 가이드가 **실제로 들어가 있음**
- 다만 헤드라인 카피는 원본 템플릿("마이페이지에서 나의 칭찬 활동 내역을…", "칭찬 구슬", "칭찬 공개 전/후")이 그대로 남은 상태 → **카피 교체 필요**
- 여기서 건질 정보 장치 5개:
  1. **지시선 콜아웃** — 화면 옆에 선을 뽑아 `받은 칭찬 개수` `타임트래커 & CTA버튼` 처럼 기능을 지목
  2. **번호 시퀀스 캡션** `01` `02` — 화면에 읽는 순서를 부여
  3. **상태 칩** `공개 전` / `공개 후` — 같은 화면의 두 상태를 나란히
  4. **역할 그룹핑** — 컬러 블롭으로 화면 군집을 묶음
  5. 코드 에디터 · 웹 대시보드 · 실사 사진을 폰 사이에 섞어 리듬을 만듦

**002 실측 (원본 3507px ÷ 297mm = 300dpi 확정. px→pt는 ÷300×72)**

| 요소 | 실측값 | 우리 판 적용값 |
|---|---|---|
| 섹션 라벨 (`MY PAGE`) | 22px ≈ 5.3pt · 액센트 볼드 · 대문자 | **7pt**(인쇄 하한 준수) |
| 국문 헤드라인 | 52px ≈ 12.5pt Bold · 2행 · **강조어만 액센트색** | 보드2 존 제목 12pt |
| 부속 본문 | 26px ≈ 6.2pt 회색 2행 · 헤드라인 **우측**에 베이스라인 정렬 | 6.5pt |
| 지시선 | 폰 우측 가장자리에서 15px 띄우고 **점선 50px(4.2mm)** + 끝에 지름 8px 원점 | 헤어라인 실선 4mm + 0.7mm 점 |
| 콜아웃 라벨 | 28px ≈ 6.7pt 액센트 볼드 | 7pt |
| 콜아웃 본문 | 24px ≈ 5.8pt 회색 3행 · 폭 250px(21mm) | 6.3pt / 폭 22mm |
| 콜아웃 세로 간격 | 290px ≈ 24.5mm | 24mm |
| 번호 캡션 | 번호 40px ≈ 9.6pt 볼드 + 본문 32px ≈ 7.7pt · 간격 18px | 번호 10pt / 본문 7.3pt |
| 상태 칩 | pill · 전=연회색 필+회색 글자 / 후=진회색 필+흰 글자 | **명도 대비만 사용**(유채색 필 금지) |

**중요한 발견 2가지**
1. **번호 캡션의 번호 색이 그 군집의 역할색을 따라간다**(파랑=보호자군, 주황=어르신군). 컬러 블롭 없이 **번호 색만으로 역할 군집을 표시**할 수 있다. 배경 필이 아니라 타이포 색이므로 우리 규칙에 걸리지 않는다 — 이걸로 블롭을 대체한다
2. **헤드라인 블록은 이미 흰 에디토리얼이다.** 흰 배경·박스 없음·강조어 1색·크기로만 위계. 버릴 건 배경 블롭과 그라데이션뿐이고, 정보 블록 자체는 그대로 쓸 수 있다

**확정 규칙과의 충돌 (그대로 가져오면 안 되는 것)**

| 레퍼런스 요소 | 충돌하는 우리 규칙 | 흰 에디토리얼로의 번역 |
|---|---|---|
| 하늘 그라데이션 배경 | 그라데이션 전면 금지 | 흰 바탕 |
| 역할별 컬러 블롭 | 배경 컬러 필 금지 | **여백 + 헤어라인 + 역할 라벨**로 군집 |
| 둥근 컬러 카드 다수 | 박스·테두리 최소 | 카드 제거, 라벨+본문만 |
| 기울인 3D 목업 | 기존 편입판에서 이미 "버린 것"으로 명시 | 정면 목업 유지 |
| 강조어 3색 | 액센트 1색 | `#2C7AFC` 하나로(시스템 존의 3역할 컬러는 예외 — 그건 내용 자체) |

→ **채택: 지시선 콜아웃 · 번호 시퀀스 · 상태 칩 · 니즈↔해법 2열 대응표.**
→ **기각: 그라데이션 · 컬러 블롭 · 카드 · 기울임 · 다색 강조.**

### 선별 원칙 (많이 보여주기 ≠ 잘 보여주기)

1. **하나의 축에 꿴다** — "요양보호사가 남긴 기록 하나가 네 역할에게 각자의 언어로 도착한다"
2. **설계 판단이 보이는 화면만** — 설정·마이페이지·청구·알림은 판단이 안 보인다. 전부 제외
3. **크기 계급 3단** — 지배 1 / 대표 4 / 조각 다수. 같은 크기로 늘어놓지 않는다
4. **전체 화면보다 조각이 더 많은 말을 한다** — 카피 한 줄, 버튼 하나가 결정의 증거

### 정리해야 할 모순 — "세 시선" vs "네 역할"

쇼케이스는 **3시선**(환자·케어팀·보호자, 케어팀=요양보호사+의료진), 편입판은 **4역할**. 컬러도 3색이다.

> **세 시선, 네 화면, 하나의 기록.**
> 컬러는 시선을 나누고(3색), 앱은 역할을 나눈다(4개). 케어팀은 같은 시선을 공유하되 화면이 다르다.

모순이 아니라 **2계층 구조**로 설명하면 오히려 시스템의 정교함이 증명된다.

## 6. 제작 순서

1. 쇼케이스에서 이식 — 차트 SVG · 브랜드 작도 · 컬러 3역할 · 아이콘 15 (`haru-anbu-showcase-v8.html`)
2. 신규 캡처/크롭 3점 — 조각 ①②③
3. 보드1 골격 → Care Flow 6단계 다이어그램 CSS → 인용 4열 → 기여 블록 카피 확정
4. 보드2 골격 → 지시선 콜아웃 → `+ 06` 존 신설 → 캡션 압축(3~4행 → 2행)
5. Chrome 인쇄 → PDF 2p → 실측 검수(6pt 하한 · 헤어라인 · 이미지 해상도)
6. `design_audit.py` 규칙 준수 확인(이모지 · 그라데이션 · 인라인 hex)

파일은 **새로 만든다**: `09_포트폴리오/패널/하루안부_패널_A4가로_2장.html`
기존 `편입_포트폴리오/하루안부_포트폴리오.html`은 손대지 않는다(백업 겸 대조본).

## 7. 결정 필요

1. **v1 초기 시안의 이모지 노출** — 프로젝트 하드룰은 "UI에 이모지 0"이지만 이 이미지는 *제거한 과거의 기록*이다.
   증거로 노출할지, 캡션으로만 서술할지. (노출 쪽이 압도적으로 설득력 있음)
2. **역할·기여 문구** — 3인 팀에서 손예찬이 담당한 정확한 범위
3. **"세 시선 / 네 역할" 2계층 설명을 패널에 명시할지** — 넣으면 정교하지만 한 존을 먹는다
4. 지원 대학 요강 규격(미확인) — 낱장 PDF vs 책자
