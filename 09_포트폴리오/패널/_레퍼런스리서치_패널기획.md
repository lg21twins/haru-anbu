# 하루안부 UX·UI 디자인 패널 — 레퍼런스 리서치 & 제작 기획

작성 2026-08-14 · 목적: **디자인대학 편입 포트폴리오**용 하루안부 소개 패널(A4)
기존 산출물 위에 얹는 기획이며, 처음부터 새로 만드는 계획이 아님.

---

## 0. 전제

- 이 패널은 두 가지 일을 동시에 해야 한다.
  1. **서비스 소개** — 하루안부가 무엇이고 왜 이렇게 설계했는가
  2. **편입 심사용 역량 증명** — 이 사람이 리서치·구조화·타이포·시스템을 다룰 줄 아는가
- 2번이 상위 목적이다. 심사자는 서비스를 사고 싶은 게 아니라 **사고 과정**을 본다.
- 하루안부 정체성 고정: 독거노인용 앱이 아니라 **요양시설의 가족·어르신·요양보호사·의료진을 잇는 케어 소통 플랫폼**.
- 표현 규칙(프로젝트 확정): 이모지 0 · 그라데이션 0 · 배경 컬러 필 0 · 테두리 최소(헤어라인) · 위계는 타이포와 간격으로만.

## 1. 레퍼런스 해부 — 내가 만든 NASA "Pocket Mission Control" 패널

Figma `iNt51HokozrSYHr5ElRZqc` / 판형 3507×2480px = **A4 가로 300dpi**. 두 장이 역할을 나눠 갖는다.

### 패널 A (node 1-5) — 개념 · 결정 · 시스템판

읽는 순서가 Z가 아니라 **좌상단 이미지 → 우상단 타이틀 → 좌하단 브리프 → 중앙 근거 → 우측 결정/시스템 → 하단 탭 카드** 로 설계돼 있다.

| 영역 | 역할 | 하루안부 대응 |
|---|---|---|
| 좌상단 풀블리드 실사 + 손안의 폰 | 감정 훅. 패널 전체에서 **유일하게 큰 이미지 1장** | 요양시설 현장/가족 장면 + 폰 |
| 이미지 위 흰 카드(로고+한 줄) | 프로젝트 명패 | 하루안부 로고 + 부제 + 크레딧 |
| 우상단 타이틀 블록 | 초대형 제목 + 자간 넓은 마이크로 라벨 + 한 줄 정의 | 서비스 정의 한 줄 |
| CORE IDENTITY 원 3개 | 개념을 3축으로 압축(× 기호로 곱셈 표현) | 4역할 또는 3원칙 |
| MISSION BRIEF + 스펙표 | 본문 + `라벨 ··· 값` 데이터표 | 개요 + 규모/데이터 |
| 중앙 코드 에디터 콜라주 | **"진짜 만들었다"는 근거** | 토큰/감사 스크립트 (이미 보유) |
| DESIGN DECISION 1·2·3 | 초대형 숫자 + 결정문 + 초소형 다이어그램 | 설계 결정 3개 |
| DESIGN SYSTEM | 문단 + 스페이싱 스트립 + 로고 + 컬러칩 + 타입 샘플 | 토큰 357개 시스템 |
| FOUR TABS 카드 4장 | 라벨 + 2행 국문 헤드라인 + 본문 + 이미지 + 메타 | 4역할 화면 |

### 패널 B (node 1-9) — 화면 갤러리판

- 배경 실사 1장 풀블리드, 그 위에 **폰 목업 10대 + 잘라낸 UI 조각**을 비정형(느슨한 대각선)으로 띄움
- 섹션 마커는 `01 TODAY` 처럼 **번호 + 초광폭 자간 영문 + 2행 설명**만. 상자·선 없음
- 화면 자체가 유일한 채도. 배경·타이포는 무채색
- 좌하단에 코드 에디터 1개 — 갤러리판에서도 "구현물"임을 다시 못박음

### 추출한 규칙 12개 (그대로 재사용 가능)

1. 판형 A4 가로 300dpi, 여백은 크게(외곽 12~14mm)
2. **중간 크기 글자를 없앤다** — 초대형(제목) / 소(본문) / 초소(라벨·캡션) 3단만
3. 마이크로 라벨은 대문자 + 자간 0.2~0.3em + 회색
4. 번호를 시각 요소로 쓴다(01, 1·2·3, 초대형 숫자)
5. 구분은 헤어라인 1px 또는 여백. 박스·배경칠 금지
6. 컬러는 화면 캡처가 전담. 지면은 무채색 + 액센트 1색
7. 이미지는 크기 계급을 만든다 — 지배 1장 + 종속 다수
8. 데이터는 `라벨 ··· 값` 표 형태로 반복 리듬을 만든다
9. 캡션은 설명이 아니라 **주장**을 쓴다("~했습니다")
10. 근거를 노출한다(코드·법령·수치 출처)
11. 하단 러너에 메타 정보(크레딧·URL·페이지)를 고정
12. 국문 본문은 `word-break:keep-all`, 2행 이내로 끊기

### 기존 2장판의 결손 (편입 기준)

- **과정이 없다.** 리서치 → 페르소나 → 플로우 → 와이어프레임 → 테스트 → 반영이 한 장도 없음. 편입 심사가 가장 보고 싶어 하는 부분
- **키 이미지가 없다.** 첫 3초에 붙잡는 지배 이미지 부재 → 심사대 위에서 다른 지원자 판에 밀림
- **개인 기여 표기가 약함.** 3인 팀 중 무엇을 내가 했는지 한 줄뿐
- 2장은 편입 포폴 한 챕터로는 짧다(프로젝트당 6~12p가 통상)

## 3. 웹 리서치 요약

### 편입 포트폴리오 관점

- 시각디자인 편입은 브랜드·타이포·UX/UI·패키지 결과물을 제시하고 평가받는 유형이며 상위권 대학 위주 ([designthe](https://www.designthe.co.kr/%EC%8B%9C%EA%B0%81%EB%94%94%EC%9E%90%EC%9D%B8%EA%B3%BC-%ED%8E%B8%EC%9E%85-%ED%8F%AC%ED%8A%B8%ED%8F%B4%EB%A6%AC%EC%98%A4))
- 필수 3요소: **학업 연장선상의 디자인 결과물 + 지원동기·연계방안 서술 + 인사이트 중심 면접** ([dadadesignlab](https://dadadesignlab.com/21))
- UX/UI는 **UI 스펙과 인터랙션 모션**을 명확히 보여줄 자료가 필요. 어떤 툴로, 어떤 프로세스로 최적화했는지 전달 ([아카데미정글](https://ejungle.co.kr/UIUX_DesignPortfolio))
- **규격은 대학마다 다름.** 부산대는 크기 제한 없는 책자형 자유형식. 지원 대학 요강 PDF 직접 확인 필요 → *미확인 사항으로 남김*

### UX 케이스스터디 표준 구조 ([uxfol.io](https://blog.uxfol.io/ux-case-study-template/))

Hero → Overview(역할·툴·기간·문제정의) → Discovery(리서치·페르소나·경쟁분석) → Design Process(플로우·와이어프레임·테스트·반복) → Final Design(대안 비교·전후) → Impact(수치·피드백) → Learnings

핵심 조언 2개:
- 방법을 나열하지 말고 **왜 그 방법을 썼고 무엇이 다음 단계를 바꿨는지** 쓸 것
- **실패한 와이어프레임과 수정본을 같이** 보여주는 게 문제해결력 증명에 가장 효과적
- 상세한 케이스 3개가 얕은 6개보다 낫다 ([uxpilot](https://uxpilot.ai/blogs/product-design-portfolio-case-studies))

### 없어서 만들어야 하는 것

## 5. 구성안

### 추천 — A4 가로 6장 (기존 2장 확장)

| # | 판 | 내용 | 주 자산 |
|---|---|---|---|
| 1 | **표지 · 키비주얼** | 지배 이미지 1장 + 서비스 정의 한 줄 + 로고 명패 + 크레딧/기여 | 신규 제작 |
| 2 | **문제 · 사용자** | 출처 있는 수치 3 + 4역할 페르소나 + 현장 인용 | 통계, persona/ |
| 3 | **구조 · 설계 결정** | 1입력 4출력 다이어그램 + 일부러 안 만든 것 3(SaMD 회피) + 법령 근거 | 기존 2장판 보드1 |
| 4 | **네 개의 화면 언어** | 4역할 대표 화면 + 캡션(주장형) + 태블릿 결정 | 기존 2장판 보드2 |
| 5 | **스크린 갤러리** | 화면 10~14 + UI 조각 클로즈업 (NASA 패널B 구조) | 39화면 재캡처 |
| 6 | **시스템 · 과정** | 토큰/컴포넌트/자동검사 + v1→v7 진화 + 피드백 전후 3쌍 + 코드 근거 | mockup/, 실험본 |

압축이 필요하면 **4장**(1+2·3 병합+4·5 병합+6), 여유 있으면 5번을 2장으로 늘려 7장.

### 톤 — 하이브리드 추천

- 1번 표지만 **이미지 지배**(어둡거나 사진 풀블리드), 2~6번은 **흰 에디토리얼**(기존 2장판 계승)
- 이유: 편입 심사는 타이포·그리드 운용을 본다. 흰 판이 그걸 정직하게 드러냄. 다만 표지 한 장의 임팩트는 반드시 필요
- 액센트 1색만: `#2C7AFC`(브랜드 블루). 역할색은 화면 캡처 안에서만 살아 있게

## 6. 인쇄 스펙

- A4 가로 297×210mm / 300dpi(3508×2480px)
- 외곽 여백 12mm(상) 14mm(좌우) 10mm(하) — 기존 2장판과 동일하게 유지
- 재단 여백은 인쇄소 제출 시에만 3mm 추가(화면 PDF엔 불필요)
- 폰트 Pretendard Variable. 본문 7.3pt / 캡션 6.3pt / 라벨 6~7pt — **6pt 미만 금지**(A4 인쇄 하한)
- 출력 경로: HTML → Chrome 인쇄 → PDF(배경 그래픽 켜기)

## 7. 확정 필요 사항

1. **지원 대학 / 요강 규격** — 판형·장수·제출 형식(책자 vs 낱장 PDF)이 여기서 결정됨. 요강 PDF 확인 필요
2. **하루안부가 포폴 전체인가, 한 챕터인가** — 챕터면 앞뒤 다른 프로젝트와 판형·러너를 통일해야 함
3. **장수 확정** — 4 / 6 / 7
4. **키 이미지 소스** — 기존 생성 이미지 사용 vs 신규 제작
5. 개인 기여 문구 — 3인 팀에서 내가 한 것의 정확한 범위
