### 3-4. 스크린샷 50장 캡처 (v12)

**사용자 프롬프트 원문:**
> "하루안부 기획서 v12 1920*1080 사이즈에 맞게 gap과 여백 주의하고 슬라이드가 잘리거나 밀리지 않게 주의해서 50장 스크린샷 찍어줘. 누락되지 않게 확인하면서 슬라이드 번호 맞게 스크린샷 찍어."

**겪은 오류 및 해결:**

| 오류 | 원인 | 해결 |
|------|------|------|
| `networkidle` 타임아웃 | CDN 폰트 요청이 계속 열려있어 30초 초과 | `wait_until="load"` + `wait_for_timeout(2000)` |
| `setScale is not defined` | Playwright evaluate()에서 HTML 내 `<script>` 함수 접근 불가 | evaluate() 안에 스케일 로직 인라인으로 재정의 |
| 슬라이드 잘림 | scale=1 뷰포트에서 body padding이 좌표를 밀어냄 | `body { padding: 0 !important }` + clip bbox 사용 |

**최종 스크린샷 방식:**
```python
# clip으로 정확히 1920×1080 영역만 캡처
bbox = await slide.bounding_box()
await page.screenshot(clip={"x": bbox["x"], "y": bbox["y"], "width": 1920, "height": 1080})
```

### 4-4. 색상 의미 부여 — SWOT 사분면

**v12 문제:** SWOT 4분면이 모두 `background: #f9f9f9` — 강점/약점/기회/위협이 색으로 구분되지 않음.

**v13 해결:**
```
S (Strength)  → background: #f0f4ff  (파랑 — 긍정/역량)
W (Weakness)  → background: #fff5f5  (빨강 — 주의/개선)
O (Opportunity)→ background: #f0fff4 (초록 — 성장/가능성)
T (Threat)    → background: #fffbeb  (황색 — 경고/외부)
```

**원칙:** 색상은 미적 구분이 아니라 의미적 코딩이어야 한다. SWOT의 S/O는 긍정, W/T는 부정이므로 색온도도 이를 반영.

### 4-5. S39 기대효과 재설계

**v12 문제:** 3컬럼 카드가 텍스트 나열에 그침. 임팩트 전달력 약함.

**v13 해결 방향:**
- 역할별 아이콘: 텍스트 아이콘 → 의미 있는 이모지 (`😌` 보호자 / `🤝` 환자 / `⚡` 의료진)
- 아이콘 컨테이너: 원형 → `border-radius: 14px` 정사각형 (`background: #eff6ff`)
- 수치 통계: 인라인 텍스트 → `font-size: 32px; font-weight: 700` 대형 숫자
- 역할 라벨 칩 추가: 각 카드 상단에 역할 배지

> "누락되지 않게 확인하면서"

**의미:** 숫자와 검증 조건을 정확히 명시. 결과물 스펙이 명확.

## 6. 기술 스택 & 도구 사용 기록

### HTML 슬라이드 아키텍처

```html
<!-- 구조 패턴 -->
<div class="slide-outer">        <!-- 반응형 컨테이너 -->
  <section class="slide">        <!-- 1920×1080 고정 캔버스, overflow:hidden -->
    <div class="top-bar">        <!-- y=80px 고정 네비게이션 -->
    <p style="top: 168px">       <!-- 섹션 eyebrow -->
    <h2 style="top: 208px">      <!-- 페이지 타이틀 -->
    <!-- 콘텐츠 영역: top 288~360px -->
    <div class="pg-v3">          <!-- 페이지네이션 y=1000px -->
  </section>
</div>
```

**스케일링 원리:**
```javascript
// slide-outer width에 맞춰 slide를 scale()로 축소
const scale = outer.offsetWidth / 1920;
slide.style.transform = `scale(${scale})`;
outer.style.height = (1080 * scale) + 'px';
```

### Playwright 스크린샷 핵심 코드

```python
# 핵심: body padding 제거 후 정확히 1920×1080 clip
await page.add_style_tag(content="""
    body { padding: 0 !important; margin: 0 !important; }
    .slide-outer { margin-bottom: 0 !important; }
""")

# setScale 재실행 (인라인 재정의 필수)
await page.evaluate("""() => {
    document.querySelectorAll('.slide-outer').forEach(outer => {
        const slide = outer.querySelector('.slide');
        const scale = outer.offsetWidth / 1920;
        slide.style.transform = 'scale(' + scale + ')';
        outer.style.height = (1080 * scale) + 'px';
    });
}""")

# 슬라이드 캡처
bbox = await slide.bounding_box()
await page.screenshot(path=str(fname), clip={
    "x": bbox["x"], "y": bbox["y"],
    "width": 1920, "height": 1080
})
```

## 7. 이 세션에서 학습한 것

### 기술적 학습

1. **Playwright `wait_until` 선택**: `networkidle`은 CDN 폰트/외부 리소스가 있으면 타임아웃 발생. HTML 파일 로컬 로딩은 `"load"` + 고정 대기가 더 안정적.

2. **`page.evaluate()`의 스코프**: Playwright evaluate()는 HTML `<script>` 태그 안의 함수를 참조할 수 없음. 필요한 로직은 evaluate() 내부에 인라인으로 재정의해야 함.

3. **CSS `letter-spacing`**: 퍼센트 단위(`-2%`)는 `letter-spacing` 속성에서 유효하지 않음. `px` 또는 `em`으로만 지정.

4. **다크 슬라이드 색상 전략**: 특정 hex 값 대신 `rgba(255,255,255, opacity)` 패턴을 쓰면 배경색이 바뀌어도 시각적 계층이 유지됨.

### 디자인 학습

1. **여백 감사 체계**: "여백이 많다"는 주관적 판단을 수치화하려면 `top: Npx`를 전체 슬라이드에서 스캔해 분포를 파악하는 것이 가장 빠름.

2. **콘텐츠 시작점의 황금 기준**: 이 프로젝트에서 확인된 최적 범위 = eyebrow `168px` + title `208px` + content `288~352px`. 이 범위를 벗어나면 시각적으로 이상함을 느낌.

3. **의미적 색상 코딩**: 4분면/4범주 데이터는 임의 색상이 아니라 의미(긍정/부정/위험/기회)에 기반한 색온도를 사용해야 정보 전달력이 높아짐.

4. **Featured 카드 패턴**: 3개 이상의 병렬 카드가 있을 때, 가운데 카드를 `background: #eef3ff + border: 2px solid #2c7afc`로 강조하면 자연스럽게 시선이 집중됨.
