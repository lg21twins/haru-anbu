# 03 · Patterns

**하루안부 디자인 시스템 v3.2 — 화면·플로우 패턴**

이 문서는 컴포넌트를 어떻게 조합해서 화면을 만드는지에 대한 규칙이다. [02_COMPONENTS.md](02_COMPONENTS.md)가 "벽돌"이라면 이 문서는 "방의 평면도".

## v3.1 화면 디자인 원칙 (조용한 기본값)

화면을 디자인할 때 다음 규칙을 지킨다 — **베리에이션이 아니라 차분함**이 우선:

1. **강한 히어로 그라디언트는 화면당 최대 1개** — 역할 그라디언트 카드(card-hero)는 한 화면에 한 번만. 나머지는 모두 흰 surface 카드.
2. **배경 그라디언트는 약한 tint만** — 페이지 상단 120px만 살짝 물들이고, 본문 영역은 캔버스 그레이로 빠르게 페이드.
3. **Glass card 반복 금지** — 정보 카드는 모두 `card-default`(흰 surface). Glass는 탭바·모달 등 정해진 4곳만.
4. **환자 화면은 더 큰 UI, 더 강한 색은 아님** — 본문 18px·터치 56px·카드 padding 24px로 자동 상향. 오렌지는 큰 면이 아닌 액센트로만.
5. **의료진 화면은 색면을 줄이고 표·리스트 가독성 우선** — 그린 큰 면 사용 금지. 정보 밀도가 우선.
6. **보호자 화면은 안심 상태·최근 변화·다음 행동 순서** — 감성적 문구가 아니라 정보 위계가 우선.

## P0. 화면 표면 원칙 (v3.1 통합)

**기본은 하나다**: 흰 surface + 약한 보더 + 약한 shadow. 모든 화면이 이 기본을 따른다.

### P0.1 모든 화면의 공통 기본

| 영역 | 표면 |
|---|---|
| 페이지 배경 | `--color-bg-canvas` (#F0F4F8) — 모든 역할 동일 |
| 페이지 상단 120px | 매우 약한 역할 tint 그라디언트 (`--color-bg-role-gradient`) |
| 일반 정보 카드 | `card-default` (흰 surface + 1px 보더 + shadow-1) |
| 클릭 가능 카드 | `card-action` |
| 상태 강조 | `card-alert--{success/warning/danger/info}` |
| 화면 1순위 강조 | `card-hero` — 화면당 최대 1개 |

### P0.2 화면별 미세 조정 (큰 차이 없음)

| 역할 | 미세 조정 |
|---|---|
| 보호자 (모바일) | 위 기본 그대로 |
| 의료진 (웹) | 카드 padding `--space-5`로 컴팩트, 행 간격 `--space-3`로 dense |
| 요양보호사 (모바일) | 터치 48px, 버튼 52px, 행 60px (현장 한 손 조작) |
| 환자 (모바일) | 본문 18px, 터치 56px, 행 64px, 카드 padding 24px (자동 상향) |

### P0.3 Glass 사용 한정 (4곳만)

Glass(반투명 + blur)는 일반 정보 카드에 절대 쓰지 않는다. 다음 4곳에만 한정:

1. 플로팅 필 탭바
2. 모달 sheet (바텀시트 본체)
3. AI 리포트 카드 (선택적, hero 대신 쓸 때)
4. 환자앱 가족 사진 카드 (감성 자료)

### 결정 흐름

새 화면을 만들 때:

```
이 카드는 어떤 역할인가?
├── 일반 정보 표시 → card-default
├── 탭하면 이동 → card-action
├── SOS·위험·주의·정보 → card-alert
├── 화면의 1순위 강조 (1개 한정) → card-hero
└── 그 외 (탭바·모달·AI·가족 사진) → glass
```

화면당 `card-hero`는 1개를 넘지 않는다. 더 강조할 게 있으면 우선순위를 다시 검토.

## P1. 페이지 셸 (Page Shell)

모든 모바일 페이지의 골격은 동일하다.

```
┌──────────────────────────────┐ ← 역할 그라디언트 배경
│  Header (sticky, 44px)       │
├──────────────────────────────┤
│                              │
│  Page content (16px margin)  │
│                              │
│  - card                      │
│  - card-row                  │
│  - card                      │
│                              │
│  ─ scroll padding-bottom 96px│ ← 탭바 가림 방지
├──────────────────────────────┤
│ [floating tabbar 16px inset] │ ← 56px + safe-area
└──────────────────────────────┘    [FAB] ← 우측 분리
```

```css
.page {
  min-height: 100dvh;
  background: var(--color-bg-role-gradient);
  padding-bottom: calc(56px + var(--space-5) + env(safe-area-inset-bottom) + var(--space-7));
}
.page__main {
  padding: var(--space-5);                 /* 16px (data-platform=web 시 24px 자동) */
}
```

웹 의료진은 페이지 셸이 다르다 — 사이드바 240px + 헤더 64px + 본문 max-width 1280px.

## P2. 홈 화면 — "오늘 안심 확인" (보호자)

서비스개선안 v1.0 P0 기능: 매일 저녁 보호자가 안심하게 확인하는 핵심 화면.

```
┌────────────────────────────────┐
│ [헤더: 오늘 5월 9일 · 알림 · ]  │
├────────────────────────────────┤
│ ┌─Hero card──────────────────┐ │ ← card-hero (오늘의 안부 상태)
│ │ "오늘은 안정적이세요"        │ │
│ │ 식사 ●● 투약 ●● 활동 ●     │ │
│ └────────────────────────────┘ │
│ ┌─Card grid (2x2)────────────┐ │ ← 핵심 카드 4개
│ │ 식사     │ 투약            │ │
│ │ 수면/기분│ 활동            │ │
│ └────────────────────────────┘ │
│ ┌─AI 리포트 카드──────────────┐ │ ← card-glass (예외 4곳 중 하나)
│ │ "오늘의 한 문장 요약"       │ │
│ │ [자세히 보기]              │ │
│ └────────────────────────────┘ │
│ ┌─Card──────────────────────┐ │
│ │ 궁금한 점 남기기 (CTA)      │ │
│ └────────────────────────────┘ │
│ ┌─주간 안심 지수 (P1)───────┐ │
│ │ [차트]                    │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

위계:
1. **Hero** — 오늘의 한 줄 상태 (안정 / 확인 필요 / 긴급)
2. **2×2 그리드** — 식사·투약·수면·활동 4축 요약
3. **AI 리포트** — 오늘의 한 문장 + 자세히 보기 (바텀시트로 풀 리포트)
4. **문의 CTA** — 단일 진입점
5. **주간 추세** — 보조 정보

사용자는 위에서 아래로 자연스럽게 읽고, 첫 화면에서 "안심"을 받아야 한다. 정보가 5번째 카드를 넘어가면 잘라내거나 다른 페이지로 분리.

## P3. AI 패턴 5종 (v3.2 확장)

**v3.2 변경**: 이전 버전은 P3가 'AI 리포트' 한 종류만 다뤘다. v3.2부터 하루안부의 모든 AI 상호작용을 **5종 패턴**으로 표준화한다 — KT Seamless Flow의 AI 패턴 5종을 하루안부 도메인(돌봄·환자·의료진)에 맞춰 재정의한 것.

### P3.0 5종 한눈 매트릭스

| # | 패턴 | 사용처 | 핵심 컴포넌트 | 진입점 |
|---|---|---|---|---|
| P3A | **대화형 질의응답** | 보호자 챗, 가족 채팅 | H1 Input · H2 Output · H4 Refusal | 탭바 옆 FAB |
| P3B | **음성 입력** | 환자 도우미, 요양보호사 핸즈프리 | H1 Input(mic 활성) · H2 Output | Prompt Input 마이크 |
| P3C | **사진·파일 분석** | 요양보호사 메모 사진, 의료진 차트 첨부 | H1 Input(첨부) · H2 Output(인용) | Prompt Input 클립 |
| P3D | **AI 리포트 (장문 요약)** | 보호자 일간/주간 리포트 | H2 Output(hero 변형) · timeline | 홈 P2 카드 |
| P3E | **인라인 제안** | 요양보호사 메모, 보호자 답장 작성 | H3 Inline Suggestion | textarea 내부 |

**전체 5종 공통 규칙:**
- 진입점·응답 마크는 **하루안부 심볼 1종** (Fluent sparkle/wand/robot 금지)
- AI 표면은 항상 **중립**(흰색 또는 gray-50). 역할 accent로 큰 면 칠하지 않는다
- 의료 관련 응답은 마지막 줄에 **"최종 판단은 의료진이 합니다"** 면책
- 응답 본문 line-height = `--leading-relaxed` (1.6)
- 라이팅 원칙: 진단·처방 변경 제안 금지, 불안 자극 금지, 사실/수치 분리, 친근 ~요체

### P3A. 대화형 질의응답 (보호자 챗)

```
┌────────────────────────────┐
│                            │ ← 페이지 상단: 컨텍스트 카드 (예: 오늘 안부 요약)
│  [상대 메시지, 좌측]        │
│  ai-output (mark + body)   │
│                            │
│           [내 메시지, 우측] │ ← 사용자 메시지 (accent 배경)
│                            │
│  [상대 메시지]              │
│  ai-refuse (거절 카드)      │ ← 답할 수 없을 때
└────────────────────────────┘
[ai-prompt: 좌측 마크 + 입력 + 우측(첨부·마이크·전송)]
```

#### 규칙

- AI 응답은 항상 **하루안부 심볼 좌측 + "하루안부 AI" 라벨**. 사람 메시지와 헷갈리지 않게.
- 응답 카드 우상단에 `AI 생성` 뱃지 (H2 Output 변형).
- 첫 진입 시 **추천 질문 칩 3개** 노출 (예: "오늘 식사는?" / "어제와 달라진 점은?" / "주간 요약").
- 응답 생성 중: 본문 자리에 **3-dot 타이핑 인디케이터** + 좌측 심볼은 부드러운 펄스 애니메이션.
- 응답 길이가 짧으면(2줄 이하) 인용 footer 생략 가능. 의료/처방 응답은 길이 무관 footer 필수.

#### 거절 트리거 (P3A → H4)

| 입력 의도 | 트리거 |
|---|---|
| 처방 변경 ("약 좀 바꿔달라") | H4 "이 질문은 의료진께 문의해 주세요" |
| 진단 ("우울증인가요?") | H4 동일 |
| 본인 외 개인정보 요청 | H4 "이 정보는 알려드릴 수 없어요" |
| 데이터 부족 (3일 이상 기록 없음) | H4 "오늘은 답변할 데이터가 부족해요" |

### P3B. 음성 입력 (환자 · 요양보호사)

```
┌────────────────────────────┐
│  [기존 채팅 영역]            │
│                            │
│  [현재 음성 인식 텍스트…]   │ ← 회색 흐림 미리보기, 실시간 업데이트
│                            │
└────────────────────────────┘
[ai-prompt: mic 활성 (붉은 펄스) + "취소"]
       ↓ 음성 종료 시
[하루안부 심볼 펄스 → 응답 카드]
```

#### 규칙

- **환자앱과 요양보호사앱에서 기본 활성**. 보호자앱·의료진은 선택적.
- 음성 입력 시 화면에 두 영역만 보인다: **(1)** 인식 중인 텍스트(`color-text-tertiary`로 흐림), **(2)** 큰 마이크 아이콘 + "듣고 있어요" 라벨.
- 마이크 아이콘 옆 **취소 버튼은 항상 56px 이상** (환자 화면도 동일 — KRDS 접근성).
- 음성 종료 → 인식된 텍스트가 사용자 메시지로 굳어진 뒤 AI 응답 시작.
- 환자앱 한정 추가 규칙:
  - **모든 응답을 TTS(Text-to-Speech)로도 재생** — 카드 우측에 스피커 아이콘.
  - 응답 카드에 텍스트 라벨 병기 ("듣기 / 다시 듣기").
  - 음성 인식 실패 시 H4 Refusal 사용 안 함 — 단순 토스트 "다시 말해 주세요"로 가벼이 처리.

#### 접근성

- `aria-live="polite"`로 인식 중 텍스트 갱신을 스크린리더에 전달.
- `prefers-reduced-motion: reduce`면 마이크 펄스 애니메이션은 정적 색 토글로 대체.

### P3C. 사진·파일 분석

```
┌──────────────────────────────┐
│ [ai-prompt: 첨부 파일 칩]    │ ← 입력 위에 첨부 미리보기 (썸네일 + 파일명 + ×)
│  ┌──────┐                    │
│  │ IMG  │ 사진 1장 첨부됨    │
│  └──────┘                    │
│ [궁금한 점 입력]              │
└──────────────────────────────┘
       ↓ 전송
[ai-output: 인용 footer에 첨부 출처 표기]
```

#### 규칙

- **요양보호사앱 사진 메모**: 메모 입력란에 사진 1장 첨부 → AI가 "사진 속 상황 자동 설명" 제안 → 보호사가 검토 후 전송.
- **의료진 차트 파일**(v3.2 미구현): 추후 PDF·이미지 첨부 가능. UI 슬롯만 예약.
- 보호자앱은 사진 첨부 비활성 (개인정보 보호 차원 — 가족 사진은 채팅 첨부지, AI 분석 대상 아님).
- 첨부 파일 시각: 인풋 위 별도 줄에 칩 — 인풋 내부에 끼워 넣지 않는다.
- 응답 인용 footer에 출처 명시: "근거 · 첨부 사진 1장 (분석은 자동, 정확도 보장 안 됨)".

#### 라이팅 (사진 분석 응답)

- "어머님이 ~를 하고 계신 것 같아요" 같은 **추정 표현** 사용 — 확정 금지.
- 사람의 표정·감정 추정은 **금지**. 행동·환경만 기술 ("자리에 앉아 식사 중", "창문이 열려 있음" OK / "기분이 좋아 보이심" NG).
- 의학적 판단(상처, 욕창, 출혈 등) 발견 시 → 응답에 H4 Refusal 카드를 함께 표시 ("의료진 확인이 필요해요").

### P3D. AI 리포트 (장문 요약)

기존 P3 리포트 패턴을 그대로 흡수한 항목. 보호자 P2 홈에서 카드 탭 → 바텀시트로 풀 리포트가 열린다.

#### P3D.1 리포트 구조 (6 섹션 고정)

```
1. 오늘의 한 문장        ← H2 Output hero 변형 (역할 그라디언트 + 흰 텍스트)
2. 식사와 수분           ← H2 Output (food 아이콘)
3. 투약                  ← H2 Output (pill 아이콘)
4. 활동과 컨디션         ← H2 Output (accessibility 아이콘)
5. 특이사항              ← H2 Output (info 아이콘)
6. 내일 확인하면 좋은 점 ← H2 Output (lightbulb 아이콘)
```

이 6개 섹션 순서를 바꾸지 않는다. 누락된 정보는 "기록되지 않음"으로 명시 (빈 카드 X).

#### P3D.2 시각 표현

- 한 섹션 한 H2 Output 카드. 좌상단 fluent 아이콘 + 우상단 `AI 생성` 뱃지.
- "오늘의 한 문장"만 `ai-output--hero` (역할 그라디언트). 나머지는 흰 카드.
- 섹션 사이 간격 `--space-stack-section` (32px).
- 마지막 카드 아래 면책 1줄: "최종 판단은 의료진이 합니다. 궁금한 점은 담당 간호사에게 문의해 주세요."

#### P3D.3 라이팅 원칙 (서비스개선안 v1.0 §5.2)

- **진단하지 않는다** — "어머님은 우울하십니다" 금지.
- **처방 변경 제안 금지** — "약을 바꿔야 합니다" 금지.
- **사실과 수치 분리** — "식사 2/3 드심 (관찰)", "혈압 130/85 (측정)".
- **불안 자극 금지** — "위험"은 SOS 채널에서만.
- **마지막 판단은 시설** — 면책 1줄 필수.

#### P3D.4 주간 리포트 차이

- 일간 리포트(P3D) = 6 섹션 / 주간 리포트 = 4 섹션 (요약 / 변화 패턴 / 강점 / 살펴볼 점).
- 주간은 차트 1개 포함 가능 (`--chart-*` 토큰, P0 #4에서 정의 예정).

### P3E. 인라인 제안 (Inline Suggestion)

본문 입력 중 AI가 음영 회색 텍스트로 자동완성 제안 → Tab 또는 우측 체크 칩으로 채택. H3 컴포넌트 참조.

#### 사용처

| 화면 | 제안 내용 |
|---|---|
| 요양보호사 메모 | "오전 식사를 잘 드" → "셨어요. 평소보다 활기차 보이세요." |
| 보호자 답장 작성 | "감사합니다. 오늘도 잘" → "부탁드려요. 어머님께 안부 전해 주세요." |
| 의료진 차트 코멘트 | (v3.2 미구현) |
| **환자앱** | **사용 금지** — 작은 글자 미리보기는 환자 가독성을 해친다. 환자 입력은 P3B 음성 우선. |

#### 규칙

- 제안은 인풋 값에 들어가지 않는 **고스트 텍스트**로만 표시 (placeholder처럼).
- Tab으로 채택, ESC로 무시, 다른 키 입력 시 자동 사라짐.
- 제안 채택 후 사용자가 한 글자라도 수정하면 추가 제안 일시 정지 (10초 쿨다운).
- 제안 출처 표기: 인풋 우측 칩의 `aria-label` = "AI 제안 (Tab으로 채택)".

#### 라이팅 (인라인 제안 한정)

- **친근 톤 + ~요체** 그대로.
- 길이는 한 문장(최대 60자) — 두 문장 이상 제안 금지.
- 의료 용어 사용 금지 ("투약" → "약 드림", "처치" → "케어").
- 사실 추가 제안 금지 — "어머님이 행복해 보이세요" 같은 감정 단정 금지.

## P6. 알림 / 경보 위계 (v3.2 통합 매트릭스)

KRDS 원칙 + 서비스개선안 §6.1 + Fluent 2 MessageBar 정렬을 따른다 — **위험도가 높을수록 더 침입적인 채널**. v3.2에서 인앱·푸시·배너·토스트 4채널을 단일 매트릭스로 통합.

### P6.1 4단계 × 4채널 매트릭스

| 단계 | 트리거 예 | 인앱 카드 | 인앱 토스트 | 푸시 | SMS/이메일 |
|---|---|---|---|---|---|
| **0 · 정상** | 일반 케어 완료 | success 뱃지 | — | — | — |
| **1 · 정보** | AI 리포트 발송, 메시지 도착, 시스템 안내 | info `card-alert` (선택) | 1회 (2.5초) | 1회 (사용자 설정 시) | — |
| **2 · 주의** | 미완료 케어, 늦은 투약, 입소 만료 14일 전 | warning `card-alert` (홈 상단) | 1회 + 푸시 도착 시 | 1회 (필수) | — |
| **3 · 긴급** | SOS, 의식 저하, 119 호출 | `sos-banner` (최상단, 닫기 없음) | — (SOS가 우선) | **반복 (5분 간격, 응답 시 중단)** | **30초 후 미응답 시** |

### P6.2 채널 정의

| 채널 | 형태 | 보존 시간 | 닫는 방법 | 사용자 통제 |
|---|---|---|---|---|
| **인앱 카드** | 화면 안 `card-alert` 또는 `sos-banner` | 사용자가 닫을 때까지 | 닫기 버튼 / 액션 수행 | 알림 설정으로 비활성 가능 (단계 3 제외) |
| **인앱 토스트** | 플로팅 토스트 (탭바 위 100px) | 2.5초 자동 닫기 | 자동 / 탭 시 즉시 | 비활성 불가 (전체 토스트는 OS 설정) |
| **푸시 알림** | 시스템 푸시 | OS 정책 | OS 정책 | iOS/Android 설정 + 앱 내 토글 |
| **SMS/이메일** | 외부 채널 | 외부 보존 | — | 보호자 본인 외 수신자는 앱 동의 필수 |

### P6.3 채널 격상 규칙

> 단계가 올라가면 위 채널의 모든 하위 채널도 발동한다 (인앱 + 푸시 + SMS).

- 단계 2 미완료가 1시간 지속 → 자동 단계 3으로 격상 (의료진/요양보호사에게 강제 푸시).
- 단계 3 발동 후 30초 내 미응답 → SMS·이메일까지 발송 (보호자, 의료진).
- 단계 3 응답(전화 받기·확인 버튼) → 모든 채널 즉시 중단.

### P6.4 사용자 통제 (앱 내 알림 설정 페이지)

```
┌──────────────────────────────┐
│  알림 설정                    │
├──────────────────────────────┤
│  정보 알림     [ ON ─ ●]      │ ← 단계 1 (사용자 끄기 가능)
│  주의 알림     [ ON ─ ●]      │ ← 단계 2 (사용자 끄기 가능, 권장 ON)
│  긴급 알림     [ON · 잠금 ]  │ ← 단계 3 (잠금, 끄기 불가)
│                              │
│  ───────                     │
│                              │
│  방해 금지 시간                │
│   22:00 ─ 07:00              │ ← 단계 1·2만 무음 처리, 단계 3은 무시
└──────────────────────────────┘
```

#### 규칙

- **단계 3 알림은 사용자가 끌 수 없다** — 환자 안전 직결. 토글에 잠금 표시.
- 방해 금지 시간: 단계 1·2만 무음 / 단계 3은 무시하고 발동.
- iOS Critical Alerts / Android Full-Screen Intent는 단계 3 한정으로 신청.

### P6.5 시각·청각·진동 동시 활용 (KRDS 접근성)

- **시각만 의존 금지** — 단계 3은 빨강 + 사이렌 아이콘 + "긴급" 텍스트 + 푸시 사운드 + 진동 패턴 5중.
- 청각 손실 사용자 대비: 단계 3 푸시는 강한 진동 패턴(긴-짧-짧 반복) 필수.
- 시각 손실 사용자 대비: `aria-live="assertive"` + 스크린리더 우선순위 max.

### P6.6 단일 노출 원칙

- 한 화면에 단계 3 알림은 **1개만**. 동시 노출 시 가장 최근 1개만 표시, 나머지는 알림 센터에.
- 토스트는 동시 1개. 새 토스트 발생 시 이전 토스트는 250ms fade-out 후 새 토스트 진입.
- 인앱 카드(단계 2 warning)는 한 화면에 최대 3개 — 그 이상은 "알림 N개 더보기"로 묶음.

### P6.7 디덥(중복 제거)

- 같은 트리거가 5분 내 다시 발생하면 새 알림 생성하지 않고 기존 알림의 카운트만 갱신 ("미완료 케어 3건").
- 푸시는 OS 그룹화 활용 (iOS thread-id / Android channel).

### P6.8 알림 센터 (모바일 한정)

- 헤더 우측 `fluent:alert-24-filled` 탭 → 시간 역순 알림 리스트.
- 안 읽은 알림은 좌측 도트(`--color-accent`), 읽으면 사라짐.
- 단계 3 알림은 응답 전까지 알림 센터에 빨간 보더로 강조.
- 단계 1 알림은 7일 후 자동 삭제, 단계 2·3은 30일 보존.

## P7. 빈 상태 (Empty State) + 에러 화면

### P7.1 빈 상태

| 상황 | 카피 | 보조 액션 |
|---|---|---|
| 첫 진입 — 데이터 없음 | "아직 오늘의 기록이 없어요" | (없음. 시설이 입력해야 함) |
| 검색 결과 없음 | "검색 결과가 없어요" | "검색어를 다시 확인해보세요" |
| 권한 없음 | "이 정보는 의료진만 볼 수 있어요" | "보호자님께 공유 요청 보내기" |
| 신규 사용자 — 환자 미연동 | "어머님 정보를 먼저 연결해주세요" | "환자 연결하기" CTA |

### P7.2 에러 화면 4종 (v3.2.4 신설)

빈 상태와 달리 **시스템 문제**로 인한 화면. 동일 시각 구조(라인 일러스트 + 한 줄 카피 + 액션)지만 라이팅이 친근 ~요체, 시스템 메시지 금지.

| 상황 | HTTP/원인 | 카피 (제목) | 보조 메시지 | 액션 | 일러스트 |
|---|---|---|---|---|---|
| **네트워크 오류** | offline / fetch fail | "잠시 연결이 불안정해요" | "와이파이나 모바일 데이터를 확인해 주세요" | "다시 시도" | `wifi-disconnected` 라인 |
| **서버 오류** | 5xx | "지금은 잠깐 어려워요" | "잠시 후 다시 시도해 주세요. 문제가 계속되면 고객센터로 연락 주세요" | "다시 시도" + "고객센터" | `cloud-error` 라인 |
| **권한 만료 / 미인증** | 401 / 403 | "다시 로그인이 필요해요" | "보안을 위해 일정 시간 후 자동 로그아웃됐어요" | "다시 로그인" | `lock` 라인 |
| **타임아웃** | timeout | "응답이 늦어지고 있어요" | "잠깐 멈췄어요. 다시 시도하시거나 새로고침해 주세요" | "다시 시도" | `clock-pause` 라인 |

#### 공통 마크업

```html
<div class="error-state" role="alert">
  <svg class="illust-line" aria-hidden="true">...</svg>
  <h2 class="error-state__title">잠시 연결이 불안정해요</h2>
  <p class="error-state__hint">와이파이나 모바일 데이터를 확인해 주세요</p>
  <div class="error-state__actions">
    <button class="btn-primary">다시 시도</button>
    <button class="btn-secondary">고객센터</button>   <!-- 5xx 한정 -->
  </div>
</div>
```

#### 절대 규칙

- `<h2 role="alert">` + 스크린리더가 즉시 읽도록 `aria-live="assertive"`(네트워크/서버) 또는 `polite`(타임아웃)
- 라이팅: 시스템 메시지 금지 ("Error 500", "Network failure", "Timeout exceeded"). 시간·주체·해법 명시.
- 자동 재시도 시 **지수 백오프** (1s → 2s → 4s, 최대 3회). 동시에 "다시 시도" 버튼 손도 제공.
- 환자앱은 본문 18px·터치 56px 자동 상향 — 토큰이 처리.
- 다국어: 요양보호사앱은 중국어 폴백 카피 동시 표시 ("연결을 확인해 주세요 / 请检查网络连接")

## P8. 폼 검증 (Form Validation)

### P8.1 단일 에러

```
┌──────────────────────────┐
│ 이름                       │
│ ┌──────────────────────┐ │
│ │ [입력 필드, danger 보더] │ │
│ └──────────────────────┘ │
│ 이름을 입력해주세요          │ ← caption, danger 컬러
└──────────────────────────┘
```

- 인풋 보더 → `--color-danger`
- 헬퍼 텍스트 → `--text-caption`, danger
- 인풋 위 라벨은 그대로 유지

### P8.2 검증 시점

- **타이핑 중**: 검증하지 않는다 (입력 방해).
- **블러(focus 이탈) 시**: 검증 실행.
- **제출 시**: 모든 필드 검증, 첫 에러 필드로 포커스 자동 이동.

### P8.3 비동기 검증 (예: 중복 확인) — v3.2 확장

인풋 우측 끝에 16px 슬롯이 항상 예약된다. 상태에 따라 4가지 표시:

| 상태 | 표시 | 색 |
|---|---|---|
| 대기 (idle) | (빈 슬롯) | — |
| 검증 중 | 16px 회전 스피너 | `--color-accent` |
| 성공 | `fluent:checkmark-circle-16-filled` | `--color-success` |
| 실패 | `fluent:dismiss-circle-16-filled` | `--color-danger` |

```css
.input-wrapper {
  position: relative;
}
.input-wrapper .input {
  padding-right: 40px;  /* 우측 슬롯 공간 */
}
.input-validator {
  position: absolute;
  right: var(--space-4);
  top: 50%;
  transform: translateY(-50%);
  width: 16px;
  height: 16px;
  display: flex;
  align-items: center;
  justify-content: center;
}
.input-validator[data-state="loading"] iconify-icon {
  animation: spin 800ms linear infinite;
}
@keyframes spin { to { transform: rotate(360deg); } }
```

#### 디바운스

- 사용자가 타이핑을 **400ms 멈췄을 때** 비동기 호출 시작 (너무 빠르면 서버 부담, 너무 느리면 답답함).
- 호출 중에 새 입력이 들어오면 이전 호출은 abort (`AbortController`). 가장 마지막 결과만 반영.
- 모바일 셀룰러 환경 가정: 응답이 1.5초 이상 걸리면 스피너 옆에 "확인 중…" 캡션 표시.

#### 결과 메시지 위치

- 성공: 인풋 아래 헬퍼 텍스트 영역에 `--color-success` 메시지 ("사용 가능한 아이디예요").
- 실패: 동일 위치에 `--color-danger` 메시지 + 보더 색상도 함께 변경.
- 메시지 없이 아이콘만 표시하지 않는다 (스크린리더용 텍스트 필수).

### P8.4 다중 에러 (제출 시) — v3.2 신설

여러 필드가 동시에 에러 상태일 때의 패턴.

```
┌──────────────────────────────────┐
│  (!) 입력하신 정보 중 3가지 확인이│ ← card-alert--warning, 폼 상단
│  필요해요                          │
│                                  │
│  1. 이름을 입력해주세요             │ ← 클릭하면 해당 필드로 스크롤+포커스
│  2. 전화번호 형식이 맞지 않아요    │
│  3. 동의 항목을 확인해주세요        │
└──────────────────────────────────┘

[이름] [에러 보더 + 캡션]
[전화] [에러 보더 + 캡션]
...
```

#### P8.4.1 제출 흐름

1. 사용자가 [저장] 클릭 → 전체 필드 검증 (동기 + 비동기).
2. 에러가 1개 → 단일 에러 패턴(P8.1). 폼 상단 알림 카드 표시 안 함.
3. 에러가 2개 이상 → **폼 상단에 `card-alert--warning` 요약 카드** 추가.
4. 요약 카드의 각 항목은 클릭 가능 — 해당 필드로 부드러운 스크롤 + 포커스 자동 이동.
5. 모든 에러 필드에 보더 + 캡션 표시 (요약과 중복이지만 OK — 사용자가 어디서 시작했는지 알기 위함).

#### P8.4.2 라이팅

- 요약 카드 제목: "입력하신 정보 중 N가지 확인이 필요해요" (불안 자극 단어 "오류"·"실패" 금지).
- 각 항목: **필드명 없이 본 캡션 그대로** ("이름을 입력해주세요"). 사용자가 한 번에 어디인지 알 수 있게.
- "전체 실패" / "검증 실패" 같은 시스템 메시지 금지.

#### P8.4.3 접근성

- 요약 카드: `role="alert"` + `aria-live="assertive"` — 스크린리더가 즉시 읽음.
- 각 에러 필드: `aria-invalid="true"` + `aria-describedby="<에러 메시지 id>"`.
- 에러 메시지 ID는 필드 ID + `-error` 컨벤션 (예: `input-name-error`).
- 첫 에러 필드로 자동 포커스 이동 — 사용자가 Tab으로 헤매지 않게.

#### P8.4.4 격상 규칙

- 비동기 검증 결과까지 합쳐서 다중 에러가 되는 경우 → 모든 비동기 호출이 끝난 뒤 요약 카드 갱신.
- 사용자가 한 필드를 수정해서 에러가 해소되면 → 요약 카드의 해당 항목을 즉시 제거 (다른 항목은 유지).
- 모든 에러가 해소되면 → 요약 카드 fade-out + [저장] 버튼 활성화.

## P10. 로딩 / 스켈레톤 (v3.2 토큰화)

스피너보다 **스켈레톤**을 우선. 회색 블록이 실제 카드 형태를 미리 보여줘 layout shift를 막는다.

### P10.1 기본 스켈레톤

```css
.skeleton {
  background: linear-gradient(90deg,
    var(--skeleton-bg) 0%,
    var(--skeleton-shimmer) 50%,
    var(--skeleton-bg) 100%);
  background-size: 200% 100%;
  animation: skeleton-shimmer var(--skeleton-duration) infinite;
  border-radius: var(--skeleton-radius);
}
@keyframes skeleton-shimmer {
  0%   { background-position: 200% 0; }
  100% { background-position: -200% 0; }
}
```

### P10.2 변형 3종

| 변형 | 클래스 | 용도 |
|---|---|---|
| Line | `.skeleton--line` | 본문 1줄 자리 (`height: var(--skeleton-line-height)`) |
| Heading | `.skeleton--heading` | 헤딩 1줄 (`height: var(--skeleton-line-height-lg)`) |
| Row | `.skeleton--row` | 리스트 행 1개 (`height: var(--skeleton-row-height)`) |
| Card | `.skeleton--card` | 카드 1개 (`min-height: 120px`) |
| Avatar | `.skeleton--avatar` | 원형, `--size-avatar-md` |

```css
.skeleton--line    { height: var(--skeleton-line-height); border-radius: var(--radius-1); }
.skeleton--heading { height: var(--skeleton-line-height-lg); border-radius: var(--radius-1); width: 60%; }
.skeleton--row     { height: var(--skeleton-row-height); }
.skeleton--card    { min-height: 120px; padding: var(--card-padding); }
.skeleton--avatar  { width: var(--size-avatar-md); height: var(--size-avatar-md); border-radius: var(--radius-pill); }
```

### P10.3 카드별 스켈레톤 구성

| 실제 컴포넌트 | 스켈레톤 구성 |
|---|---|
| Stat Card | heading(40% width) + 큰 line(64px height) + line(50% width) |
| Timeline Row | avatar + line + line(70% width) |
| List Row | row 1개 (avatar + 본문 자리) |
| AI Output | mark(20px) + heading + line × 3 |

### P10.4 규칙

- 스켈레톤은 **실제 카드와 같은 라운드·간격**으로 자리잡는다 — 로딩 후 점프 없게.
- 짧은 작업(<300ms)은 스켈레톤 표시 안 함 — 깜빡임이 더 부담.
- 긴 작업(>3초)은 스켈레톤 + 하단에 "잠시만 기다려 주세요" 캡션.
- `prefers-reduced-motion: reduce`에서 shimmer 애니메이션 비활성, 정적 회색 블록만.

## P11. 채팅 / 메시지

```
┌────────────────────────────┐
│ [상대 메시지 카드, 왼쪽]    │ ← background: surface-glass, accent 텍스트 시간
│                            │
│           [내 메시지, 오른쪽]│ ← background: accent, on-accent 텍스트
│                            │
│ [상대 메시지]               │
└────────────────────────────┘
```

- 메시지 버블: `border-radius: 18px 18px 4px 18px` (꼬리 표현).
- 같은 화자 연속 메시지는 시간 라벨 합치기.
- AI 메시지는 좌측에 **하루안부 심볼**(`logo/brand-system/01_심볼단독.svg`, 24px) + accent 보더.
- 타입 인풋: pill radius, 우측 전송 버튼은 `fluent:send-24-filled`만 (라벨 없음).

## P12. 온보딩 (v13)

3슬라이드 + 역할 선택:

1. **소개**: "매일 안부를 묻습니다" — 마스코트 일러스트 + 슬로건
2. **가치**: "전화 없이 오늘 하루를 알아요" — 일상 vs 하루안부 비교
3. **시작**: "어떤 분이세요?" — 역할 선택 (보호자 / 의료진 / 요양보호사 / 환자)

역할 선택 전까지는 보호자 블루를 기본 테마로. 선택 후 즉시 해당 역할의 그라디언트로 트랜지션 (350ms fade).

## P13. 적응형 레이아웃

| 너비 | 레이아웃 |
|---|---|
| ≤ 414px (Phone) | 단일 컬럼, 탭바 16px 인셋 |
| 415–767px (Phablet) | 단일 컬럼, 일부 화면 2컬럼 카드 |
| 768–1023px (Tablet) | 모바일 앱은 중앙 정렬 + 양쪽 거터, 웹은 사이드바 축소 |
| 1024–1279px (Small desktop) | 사이드바 240px, 본문 가변 ~1280px |
| ≥ 1280px (Desktop) | 본문 1280px 고정, 여백 자동 |

모바일 앱(보호자/요양/환자/온보딩)은 PWA-first. 데스크톱에서 띄우면 phone 폭으로 중앙 정렬.

## P14. 어두운 시간대 (저녁 사용성)

하루안부의 핵심 사용 시간은 **저녁** — 보호자가 퇴근 후 AI 리포트를 확인하는 시간. 그럼에도 v3.2.3 정책상 **라이트 모드 단일 운영**(다크 봉인, FOUNDATIONS §13 참조). 저녁 가독성은 페이지 그라디언트 톤다운·고대비 모드(`data-a11y-contrast="high"`)로 보완한다.

## 확인 체크리스트 (새 페이지 만들 때)

- [ ] `<html data-role="..." data-platform="...">` 선언했는가
- [ ] sticky 헤더 사용 시 본문이 가려지지 않게 — flex column 또는 main에 `padding-top: var(--size-header)` (UX MAX Medium)
- [ ] 뒤로 버튼은 `history.back()` 사용 (location.replace 금지 — UX MAX High)
- [ ] 모달·시트·Side Panel은 ESC 키 닫기 지원 (가장 위 레이어부터)
- [ ] tokens.css만 import했는가 (다른 CSS 변수 정의 금지)
- [ ] 페이지 배경에 `--color-bg-role-gradient` 적용했는가
- [ ] 카드는 `card` (글래스) 기본인가
- [ ] 탭바 좌우 16px 인셋인가
- [ ] AI FAB은 탭바와 분리되어 있는가
- [ ] 모든 아이콘이 fluent filled인가, 이모지는 없는가
- [ ] 색·간격·라운드를 hex/px로 직접 적지 않았는가
- [ ] 환자 화면이면 18px 본문·56px 터치가 자동 적용되었는가
- [ ] 포커스 링이 보이는가 (`:focus-visible`)
- [ ] SOS는 닫기 없음, `role="alert"` + `aria-live="assertive"`인가
