# 하루안부 디자인 시스템 v3.0 개선 요청서

작성일: 2026.05.10  
대상: `07_디자인/preview.html`, `07_디자인/preview-foundations.html`, `07_디자인/preview-components.html`, `07_디자인/preview-patterns.html`, `07_디자인/preview-roles.html`, `07_디자인/tokens/tokens.css`

## 목적

현재 디자인 시스템은 구조와 방향성이 좋지만, 실제 앱에 적용했을 때 베리에이션이 다소 많고 시각 장식이 강해질 위험이 있다. 하루안부의 최우선 과제는 "깔끔함"이다. 따라서 이번 개선의 목표는 새로운 장식을 추가하는 것이 아니라, 기존 시스템을 더 조용하고 일관된 실제 서비스 UI로 다듬는 것이다.

핵심 방향은 다음과 같다.

- 역할별 개성보다 하나의 서비스처럼 보이는 통일감을 우선한다.
- 글래스, 그라디언트, 강한 색면, 그림자는 예외적으로만 사용한다.
- 컴포넌트 변형 수를 줄여 실제 구현자가 선택을 덜 하게 만든다.
- 환자 앱의 접근성 상향은 유지하되, 시각 자극은 줄인다.
- 디자인 시스템 문서 자체도 앱처럼 화려하기보다 운영 문서처럼 차분하게 정리한다.

## 현재 진단

### 1. "하나의 차체, 세 개의 테마" 원칙은 좋지만 색이 너무 전면에 있음

현재 시스템은 보호자 블루, 의료진 그린, 환자 오렌지가 큰 카드, 히어로, 배경, 탭바, FAB 등에 넓게 사용된다. 이 방식은 역할 구분은 명확하지만, 실제 사용자가 볼 때 하루안부라는 하나의 서비스보다 "파란 앱, 초록 앱, 주황 앱"처럼 느껴질 수 있다.

개선 방향:

- 역할색은 브랜드 전체를 바꾸는 색이 아니라 accent 색으로 사용한다.
- 큰 배경과 큰 카드 면은 중립색 중심으로 통일한다.
- 역할색은 버튼, 활성 탭, 작은 배지, 포커스 링, 일부 보조선에 제한한다.
- 각 역할 화면의 첫인상은 같은 제품군처럼 보여야 한다.

### 2. 그라디언트가 너무 많이 쓰일 가능성이 있음

현재 preview에서는 역할별 배경 그라디언트, 히어로 그라디언트, FAB 그라디언트, 카드형 그라디언트가 반복된다. 깔끔한 서비스 UI에서는 이 정도의 그라디언트가 쉽게 산만함으로 보인다.

개선 방향:

- 기본 화면 배경은 단색 또는 아주 약한 tint만 사용한다.
- 그라디언트는 온보딩, 주요 AI 리포트, 특별한 성공/완료 순간처럼 제한된 맥락에만 사용한다.
- 홈 화면 상단 카드도 매번 강한 그라디언트를 쓰지 말고, 기본은 흰 카드 또는 아주 약한 tint 카드로 둔다.
- FAB의 그라디언트도 단색 accent 또는 매우 은은한 2-stop으로 낮춘다.

### 3. 글래스모피즘을 기본값으로 두면 정보성이 약해짐

문서의 핵심 원칙에는 "글래스모피즘이 기본"이라고 되어 있다. 하지만 하루안부는 정보 확인, 돌봄 기록, 경보 판단이 중요한 서비스다. 글래스는 예쁘지만 텍스트 대비와 정보 밀도를 흐릴 수 있고, 화면 전체가 장식적으로 보일 수 있다.

개선 방향:

- 원칙을 `glass default`에서 `flat default, glass optional`로 변경한다.
- 기본 카드는 흰색 또는 명확한 surface 카드로 한다.
- 글래스는 플로팅 탭바, FAB 주변, 모달 오버레이, 특수 preview 데모에만 제한한다.
- 실제 앱의 정보 카드에는 blur를 기본 적용하지 않는다.

### 4. 카드 타입이 많아 실제 구현 일관성이 떨어질 수 있음

현재 카드 변형은 glass, flat, emphasis, hero, row 등으로 확장되어 있다. 카드 타입이 많으면 화면마다 선택이 달라지고, 앱 전체가 빨리 복잡해진다.

개선 방향:

카드 타입은 아래 4개로 축소한다.

1. `card-default`: 대부분의 정보 표시 카드
2. `card-action`: 클릭 가능한 카드
3. `card-alert`: SOS, 위험, 주의 등 상태 강조 카드
4. `card-hero`: 화면당 최대 1개만 허용되는 대표 카드

삭제 또는 축소할 항목:

- `card-glass`를 기본 카드로 쓰는 원칙
- `card-emphasis`의 과도한 남용
- 역할별로 완전히 다른 카드 배경을 가지는 방식

### 5. Radius 단계가 많고 일부가 너무 둥글다

현재 radius scale은 4, 8, 12, 14, 18, 24, 28, pill 등으로 충분히 넓다. 문서상으로는 체계적이지만 실제 앱에서는 카드마다 둥근 정도가 다르게 보여 정돈감이 약해질 수 있다.

개선 방향:

- 작은 요소: 8px
- 기본 버튼, 인풋, 카드: 12px 또는 14px 중 하나로 고정
- 큰 시트, 모달: 20px 또는 24px
- pill: 배지, 탭바, FAB, 칩처럼 형태가 명확한 경우만

권장:

- `--radius-card`와 `--radius-button`을 더 강하게 통일한다.
- preview에서 radius scale을 보여주더라도 실제 사용 권장값은 3단계 정도로 제한한다.

### 6. 의료진 그린과 success 그린이 충돌함

의료진 테마의 accent가 초록이고, success 상태도 초록이다. 의료진 화면에서는 "브랜드 강조"와 "정상 상태"가 같은 의미처럼 보일 수 있다.

개선 방향:

- 상태 색은 역할색과 독립적으로 의미를 가진다.
- 의료진 화면의 success는 브랜드 accent와 시각적으로 구분되도록 명도나 채도를 조정한다.
- success는 텍스트/배지/아이콘 위주로 쓰고, 브랜드 accent는 활성, CTA, 포커스에 제한한다.
- SOS/danger는 모든 역할에서 동일한 빨강을 유지한다. 이 방향은 좋다.

### 7. 환자 오렌지는 따뜻하지만 큰 면으로 쓰면 피로할 수 있음

환자 앱은 고령 사용자와 정서적 안정감이 중요하다. 오렌지는 따뜻하지만 큰 면적에 반복되면 자극적이고 장난감처럼 보일 수 있다.

개선 방향:

- 환자 앱의 큰 배경은 크림/오프화이트/밝은 회색 기반으로 둔다.
- 오렌지는 주요 버튼, 도움 요청, 활성 상태, 작은 배지에 제한한다.
- 환자용 접근성 상향은 유지한다.
  - 본문 18px
  - 주요 버튼 56px
  - 행 높이 64px
  - 카드 padding 증가
- 접근성 상향은 "더 큰 UI"이지 "더 강한 색"이 아니다.

### 8. 플로팅 필 탭바는 좋지만 tint를 줄여야 함

플로팅 필 탭바는 하루안부의 시그니처 UI로 유지할 가치가 있다. 다만 역할별로 탭바 배경색까지 강하게 바뀌면 하단이 장식처럼 보인다.

개선 방향:

- 탭바 배경은 모든 역할에서 거의 동일한 흰색 또는 반투명 흰색으로 통일한다.
- 활성 아이콘과 활성 라벨만 역할색을 사용한다.
- 비활성 아이콘은 중립 회색으로 유지한다.
- 탭바에는 강한 그림자보다 얕은 shadow와 border를 사용한다.

### 9. 버튼 위계를 더 엄격히 해야 함

현재 버튼 변형 자체는 필요하지만, 실제 화면에서 primary가 여러 개 나오면 정보 위계가 무너진다.

개선 방향:

- 한 화면에 primary 버튼은 원칙적으로 1개만 둔다.
- secondary는 구조적 보조 행동에만 쓴다.
- destructive는 삭제, SOS, 위험 조치에만 쓴다.
- ghost/text button은 "자세히 보기", "나중에", "건너뛰기" 같은 낮은 우선순위에 쓴다.
- FAB는 AI 진입점 또는 가장 중요한 반복 행동 하나에만 쓴다.

### 10. 디자인 시스템 preview 문서 자체도 더 차분해야 함

현재 `preview.html`은 DS 홈인데도 히어로, 역할 chip, 풍성한 카드, 그라디언트가 꽤 강하다. DS 문서는 실제 앱보다 더 조용해야 개발자와 디자이너가 규칙을 빠르게 읽을 수 있다.

개선 방향:

- `preview.html`의 hero 그라디언트를 제거하거나 매우 약하게 낮춘다.
- 문서 링크 카드는 더 단순하고 균일한 리스트/카드 형태로 정리한다.
- 역할 chip은 작은 보조 정보로 낮춘다.
- 시각화 페이지 카드는 같은 높이와 같은 밀도로 맞춘다.
- "예쁜 쇼케이스"보다 "정확한 운영 문서"에 가깝게 만든다.

## 구체 수정 요청

### A. 디자인 원칙 문구 수정

현재 원칙:

> 글래스모피즘이 기본

수정 요청:

> 기본 표면은 선명한 flat surface다. Glass는 플로팅 탭바, 오버레이, 특수 강조 상황에만 제한적으로 사용한다.

현재 원칙:

> 하나의 차체, 세 개의 테마

보완 요청:

> 역할색은 큰 배경을 바꾸는 테마색이 아니라, 행동과 상태의 accent로 제한한다. 모든 역할의 기본 표면과 정보 구조는 동일하게 유지한다.

### B. 토큰 정리 요청

`tokens.css`에서 다음 방향으로 토큰 의미를 정리한다.

- `--color-bg-canvas`: 모든 역할에서 거의 동일한 중립 배경 유지
- `--color-bg-role-gradient`: 실제 앱 기본값으로 쓰지 말고, 특수 hero 또는 preview 전용으로 격하
- `--color-bg-glass`: 기본 카드가 아니라 optional token으로 명시
- `--card-bg`: `var(--color-bg-surface)` 유지
- `--card-shadow`: 더 약하게 유지
- `--card-shadow-glass`: 실제 앱 기본값에서 제외
- `--tabbar-bg`: 역할별 tint보다 공통 white/translucent 계열 우선

### C. 컴포넌트 문서 정리 요청

`preview-components.html`에서 컴포넌트 변형을 줄인다.

버튼:

- primary
- secondary
- destructive
- ghost/text
- FAB

카드:

- default
- action
- alert
- hero

탭바:

- 공통 surface
- 활성 상태만 role accent

badge/status:

- 상태 색은 role accent와 독립
- success/warning/danger/info를 명확히 구분

### D. 패턴 문서 정리 요청

`preview-patterns.html`에서 실제 앱 목업은 다음 기준을 따른다.

- 홈 화면 상단의 큰 컬러 hero는 화면당 1개 이하
- 기본 정보 카드는 흰색 surface
- glass card 반복 사용 금지
- 환자 화면은 큰 글자와 여유 있는 터치 영역으로 구분하고, 큰 오렌지 면은 최소화
- 의료진 화면은 정보 밀도를 유지하되 색면을 줄이고 표/리스트 가독성을 우선
- 보호자 화면은 감성적 문구보다 안심 상태, 최근 변화, 다음 행동이 먼저 보이게 정리

### E. 역할 비교 문서 정리 요청

`preview-roles.html`은 역할 차이를 보여주는 문서이므로 색 비교 자체는 필요하다. 다만 "차이"보다 "동일한 구조"가 더 먼저 보이게 바꾼다.

수정 방향:

- 역할별 큰 원색 카드보다 같은 레이아웃의 미니 화면 비교를 먼저 보여준다.
- 색상 표는 하단으로 내리거나 더 작게 둔다.
- "색만 다름"이 아니라 "구조는 동일, 접근성만 환자에서 상향"이라는 메시지를 강화한다.
- caregiver는 의료진 색을 공유하지만 모바일 현장용이라는 차이를 명확히 하되, 별도 브랜드처럼 보이지 않게 한다.

## 우선순위

### 1순위: 실제 앱의 깔끔함을 해치는 요소 제거

- 큰 역할별 그라디언트 줄이기
- glass 기본값 철회
- 카드 타입 축소
- 탭바 tint 약화

### 2순위: 토큰 의미 정리

- role accent와 status color 분리
- card token을 flat default로 재정의
- role gradient를 특수 용도로 격하
- radius 권장값을 단순화

### 3순위: preview 문서 정돈

- DS 홈을 조용한 문서형 화면으로 수정
- Foundations는 원칙 중심으로 정리
- Components는 선택지를 줄여 명확히 제시
- Patterns는 실제 앱 기준으로 더 현실적인 화면을 보여줌
- Roles는 통일감 우선으로 재배치

## 완료 기준

수정 후 결과가 아래 기준을 만족해야 한다.

- 첫 화면을 봤을 때 "세 앱"보다 "하루안부 하나의 제품군"으로 느껴진다.
- 큰 컬러 면과 그라디언트가 눈에 먼저 들어오지 않는다.
- 카드 기본형이 명확하고, 화면마다 다른 카드 스타일을 고를 필요가 없다.
- 환자 화면은 커지고 쉬워졌지만 과하게 주황색이 아니다.
- 의료진 화면에서 green accent와 success 상태가 혼동되지 않는다.
- 탭바는 시그니처로 남되 과하게 장식적이지 않다.
- preview 문서가 예쁜 쇼케이스보다 실무 가이드처럼 읽힌다.

## 핵심 한 줄

현재 디자인 시스템은 "예쁜 베리에이션 모음"에 가깝다. 더 좋은 서비스가 되려면 "조용한 기본값 + 필요한 순간의 강조"로 바뀌어야 한다.
