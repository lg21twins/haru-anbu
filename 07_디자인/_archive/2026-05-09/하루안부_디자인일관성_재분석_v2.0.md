## CRITICAL — 디자인 시스템 자체가 작동하지 않는 영역

### C1. common.css와 HTML이 서로 다른 토큰 체계, 그리고 HTML은 common.css를 import조차 하지 않음

근거:
- `v9_보호자앱/common.css`는 `--guardian / --nurse / --patient` (역할 기반)
- `v9_보호자앱/g-*.html`은 모두 자체 `:root{}` 안에 `--blue / --green-d / --amber` (색상 기반)
- HTML 5개 검증 결과 — 누구도 `<link rel="stylesheet" href="common.css">` 또는 `@import 'common.css'` 사용하지 않음

영향: common.css는 사실상 **데드코드**. 디자인 토큰 시스템이 존재하지 않는 것과 같다. 토큰을 한 군데서 바꿔도 화면에 반영되지 않는다.

### C2. 3개 디자인 문서가 서로 다른 토큰 명명을 권장

| 문서 | 보호자 | 의료진 | 환자 |
|------|--------|--------|------|
| 브랜드아이덴티티 v2.0 | `--guardian` | `--medical` (또는 --nurse) | `--patient` |
| 디자인시스템 v2.0 | `--blue` / `--blue-l` / `--blue-d` | `--green-d` | `--amber` |
| common.css | `--guardian` | `--nurse` (단일) | `--patient` |
| 실제 HTML | `--blue` | `--green-d` | `--amber` |

영향: 어느 문서를 봐도 "정답"이 다르다. 새 개발자가 합류하면 어떤 토큰을 써야 할지 결정할 수 없다.

### C3. 탭바 스펙 3중 모순

| 출처 | 탭바 높이 | 배경 | backdrop-filter |
|------|----------|------|----------------|
| 디자인시스템 v2.0 문서 | **56px** floating pill | `rgba(210,225,250,.55)` | `blur(20px)` |
| common.css `--tabbar-height` 토큰 | 50px | — | — |
| common.css `.tabbar` 클래스 (실제 코드) | **68px** | `#ffffff` (불투명) | `none` |

영향: 디자인 시스템이 약속한 "글래스모피즘 플로팅 필탭"이 실제 코드에는 어디에도 없다. 토큰조차 자기 자신과 모순.

### C4. common.css에 옛 컬러·옛 명칭 잔존

```css
/* common.css 줄 19, 34, 40 */
--guardian-light: #D9F0F7;   /* ← v2.0은 #DBEAFE */
--info:           #0891B2;   /* ← v2.0은 #2C7AFC */

/* common.css 헤더 (줄 5) */
Version: 1.0 | 2026.04.02
/* 바로 아래 줄 17의 주석은 "컬러 시스템 v2.0" — 자기 모순 */
```

영향: v6.0 정렬 작업이 common.css까지 도달하지 못함.

## HIGH — 토큰 시스템의 신뢰성을 떨어뜨리는 영역

### H1. 시멘틱 배경 토큰을 정의해놓고 정작 컴포넌트는 하드코딩 사용

```css
/* 정의 */
--bg-success: #D1FAE5;
--bg-warning: #FEF3C7;
--bg-critical: #FEE2E2;
--bg-info:    #D9F0F7;

/* 그러나 실제 사용 (.badge / .card-alert) */
.badge--success  { background: #E8F8ED; }   /* 정의값과 다름 */
.badge--warning  { background: #FFF3E0; color: #E65100; }
.badge--critical { background: #FFEBEE; }
.badge--info     { background: #E8F0FE; }
.card-alert--info     { background: #E8F0FE; }
.card-alert--success  { background: #E8F8ED; }
.card-alert--warning  { background: #FFF3E0; }
.card-alert--critical { background: #FFEBEE; }
```

영향: 시멘틱 컬러를 한 곳에서 관리할 수 없다. 4개 토큰 + 8개 클래스 = 12군데를 별도로 바꿔야 한 가지 색이 바뀐다.

### H2. 의료진·환자·요양보호사 앱은 v9 표준 미적용

| 역할 | 최신 mockup | 일자 | 컬러 시스템 | 비고 |
|------|------------|------|-----------|------|
| 보호자 | `v9_보호자앱/` | 2026-04 | `--blue/--green-d/--amber` | v9 표준 |
| 간호사 | `mockup/v4_최신/nurse.html` | 2026-03-23 | `--primary:#059669`, `--accent:#0891B2`, `--text:#0F172A`, `--border:#E2E8F0`, `--r/--rs/--rx` | 한 달 전, 옛 스카이블루 액센트 잔존 |
| 환자 | `mockup/v4_최신/patient.html` | 2026-03-23 | `--primary:#B45309` (다크브라운), `--bg:#FAF5F0` (베이지) | **v6.0 환자 컬러 #FB923C와 정면충돌** |

영향: 한 서비스의 4개 역할 화면이 서로 다른 시대·다른 디자인 언어로 만들어져 있다. 환자 앱은 컬러 자체가 v6.0과 어긋난다.

### H3. common.css에 의료진(통합)/요양보호사 셀렉터 부재

```css
/* 현재 정의된 셀렉터 — 보호자/간호사/환자만 */
[data-role="guardian"] { … }
[data-role="nurse"]    { … }
[data-role="patient"]  { … }
```

통합기획서 v6.0이 의료진을 단일군(의사·간호사·요양보호사 공통)으로 결정했음에도, 셀렉터는 `nurse` 단일 명칭으로만 존재. `[data-role="medical"]`, `[data-role="caregiver"]`, `[data-role="doctor"]` 모두 없음.

### H4. 각 HTML이 자체 :root에 임의 토큰 추가

| 파일 | 추가 토큰 | 용도 불명 |
|------|---------|---------|
| g-guardian-live.html | `--blue/--blue-l/--blue-d --green/--green-d --amber --red --t1/--t2/--t3 --font` | 베이스 |

영향: 화면별로 토큰이 늘어나기만 하고 **공통 기준으로 회수되지 않음**. "디자인 시스템"이라기보다 "각자 만든 컴포넌트의 모음".
