## 1. 핵심 전략 — "임팩트 ≠ 장식, 임팩트 = 정보 시각화"

리뷰어는 "색 줄이고 덜어내라"(60/30/10), 우리는 "더 재밌게". **안 부딪힘.**
재미를 **색·박스·그라데이션(장식)** 이 아니라 **데이터의 모양(정보 시각화)** 에서 뽑으면
우리 금지룰(그라데이션·스트로크·배경컬러레일 X, flat-first)과도 안 싸우고 심사에서도 더 세련돼 보인다.

프리미엄 레퍼런스(WHOOP·Oura·Apple Fitness·Timepage·Any Distance)의 공통 DNA = 아래 6원칙.

## 2. 통일성 DNA (6원칙) — 6개 화면 공통 적용

1. **화면당 히어로 1개** — 큰 숫자(WHOOP)·큰 사진(Any Distance)·큰 링(Apple)·큰 타임라인. 나머지는 조용히.
2. **에디토리얼 헤더** — 날짜/인사를 크고 굵게(Timepage `WEDNESDAY 16 AUGUST`, GoodRx `Hello, Sam`). 굵기 대비가 곧 재미.
3. **연회색 스캐폴딩** — 구조를 박스가 아니라 고스팅된 회색으로(Timepage 빈 시간대). `--color-border-subtle`·`--color-bg-surface-muted`.
4. **데이터 주얼리** — 스파크라인·링·노드·도트를 **단색(앱 accent)** 으로 작게. 색이 아니라 모양이 임팩트.
5. **상태 = 채움/명도** — 원형 체크·진행 카운터·노드 상태(Tiimo `0/8`, Afterpay 채움/링/연한 dot). 색 의존 최소.
6. **넉넉한 여백** — 전부 숨 쉰다. 카드 내부 패딩 크게(`--space-6~8`).

**우리 룰과의 화해**: 레퍼는 링에 색·헤더에 그라데이션을 쓰지만 **우린 구조만 가져오고 색은 안 가져온다.**
링/스파크라인 = 앱 accent 단색, 그라데이션·스트로크 X, **사진 모먼트만 컬러 리치**.
→ 6개 화면이 하나의 시스템으로 묶이되 히어로가 달라 안 지루하다.

## 4. 재사용 컴포넌트 킷 (7종 — 6개 화면을 하나로 묶는 부품)

1. **타임라인 노드** — 세로선 + dot(완료=채움 / 진행=링 / 예정=연한). 좌측 시간 라벨. `--color-accent` 단색.
2. **진행 카운터** — "6/10" 대형 + 얇은 진행 바 or 링. 상단 고정.
3. **스탯카드** — 라벨(작은 회색) + 큰 숫자 + 미니 스파크라인/추세 화살표 + "avg". Oura형.
4. **스파크라인 행** — 이름 + 인라인 미니 라인 + 값 + 등락. 리스트 트리아지.
5. **모먼트 카드** — 풀블리드 사진 + 캡션 + 반응. 유일 컬러 리치 존.
6. **대형 액션 버튼** — 시니어용 ≥56px, `--font-18~20`, `--radius-5`.
7. **동의 토글 행** — 라벨 + 배지(별도동의) + 펼침 상세 + 토글.

→ 이 7종을 `07_디자인/system/`의 공통 CSS로 만들면 6개 화면이 자동으로 통일된다.

## 5. 색·타이포·여백 스펙 (토큰 매핑) — 리뷰어 60/30/10 반영

**60 / 30 / 10 비율 (리뷰어 권고):**
- **60% 그레이스케일** = 면·구조·보조 텍스트. `--color-bg-canvas`(gray-150) · `--color-bg-surface`(white) · `--color-bg-surface-muted`(gray-50) · `--color-text-secondary`(gray-500) · `--color-text-tertiary`(gray-400) · `--color-border-subtle`(gray-200).
- **30% 포인트 = 앱별 accent 단색, 주로 데이터 시각화에만** — 보호자 `--brand-blue-500 #2C7AFC` / 의료진 `--color-success #15803D`(green) / 환자 `--brand-orange-400 #FB923C`. 링·스파크라인·노드·활성 상태에 한정, 배경 필 금지.
- **10% 다크 강조** = 히어로 타이포. `--color-text-primary`(gray-900) 큰 숫자·큰 제목.
- 색을 여러 개 쓰더라도 **opacity로 위계**(리뷰어): `rgba(var(--color-accent-rgb), .12)` 식.

**타이포 위계 (굵기+명도로):**
- 히어로 숫자/제목: `--font-28~40` `--weight-bold`
- 섹션 제목: `--font-20~22` `--weight-semibold`
- 본문: `--font-16~17` `--weight-regular`
- 라벨/보조: `--font-13~14` `--weight-medium` + `--color-text-secondary/tertiary`
- **리뷰어 지적**: 포폴에 작게 배치돼도 읽히게 전반적으로 **키우기**. 작은 연한 텍스트·가운뎃점(AI슬롭 느낌) 지양.

**면·깊이 (flat-first, v3.1):**
- 카드 `--card-border: 0` (스트로크 X, 리뷰어). 깊이는 `--shadow-hairline`/`--shadow-card-borderless`만, 과한 섀도우 X.
- 간격: `--space-5(16) ~ --space-8(32)`. 카드 내부 여백 넉넉히.
- 라운드: 카드 `--radius-3~5`, 버튼 `--radius-5`, pill `--radius-full`.

**금지 재확인**: 그라데이션(linear/radial) 전면 X · italic X · 이모지 X(iconify `fluent:*`) · 위계용 배경컬러 필/좌측 레일 X · 인라인 스타일/생hex X.

## 6. 안전·법 카피 패턴 (SaMD 회피) — 레퍼에서 확인된 실사용 문구

앱이 **자동 진단·판정**하면 의료기기(SaMD) 리스크. 레퍼들도 disclaimer로 회피:
- Runna: "전문 의료 지원을 대체하지 않습니다. 구체적 의학적 조언은 의료 전문가와 상담하세요."
- Amazon Health AI: "응급이면 즉시 119(911)."
- Ahead: "당신의 데이터는 100% 비공개."

**우리 적용 규칙**:
- 수치·추세는 **보여주되 판정 문구 없이** ("혈압이 평소보다 높게 측정됨" O / "혈압 이상 감지" X — g06-alert 이미 반영).
- 임상 판단은 항상 **사람(간호사·의료진)에게 귀속** (리포트 편집 before/after가 이걸 시각화).
- AI 대화/리포트 화면 하단에 **프라이버시·비대체 고지** 상시.

## 7. HTML 베리에이션 제작 우선순위

1. **요양 일정표** (사용자 최우선 예시) — 타임라인+진행 카운터 2~3안. → 방향 확정용.
2. **보호자 AI 일일 리포트** — 지표 트리오+AI 문단+모먼트.
3. **의료진 환자 리스트/추세** — 스파크라인 행 + before/after 편집.
4. 환자 본인앱 · 모먼트 · AI 대화 · 동의는 위 3개로 시스템 확정 후 파생.

→ 확정되면 컴포넌트 킷(§4)을 `07_디자인/system/` 공통 CSS로 승격 → Figma 이관.
