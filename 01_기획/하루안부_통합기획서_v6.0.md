## 1. 왜 만드는가 — 문제 정의와 JTBD

### 1.1 핵심 문제

요양시설에 가족을 맡긴 한국의 보호자는 지금도 **오늘 엄마가 밥을 드셨는지조차 실시간으로 알 수 없다**. 시장 상황을 보면 이 문제는 점점 더 커진다.

| 지표 | 수치 | 출처 시점 |
|---|---|---|
| 65세 이상 인구 | 1,024만 명 (20.0%) | 2024 |
| 장기요양 이용자 | 110만 명 → 145만 명 전망 | 2023 → 2027 |
| 요양원 수 | 전국 4,640개소 | 2024 |
| 면회 제한 규정 운영 시설 비율 | 68% | 2024 |
| 보호자 심각한 스트레스 경험률 | 36.0% → 46.3% | 2022 → 2024 |

그런데도 **보호자·의료진·환자 3자를 실시간으로 연결하는 플랫폼은 국내에 없다**. 기존 대안은 모두 부분 해결에 그친다 — 요양원 전화는 연결률 60% 수준, 카카오톡 단톡방은 공지 일방향, 면회는 월 1회. 매칭 서비스(케어닥·케어네이션 등)는 입소 전까지만 다룬다.

### 1.2 3자 페인포인트

**보호자** — 불안·죄책감·정보 단절
- 요양원 전화 연결률 60%, 비용 구조 복잡, 처방전/진료 정보 접근 불가
- "오늘 엄마가 밥은 드셨는지조차 알 수 없다"
- 인터넷에서 치매 정보를 검색하지만 출처 불명·부정확

**의료진·요양보호사** — 과부하·이중 기록
- 보호자 전화 응대에 하루 2시간+ 소비 ("하루에 보호자 전화 10통, 비슷한 질문 반복")
- 수기 기록과 전산 기록의 이중 부담, 구두 인수인계로 초과근무
- 외국인 요양보호사 소통 어려움

**환자** — 고립감
- 가족과의 디지털 소통 수단이 사실상 없음
- 스마트폰 사용 어려움, 도움 요청이 어려움, 하루가 무료함
- "딸이 전화는 안 하고, 오늘 뭐 하는지만이라도 알고 싶어"

## 4. 고객 여정 시나리오

### 4.1 As-Is vs To-Be 감정 곡선 (보호자 기준)

| 스테이지 | As-Is 감정 | To-Be 감정 | 개선폭 |
|---|---|---|---|
| 입소 결정 | 2/5 (불안·죄책감) | 3.5/5 (안도·정보 확보) | +1.5 |
| **일상** (출근/퇴근) | 2.5/5 (걱정·답답) | **4/5** (안심·연결감) | **+1.5** |
| 궁금할 때 | 2/5 (불안·혼란) | 3.5/5 (안정·위로) | +1.5 |
| 긴급 상황 | 1/5 (공포·분노) | 3/5 (긴장하되 통제감) | **+2** |
| 비용·행정 | 2/5 (부담·피로) | 3.5/5 (파악 완료) | +1.5 |

### 4.2 스테이지별 개선 핵심

**Stage 1 — 입소 결정**
AI 케어가이드 '요양원 찾기' 모드로 조건별 검색 + '비용 계산기'로 시뮬레이션. 비교 기준·비용 불확실성 해소.

**Stage 2 — 일상 (가장 빈번·가장 큰 개선)**
출근길 대시보드로 상태 확인 → 저녁 AI 일일 리포트 수신 → 필요 시 채팅. 전화 자체가 불필요해진다.

**Stage 3 — 궁금할 때**
AI 케어가이드 '질병 백과' + '감정 지원' 모드로 신뢰 가능한 단일 정보 창구 확보.

**Stage 4 — 긴급 상황**
SOS 실시간 알림(30초 이내) → 상세 정보 확인 → 앱 내 의료진 소통 → 처방전·의료기록 확인. 정보 공유가 공포를 "통제 가능한 긴장"으로 바꾼다.

**Stage 5 — 비용·행정**
AI 케어가이드 '비용 계산기' + '돌봄 제도' 모드. 등급·감경·비급여 복합 조건 시뮬레이션.

### 4.3 핵심 인사이트

1. 가장 빈번한 여정(일상)에서 가장 큰 감정 개선 효과 발생 → **대시보드 + AI 리포트가 서비스 핵심**.
2. 극단 감정(긴급)에서 +2점 개선 → SOS 통합이 브랜드 약속의 반석.
3. 정보 불안 해소는 "단일 신뢰 창구" 제공으로 달성 → AI 케어가이드 5모드의 존재 이유.

| 주의 | 주황 | "촉탁의 상담 권장 — 근거: 혈압 상승 추세 3일" |
| 위험 | 빨강 + 알림 | "즉시 이송 권장 — 근거: 수축기혈압 180+ 2회 연속" |

야간 모드에서는 알림 민감도 상향(경과관찰부터 팝업). 과거 유사 패턴과 비교 ("지난달 비슷한 추이 후 입원 이력 있음").

#### 5.3.4 핵심 기능 — eMAR (전자 투약 기록)

체크리스트에서 분리된 독립 화면. **투약 오류 방지가 핵심**. 시간대별 투약 매트릭스 + 색상 코딩.

#### 5.3.5 핵심 기능 — SBAR 인수인계

교대 시점에 AI가 자동 생성: Situation / Background / Assessment / Recommendation 4영역. 수동 특이사항 메모 추가, 교대별 이력 조회.

#### 5.3.6 의사·간호사 사용 패턴 차이

| 영역 | 간호사 | 의사(촉탁) |
|---|---|---|
| 주 진입점 | 대시보드 → 체크리스트 | 환자 관리 → 타임라인 |
| 주 기능 | eMAR / SOS 발송 / 보호자 채팅 / 스케줄 / 인수인계 | 처방전 입력·관리 / 진료기록 입력 / 의료 타임라인 / SOS 응답 |
| 커뮤니케이션 | 보호자 + 요양보호사 + 촉탁의 모두 | 간호사 보고 회신 위주 |

### 5.4 요양보호사 앱 *[IA v1.0 — 2026-04-16 기준]*

> 출처: `03_설계/요양보호사앱_정보구조도_v1.0.docx`. 의사·간호사 앱과 분리된 모바일 전용 프로덕트. 원래 "의료진" 단일 역할로 묶여 있던 것을 v6.0에서 분리. **의료진 카테고리 내의 독립 역할**(보호자 앱에 흡수되지 않음)이며, 컬러는 의료진 공통 `#22C55E`를 사용. v6.1에서 IA v1.0의 4탭 구조로 정정.

#### 5.4.1 설계 근거 — 왜 의료진에서 분리하는가

| 항목 | 의사·간호사 | 요양보호사 |
|---|---|---|
| 핵심 진입점 | 체크리스트·처방 입력 | **출퇴근 → 케어 일지** |
| 가장 빈번한 작업 | 처방·진료기록 입력 | **ADL 케어 기록** (식사/투약/위생/배변/활동) |
| 자격 기반 | 의료 면허 | 요양보호사 1급/2급 자격 |
| 업무 플랫폼 | PC 웹 중심 | 현장 모바일 중심 |
| 커뮤니케이션 | 보호자·의료진 채팅 | 보호자 + **센터 관리자 분리** |
| 누락 기능 | — | 출퇴근 전자서명, 서비스 제공기록지, 급여 청구 연동 |

하나의 "의료진" 역할로 묶으면 두 사용자 모두 불편하다. 업무 플로우가 근본적으로 다르기 때문.

#### 5.4.2 하루 업무 플로우 (As-Is)

```
출근 (이동 중)
  │

  │

  │

  ├── 신체활동 지원 (식사, 배변, 목욕, 이동 보조)
  ├── 가사활동 지원 (청소, 세탁, 조리)
  └── 인지활동 지원 (대화, 활동 프로그램)
```

#### 5.4.3 IA — 4탭 + 플로팅 SOS *(IA v1.0 정정)*

```
┌─ SOS 수신 배너 (긴급 시만 노출) ─────────────────────┐
│                                                      │
│                메인 콘텐츠                            │
│                                       ╔═══╗          │
│                                       ║SOS║ (플로팅) │
│                                       ╚═══╝          │
├────────── 탭바 (4탭 floating pill) ──────────────────┤
│  🏠 홈   ✏️ 체크리스트   💬 소통   👤 마이         │
└──────────────────────────────────────────────────────┘
```

**탭 1 — 홈 (업무 현황)**
- 인사말 + 근무 정보: "김미영님, 오늘 주간 근무" + 시간대 표시
- 오늘 케어 진행률 바 (예: 12/18 완료, 67%)
- 주의 환자 알림 배지
- **지금 해야 할 일 타임라인** (현재 시각 기준 가장 가까운 업무 2~3개) — 상단 영역 바로 아래
- 담당 환자 카드 리스트 (이름·방번호·진행률·다음 할 일·주의 표시)

**탭 2 — 체크리스트** *(가장 빈번한 화면)*
- 환자 선택 가로 스크롤 (담당 환자 프로필 칩)
- 시간대 세그먼트 (아침 / 오후 / 야간)
- 카테고리별 체크 섹션 (아코디언) — 투약 / 식사 / 위생 / 활동 / 바이탈
- 특이사항 입력 (텍스트 + 사진 + "간호사에게 보고" 토글)
- 8단계 스텝퍼 상세는 §5.4.4 참조
- 입력된 데이터는 **3초 이내 보호자 앱 일일 리포트로 실시간 반영**

**탭 3 — 소통**
- 세그먼트: 대화 / 알림
- 대화: 간호사 + 보호자 채팅방 통합, **빠른 보고 버튼** 상단(환자+사진+한줄 메모로 간호사에게 즉시 전송)
- 알림: AI 요약 카드 피드 + AI 인수인계 요약(읽기 전용)
- 중요도별 색상 구분 (긴급=빨강 / 일반=초록 / 참고=회색)

**탭 4 — 마이페이지**
- 프로필 카드 (이름·소속 요양원·담당 환자 수·자격 정보)
- 근무 스케줄 (주간/야간/휴무 캘린더, 다음 근무 미리보기)
- 알림 설정 (SOS·업무 리마인더·보호자 메시지)
- 앱 설정·고객센터·로그아웃

**플로팅 SOS**: 탭바 우측 상단 고정(보호자 앱 AI FAB와 동일 위치). 길게 누르면 발신(2초) — 오터치 방지. 환자 빠른 선택 → 상황 유형(낙상/의식저하/호흡곤란/기타) → 사진 + 한줄 메모 → 간호사 + 보호자 동시 FCM 푸시.

**SOS 수신 배너**: 다른 직원의 SOS 수신 시 모든 화면 최상단 빨간 배너. 탭하면 해당 환자 상황 + 대응 타임라인.

#### 5.4.4 8단계 케어 기록 스텝퍼

한 화면에 한 항목씩 입력. 현장에서 한 손으로 빠르게 기록 가능하도록 슬라이더·체크박스·스텝퍼 중심.

| Step | 항목 | 입력 방식 |
|---|---|---|
| 1 | 바이탈 | 혈압·체온·맥박·혈당(당뇨 수급자) — 숫자 패드 |
| 2 | 식사 | 식사량(%) 슬라이더, 형태(일반/연식/유동식), 수분량, 기호도 |
| 3 | 투약 | 약 목록 체크 + 거부 메모 |
| 4 | 위생 | 체크박스 — 구강/세수/세발/목욕/손발 |
| 5 | 활동 | 보행보조, 체위변경, 프로그램 참여 |
| 6 | 배변 | 대변 횟수·형태, 소변 횟수·색상, 실금, 기저귀 교체 |
| 7 | 인지/정서 | 상태 선택 + 음성메모 (대화 내용 요약) |
| 8 | 특이사항 | 사진 첨부, 인수인계 메모 (낙상·피부 이상·구토·발열·행동 변화) |

#### 5.4.5 핵심 사용자 플로우

```

→ [출근하기] 탭 (시간·GPS 기록 + 수급자/가족 서명 옵션)

```

**② 긴급 상황 플로우 (SOS)**

```

→ SOS 타임라인 기록 (발송·확인·대응 완료 시각)
→ 케어 일지 특이사항 자동 반영
```

**③ 월말 급여 청구 플로우**

```
케어 기록 탭 → 서비스 제공기록지 진입

```

#### 5.4.8 DB 스키마 확장

기존 `care_records` 테이블 외에 요양보호사 앱용으로 신규 생성해야 할 테이블.

```sql
-- 바이탈 기록 (신규)
CREATE TABLE vitals (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id UUID NOT NULL REFERENCES patients(id),
  staff_id UUID REFERENCES users(id),
  blood_pressure_systolic INTEGER,
  blood_pressure_diastolic INTEGER,
  temperature DECIMAL(4,1),
  pulse INTEGER,
  blood_sugar INTEGER,
  measured_at TIMESTAMPTZ DEFAULT now()
);

-- 출퇴근 기록 (신규)
CREATE TABLE attendance (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  staff_id UUID NOT NULL REFERENCES users(id),
  patient_id UUID NOT NULL REFERENCES patients(id),
  check_in TIMESTAMPTZ,
  check_out TIMESTAMPTZ,
  check_in_gps POINT,
  check_out_gps POINT,
  signature_url TEXT,  -- 수급자/보호자 전자서명
  service_minutes INTEGER GENERATED ALWAYS AS (
    EXTRACT(EPOCH FROM (check_out - check_in)) / 60
  ) STORED
);

-- 인수인계 메모 (신규)
CREATE TABLE handover_notes (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id UUID NOT NULL REFERENCES patients(id),
  from_staff_id UUID REFERENCES users(id),
  content TEXT,
  voice_url TEXT,
  care_date DATE DEFAULT CURRENT_DATE,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

### 5.5 환자 태블릿 *[IA v1.0 — 2026-04-16 · 단일화면 AI 말벗]*

> 출처: `03_설계/환자태블릿_정보구조도_v1.0.docx`. 요양원에 계신 어르신이 직접 사용하는 태블릿(10~11인치). 스마트 기기에 익숙하지 않은 사용자를 위해 **화면 수를 극도로 최소화**하고, **AI 말벗 대화를 중심으로 모든 기능을 통합**. v6.1에서 기존 "3탭 구조" 폐기 → 단일화면 컨셉으로 전면 재설계.

#### 5.5.1 핵심 컨셉 — 왜 단일화면인가

요양원 어르신들의 가장 큰 문제는 **외로움과 소외감**이다. 가족이 매일 방문할 수 없고, 다른 입소자와의 소통도 제한적인 환경에서 AI 말벗이 정서적 연결과 실용적 정보 전달을 동시에 담당한다.

**설계 원칙**
- 탭바·메뉴·페이지 이동 **없음** — 대화 하나로 모든 기능 통합
- 24pt+ 큰 글씨, 큰 버튼, 높은 콘트라스트
- 음성 입력 우선, 터치 보조
- AI가 능동적으로 먼저 말을 거는 구조 (사용자 주도가 아닌 **AI 주도**)
- 컬러: Orange `#FB923C` (따뜻한 느낌)

#### 5.5.2 두 가지 상태 — 별도 페이지 이동 없음

| 상태 | 화면 구성 | 전환 조건 |
|---|---|---|
| **대기 모드** | 디지털 액자 — 가족 사진 슬라이드쇼 + 시계 + 날씨 + 도움 버튼 | 일정 시간 무응답 시 대화 → 대기 자동 전환 |
| **대화 모드** | AI 말벗 대화 + 인라인 카드(사진/일정) + 입력 영역 + 도움 버튼 | 화면 터치 또는 AI 알림 시 대기 → 대화 |

**상시 고정 요소** (두 모드 공통)
- 상단 정보 바: 좌측 큰 시계+날짜+요일 / 우측 날씨+기온
- **도움 요청 버튼**: 하단 우측, 크고 빨간 원형, 항상 보임 — 어떤 상황에서든 한 번에 접근

#### 5.5.3 대기 모드 (디지털 액자)

- 보호자 앱에서 보낸 가족 사진들이 큰 화면으로 자동 전환 (10초 간격)
- 사진 위에 시계 + 날씨 오버레이
- 화면 아무 곳 터치 → 대화 모드로 전환
- AI가 알림이 있을 때(일정, 가족 새 메시지) 자동으로 대화 모드 전환

#### 5.5.4 대화 모드 (AI 말벗) — 앱의 핵심

**대화 영역 (화면의 80%)**
- 큰 글씨 말풍선 (24pt+)
- AI 메시지: 좌측 정렬, 따뜻한 색상 배경 / 어르신 응답: 우측 정렬
- 대화 중 **인라인 카드**로 사진/일정/콘텐츠 표시 (별도 화면 이동 없음)

**입력 영역 (하단 20%)**
- 아주 큰 마이크 버튼 (음성 입력 메인)
- 이모티콘 빠른 응답 4개: "좋아요" / "감사해요" / "보고싶어요" / "힘들어요"
- 음성 인식 실패 시 선택지 버튼 제시 ("혹시 이 중에 있으세요?" + 큰 버튼 3~4개)

#### 5.5.5 AI 능동적 대화 — 시간대별 맥락

AI가 사용자를 기다리는 것이 아니라 **먼저 말을 건다**.

| 시간대 | AI 인사 | 연계 기능 |
|---|---|---|
| 아침 (07~09) | "정희님, 잘 주무셨어요? 오늘 날씨가 맑아요" | 날씨 정보 + 오늘 일정 알림 |
| 점심 후 (12~14) | "점심 맛있게 드셨어요? 오후에 물리치료 있으세요" | 식사 후 안부 + 오후 일정 |
| 오후 (15~17) | "심심하시죠? 재미있는 이야기 해드릴까요?" | 회상 치료 / 퀴즈 / 이야기 콘텐츠 |
| 저녁 (18~20) | "따님이 사진 보내셨어요, 볼까요?" | 가족 사진/메시지 전달 |
| 취침 전 (21~) | "오늘 하루 수고하셨어요. 편안한 밤 되세요" | 하루 요약 + 굿나잇 인사 |

#### 5.5.6 인라인 카드 — 화면 이동 없이 콘텐츠 전달

| 카드 유형 | 표시 내용 | 상호작용 |
|---|---|---|
| 가족 사진 | 보호자가 보낸 사진이 큰 말풍선 안에 | 탭 → 전체화면 + 이모티콘/음성 답장 |
| 가족 메시지 | 보호자가 보낸 텍스트/음성 메시지 큰 글씨로 | AI가 "뭐라고 할까요?" → 이모티콘/음성 답장 |
| 일정 알림 | "오후 3시 물리치료" 큰 글씨 카드 | 확인 버튼 "네, 알겠어요" |
| 콘텐츠 | 퀴즈, 옛날 이야기, 노래 등 | "맞춰볼까요?" / "들어볼까요?" 큰 버튼 |

#### 5.5.7 안전장치 — 감정 감지 + 현실 소통 유도

- AI가 어르신의 감정 상태를 대화에서 감지
- "힘들어요" 이모티콘 또는 부정적 발화 감지 시 **간호사에게 자동 알림**
- AI가 정기적으로 안내: "저는 AI 도우미예요. 진짜 사람이랑 얘기하고 싶으시면 간호사님 불러드릴까요?"
- 치매 초기 단계 환자의 **과도한 AI 의존 방지** — 현실 소통 유도 메커니즘 내재

#### 5.5.8 도움 요청 화면

화면 하단 우측의 빨간 버튼을 누르면 즉시 활성화. 원터치로 끝나는 극도로 단순한 구조.
- 큰 아이콘 버튼 3개 (세로 나열): "아파요" / "도와주세요" / "가족 연락"
- 하나 누르면 즉시 간호사에게 알림 발송 (복잡한 입력 없음)
- 발송 후 안심 메시지: "간호사님께 알렸어요, 곧 와주실 거예요"

#### 5.5.9 인지 모드 설정 (간호사·보호자가 설정)

환자의 인지 능력에 따라 태블릿 UI를 조절. 간호사 웹 환자 상세 케어플랜에서 설정.

| 모드 | 화면 구성 | 대상 |
|---|---|---|
| 일반 모드 | AI 대화 + 사진 + 일정 + 콘텐츠 전부 활성 | 인지 능력 정상인 어르신 |
| 간소화 모드 | 사진 액자 + 도움 버튼만 (대화 비활성화) | 중증 치매 등 인지 능력 저하 환자 |
| 보조 모드 | 음성 위주, 화면 터치 최소화, AI가 음성으로 말해줌 | 시력 저하 또는 손 떨림 환자 |
